SLA / SA 缓存

SA / SLA 工具链有多处缓存。它们大多只按文件内容作键——不含编译器或插件版本—— 因此编译器或插件重编之后，陈旧缓存会静默回放旧编译器产出的制品。症状在两个方向上都骗人： 真修复看起来毫无效果，或者健康的树看起来是坏的。本章列全每个缓存面的位置、键、失效方式与清理方法。

通则：验证任何编译器或插件改动之前，先清下面全部六个缓存面。 门禁或金丝雀结果与树的状态矛盾时，清缓存是调查的第一步，不是最后手段。 清缓存永远安全——所有缓存都会再生，唯一代价是重编时间。

六个缓存面

#缓存位置键失效方式清理
1SLA 宏索引缓存sa_plugin_sla 树内的 .sla-cache/ （macros/*.idx）宏文件路径 + 长度 + 源码哈希；不含编译器分析版本 编译器改动后仍回放旧宏展开，修好的编译器会继续以原样崩溃或出错。 删该树的 .sla-cache。注意：SLA_NO_FRESHNESS_CACHE=1 不覆盖此缓存。
2宿主前端缓存~/.cache/sa/frontend 仅源码文件 sha256；不含插件 / 编译器版本插件重编后，编译未改动的 .sla 会回放首次编译的产物，修复可以连续数轮看起来完全无效。删 ~/.cache/sa/frontend。
3构建图缓存插件树内的 .zig-cache/ 与 zig-out/ Zig 构建图，含配置时捕获的优化模式构建或安装时若环境带 SA_PLUGIN_DEV=1， 构建图会记下 Debug 配置：插件 .so 膨胀（约 129 MB，而 ReleaseFast 约 37 MB）， 且此后直接 zig build 会 0 秒退出、什么都不重编。.zig-cache 与 zig-out 两者都删（只删其一不够），构建 / 安装用 env -u SA_PLUGIN_DEV。运行时仍需 SA_PLUGIN_DEV=1——构建与运行环境不同。
4sa test 产物缓存各测试目录内的 .sa_cache/test/<hash>/artifact.sa.bc 测试源码哈希；不含编译器版本 sa test 回放旧编译器构建的 bitcode 产物；同一测试文件会因自身缓存持续失败或崩溃， 而字节相同的副本在别处却能通过。 删受影响测试目录内的 .sa_cache。
5独立版 CLI 新鲜度缓存Rust 版 sla CLI 管理（按工程的产物存储） 源码新鲜度元数据编译管线直接返回缓存的 .sa 并整体跳过前端， 新编译器行为根本不会运行。运行时带 SLA_NO_FRESHNESS_CACHE=1。 该变量只覆盖这一个缓存面。
6工程 / demo 目录产物缓存demo 与工程目录内的 .sa_cache/ （与 #4 同一存储、不同位置）同 #4 build-exe 回放旧编译器留下的陈旧 artifact.sa.bc—— 曾让健康树上的金丝雀格子假红一整天。 金丝雀或门禁运行前，删 demo / 工程目录内的 .sa_cache。

清理清单

# 在 sa_plugin_sla 树内
rm -rf .sla-cache .zig-cache zig-out
rm -rf ~/.cache/sa/frontend
find . -type d -name .sa_cache -prune -exec rm -rf {} +
SLA_NO_FRESHNESS_CACHE=1 <你的命令>

同族陷阱（同属静默陈旧）

  • sa plugin install --dev 会吞构建错误。构建失败时它可以退出码 0 并保留旧 .so。装机后必须双确认：已装 .so 的 mtime / 大小已更新，且本轮新引入的字符串字面量 能在 .so 内 grep 命中。md5 要在装机静置后取，且只许在同一轮构建 → 装机内比对： 插件 .so 字节跨重编不可复现，跨轮 md5 比对没有意义。新机器上裸形式还可能要求显式路径： sa plugin install --dev .
  • dev 模式加载的是已安装插件，不是工作树。 sa sla check / test 跑的是 $HOME/.local/share/sa_plugins/installed/ 下的插件，只在树内改源码 + zig build 不会改变任何行为。任何 A/B 对照必须先把被测树装进该轮 HOME 并 md5 核对已装 .so。
  • zig build test 会缓存成功运行。先前成功的一轮会被静默回放 （rc=0、日志为空、--summary all 下显示 run test cached）；失败不缓存， 所以这个陷阱很容易漏看。判读一轮运行须四联：rc=0、输出含预期结果行、失败名字集为空、 双路特性两路都过。rc=0 + 空日志不算一次运行。
  • sa-std-static 归档新鲜度。zig build sa-std-static 不把 sa_std/*.sa 追踪为步骤输入，暖重编可能回放旧归档。新鲜度以归档 mtime / 大小变化 加行为复证判读，不以构建退出码判读。

何时清理

  • 任何编译器 / 插件源码改动之后、跑验证之前。
  • 金丝雀 / 门禁运行之前；门禁结果与树状态矛盾时作为调查第一步。
  • 两份相同源码行为不一致时——缓存不对称是头号嫌疑。
  • 装机或重编看起来毫无效果时。
