sa sla build

sa sla build 把一个 .sla 源文件编译为经校验的 SA 汇编文本文件。读完本页可以知道如何控制输出路径，以及不指定 --out 时产物落在哪里。

语法

usage: sa sla build [file] [-p <package>] [--out <file>]

参数

名称说明
file输入的 .sla 源文件；省略时按 workspace 解析成员入口（见「sa sla check」一页）。
--out, -o输出 .sa 文件路径。省略时默认把输入扩展名替换为 .sa：main.sla → main.sa（非 .sla 输入则为 <file>.sa），写在源文件旁边。
-p, --packageworkspace 模式下选择成员包。
-h, --help显示用法并返回 0。
注意这条命令产出的是文本形式的 .sa 汇编——这是 SLA 的生产路输出，所有前端统一只输出 SA 文本。要产出 SAB 字节（已封存的优化方向，仅显式 opt-in）请用 sa sla sab build。

发射的 .sa 长什么样（实测）

编译生成的 main.sla 骨架并读取输出开头，可以看到前端已经完成了降级工作：宏已声明、vtable 常量已发射，函数体是线性 SA 指令并带显式的寄存器释放（!tmp_*）：

$ sa sla build /tmp/opencode/initdemo/src/main.sla --out /tmp/opencode/initdemo/main.sa
Sla Compiler: Successfully compiled /tmp/opencode/initdemo/src/main.sla to /tmp/opencode/initdemo/main.sa.

$ head -25 /tmp/opencode/initdemo/main.sa

[MACRO] SLA_ARRAY_FILL_U8 %array_ptr, %value, %length
    call @sa_mem_set(&%array_ptr, %value, %length)
[END_MACRO]
@const SLA_FNPTR_VT_main = vtable { call = @main }
@main() -> i32:
L_ENTRY:
    tmp_0 = 0
    tmp_1 = 32
    tmp_2 = shl tmp_0, tmp_1
    tmp_3 = ashr tmp_2, tmp_1
    !tmp_0
    !tmp_2
    !tmp_1
    return tmp_3

这份文本是交给 SA 宿主的正式交接面：sa build-exe main.sa -o prog 可以直接消费它。常量周围的 shl/ashr 是零字面量的物化方式；! 指令是所有权转移页讨论的释放。

示例

# 输出到 /tmp
SA_PLUGIN_DEV=1 sa sla build demos/rosetta/13_array_sum/main.sla --out /tmp/13_array_sum.sa

# -o 与 --out 等价；省略时写在源文件旁
SA_PLUGIN_DEV=1 sa sla build tests/test_unit_basic.sla --out /tmp/test_unit_basic.sa
SA_PLUGIN_DEV=1 sa sla build src/main.sla          # 生成 src/main.sa

# workspace 成员
SA_PLUGIN_DEV=1 sa sla build -p my_app --out /tmp/my_app.sa

产物位置

  • 显式指定 --out/-o：写到该绝对或相对路径，父目录必须已存在。
  • 未指定：写到源文件同目录下的 <stem>.sa。
  • 此命令不写 .sla-cache/sab/；SAB 托管产物只由显式 SAB 命令产生。

成功时 stdout 输出：

Sla Compiler: Successfully compiled main.sla to /tmp/main.sa.
