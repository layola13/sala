sa sla init

sa sla init 用于创建一个最小的 SLA 二进制项目骨架。读完本页可以直接用一条命令生成可编译的新项目。

迁移提示本工具链中 sa sla <verb> 拼写已弃用：语言前端现在按文件扩展名分派，因此优先使用宿主动词 sa init。sa sla init 仍可用，但会打印一行弃用提示；两种形式生成的文件完全相同。

语法

usage: sa sla init [path]

参数

名称说明
path可选。项目目录，省略时为当前目录 .。目录不存在会自动创建（含 src/ 子目录）。只能给一个路径，多余的参数或以 - 开头的未知选项都会报错退出。
-h, --help显示用法并返回 0。

生成的文件

文件内容要点
<path>/sa.mod首行 # generated by sla init，随后一行 package "<name>"。<name> 取路径的 basename；路径为 . 或无法取得名字时用 app。
<path>/src/main.sla最小入口：fn main() -> i32 { return 0; };
<path>/.gitignore预置 .sla-cache/、.zig-cache/、.sa_cache/、zig-out/、*.out、*.sa.bc。
警告init 不会覆盖已存在的文件：三个文件都以「新建」方式写入，目标位置已有同名文件时会报 File Error: failed to create ... 并返回非 0。

示例

在 /tmp/sla_app 创建新项目并立即验证：

SA_PLUGIN_DEV=1 sa sla init /tmp/sla_app
cd /tmp/sla_app
SA_PLUGIN_DEV=1 sa sla check src/main.sla
SA_PLUGIN_DEV=1 sa sla build-exe src/main.sla -o /tmp/sla_app/hello

生成的文件内容（实测）

在本工具链上运行 sa sla init /tmp/opencode/initdemo，恰好生成以下三个文件（包名取自目录名）：

$ sa sla init /tmp/opencode/initdemo
Initialized SLA binary project: /tmp/opencode/initdemo
Entry: /tmp/opencode/initdemo/src/main.sla

$ cat /tmp/opencode/initdemo/sa.mod
# generated by sla init
package "initdemo"

$ cat /tmp/opencode/initdemo/src/main.sla
fn main() -> i32 {
    return 0;
};

$ cat /tmp/opencode/initdemo/.gitignore
.sla-cache/
.zig-cache/
.sa_cache/
zig-out/
*.out
*.sa.bc

生成文件里 main 右花括号后的分号是模板自带的，解析器接受它；语言参考的 @test 例子里也能看到同样的写法。

init 之后的步骤

  1. sa sla check src/main.sla——只做前端验证，不产生制品。
  2. sa sla build-exe src/main.sla -o ./hello——发射 SA 文本并链接为本机可执行文件。
  3. 修改 src/main.sla 后，每次 build-exe 前先跑 check：这样可以把前端错误与后端降级错误隔离开。
  4. 把三个生成文件纳入版本控制；缓存目录已自动忽略。

产物位置

init 本身只生成上述三个源码文件，不产生编译产物。后续编译产生的 SAB 托管产物位于项目内的 .sla-cache/sab/，该目录已被自动写进 .gitignore。
