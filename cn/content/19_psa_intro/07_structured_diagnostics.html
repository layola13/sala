结构化诊断

状态：已落地。psa 的报错是结构化的：每条诊断都带一个稳定编号、一个命名规则、一句人话说明、它所指的位置（可以不止一处），以及——规则有修复提示时——一条可照着做的修复提示。同一条诊断既能以文本给人看，也能以 JSON 给工具读。运行时 panic 用一套平行的数字码总表，而一条命令 psa explain 可以解释这两类码。这套系统由 2026-11-26 的 errors 线建成并集成进主树；其收尾批已于 2026-11-28 落地（sapy d696d65a），补齐了 panic 总表并把对比测试套件入了仓。

每个编译期错误都有稳定编号

编号按拒绝程序的阶段分组：词法 PSA-L###、语法 PSA-P###、发射期（类型与所有权检查）PSA-E####、宿主流水线自身失败 PSA-H###（例如 PSA-H002，输入文件不存在）。注册表共 345 个唯一编号。注册表分类不了的诊断会落到一个明显是兜底的码（PSA-L900 / PSA-P900 / PSA-E9000），而不是借用一个具体编号——而仓内全部 13 个负例的审计结果是：没有一个落在兜底码上。

一条诊断可以带不止一个位置：每个 site 有文件、行、列与一个角色。例如 use-after-move 错误把「使用处」作主 site、把「移动处」作第二 site，因为两处都看清才修得对。

一个完整例子（实测原文）

这个三行程序把一个列表移动走之后又用了那个已死的绑定：

xs = [1, 2, 3]
ys = xs
print(xs)

psa check moved.psa 拒绝它（退出码 1），输出为：

error[PSA-E1001]: use of `xs` after it was moved
  --> moved.psa:3:7
   | print(xs)
   |       ^
   = site: move (line 2:6)
   | ys = xs
   |      ^
note: container assignment moves the value; the binding is dead until it is re-bound
hint: re-bind `xs` before line 3, or bind a copy at line 2

文本形态给出：编号、两个 site（带源码摘录与定位符）、一条解释规则的 note、一条说明改哪里的 hint。

机读输出：--error-format=json

全局旗标 --error-format=text|json 在子命令之前或之后都接受（环境变量 PSA_ERROR_FORMAT 是兜底来源）。同一次 check 的 JSON 形态打印一个对象：

{"code":"PSA-E1001","rule":"use-after-move","kind":"emit","file":"moved.psa","sites":[{"line":3,"col":7,"role":"use","snippet":"print(xs)"},{"line":2,"col":6,"role":"move","snippet":"ys = xs"}],"message":"use of `xs` after it was moved","note":"container assignment moves the value; the binding is dead until it is re-bound","hint":"re-bind `xs` before line 3, or bind a copy at line 2"}

字段即契约：code、rule、kind、file、sites（每项带行、列、角色与源码摘录）、message，以及可选的 note 与 hint。没有源码位置的诊断（如输入文件缺失这类宿主失败）会渲染空的 sites 列表，而不是编造一个位置。

运行时 panic 码与 psa explain

运行时失败以裸数字码 panic（Source Map 一页讲如何把码追溯回源码位置）。这些码不是口口相传的：一张机读总表 PANIC-CODES.json（在 psa_std 里）由编译器自家的码表生成，共 113 个键——102 个是编译器实际发射的码，另 11 个为预留。每条记录码、规则名、类别、一句摘要，以及适用时的一条修复说明。构建有一条受检不变量：每个被发射的码都必须在表内；历史上唯一一处违反（77083 被发射却没登记）正是被这项检查发现、并以补登记修复的。

psa explain 查任意一族的码：

$ psa explain 77083
panic 77083 - the module environment was read before it was published (closure runtime invariant; unreachable in a correctly emitted program) (PSA-R77083)
  category: runtime-core
  fix: this is a psa internal invariant, not a problem in your code; please report it with the source file

$ psa explain PSA-E1001
PSA-E1001 (use-after-move)
  use of a name after it was moved; the diagnostic carries two sites (the use and the move)

带 --error-format=json 时，explain 以同样的 JSON 形态作答（运行时码报为 PSA-R77083 式、kind 为 runtime、sites 为空）。未知码响亮失败——psa explain 99999 以退出码 1 报 psa explain: unknown panic code 99999——而不是猜一个解释。

本页要点

  • 每个 psa 错误都有稳定编号（PSA-L/P/E/H 四族、注册 345 个）、规则、带角色的位置、人话说明，以及规则有提示时的一条修复提示。
  • --error-format=json 把同一条诊断渲染成一个字段契约固定的 JSON 对象；无位置的诊断渲染空 sites，绝不编造。
  • 运行时 panic 用数字总表（113 键：102 发射、11 预留），以 PANIC-CODES.json 交付；psa explain 两族都解释、未知码响亮失败。
  • 落地头实测：对比套件 34/34、panic 总表检查通过、正例 61/61 不变。
  • 已登记缺口：5 个拒绝形状仍无 psa 码（E5002 批待落地）、提示未全覆盖、77084 未分配。
