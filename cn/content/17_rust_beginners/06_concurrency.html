并发：go、通道与共享状态

SLA 的并发规则是结构性的：借用永不跨任务边界（检查器同时拒绝 go 形式与 thread::spawn 闭包形式——见 &mut 对照页）。能跨过去的是拥有的值：通道的一端，或者一个 Arc 克隆。本页四个程序就是已验证的形态。

go 与一次通道往返

Chan::new(0) 创建一个 rendezvous 通道；recv() 返回 (value, closed) 对；go 启动一个任务，sa_task_join(h) 收取它的状态：

Rust 对应版本使用 std::thread 与两个 mpsc 通道端；两个程序都已编译运行，都输出 42。

// Rust
use std::sync::mpsc::channel;
use std::thread;

fn main() {
    let (tx1, rx1) = channel::<u64>();
    let (tx2, rx2) = channel::<u64>();
    let h = thread::spawn(move || {
        let v = rx1.recv().unwrap();
        tx2.send(v * 2).unwrap();
    });
    tx1.send(21).unwrap();
    drop(tx1);
    let r = rx2.recv().unwrap();
    h.join().unwrap();
    println!("{}", r);
}
// output: 42

fn double_worker(ch: Chan<u64>) {
    let (v, closed) = ch.recv();
    if closed { panic(9701); };
    ch.send(v * 2);
}

fn main() -> i32 {
    let ch: Chan<u64> = Chan::new(0);
    let h = go double_worker(ch);
    ch.send(21);
    let (r, closed) = ch.recv();
    if closed { return 1; };
    let st = sa_task_join(h);
    if st != 0 { return 2; };
    println("{}", r);
    ch.destroy();
    if r != 42 { return 3; };
    return 0;
}

实测输出：42，退出码 0——工作者把收到的 21 翻倍后经同一通道送回。

thread::spawn 与双通道乒乓

用 thread::spawn 时，被派生的闭包取得它捕获之物的所有权。这里工作者拥有两个通道端，回答 50 次请求：

Rust 版本是直接的 mpsc 翻译；两个程序都已编译运行，都输出 50。

// Rust
use std::sync::mpsc::channel;
use std::thread;

fn main() {
    let (req_tx, req_rx) = channel::<u64>();
    let (resp_tx, resp_rx) = channel::<u64>();
    let h = thread::spawn(move || {
        for _ in 0..50 {
            let v = req_rx.recv().unwrap();
            resp_tx.send(v + 1).unwrap();
        }
    });
    let mut last = 0;
    for i in 0..50 {
        req_tx.send(i).unwrap();
        last = resp_rx.recv().unwrap();
    }
    drop(req_tx);
    h.join().unwrap();
    println!("{}", last);
}
// output: 50

fn pp_worker(req: Chan<u64>, resp: Chan<u64>) {
    let i = 0;
    while i < 50 {
        let (v, closed) = req.recv();
        if closed { panic(9601); };
        resp.send(v + 1);
        i = i + 1;
    }
}

fn main() -> i32 {
    let req: Chan<u64> = Chan::new(0);
    let resp: Chan<u64> = Chan::new(0);
    let h = thread::spawn(^|| pp_worker(req, resp));
    let i = 0;
    let last: u64 = 0;
    while i < 50 {
        req.send(i as u64);
        let (r, closed) = resp.recv();
        if closed { panic(9602); };
        last = r;
        i = i + 1;
    }
    let jr = h.join();
    println("{}", last);
    req.destroy();
    resp.destroy();
    if last != 50 { return 1; };
    return 0;
}

实测输出：50，退出码 0——50 轮请求/响应中的最后一答，每次接收都检查 closed 标志。

共享状态：Arc<Mutex<i32>>

四个工作者，每个递增 250 次，一个共享计数器：

下面的 Rust 对应程序已编译运行，输出 1000，与 SLA 程序完全一致：

// Rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut hs = vec![];
    for _ in 0..4 {
        let c = Arc::clone(&counter);
        hs.push(thread::spawn(move || {
            for _ in 0..250 { *c.lock().unwrap() += 1; }
        }));
    }
    for h in hs { h.join().unwrap(); }
    println!("{}", *counter.lock().unwrap());
}
// output: 1000

fn worker(counter: Arc<Mutex<i32>>) -> i32 {
    let i = 0;
    while i < 250 {
        let guard = (*counter).lock().unwrap();
        let cur = *guard;
        *guard = cur + 1;
        i = i + 1;
    }
    return 1;
}

fn main() -> i32 {
    let counter = Arc::new(Mutex::new(0));
    let c1 = counter.clone();
    let c2 = counter.clone();
    let c3 = counter.clone();
    let c4 = counter.clone();
    let a = thread::spawn(^|| worker(c1));
    let b = thread::spawn(^|| worker(c2));
    let c = thread::spawn(^|| worker(c3));
    let d = thread::spawn(^|| worker(c4));
    let s = a.join().unwrap() + b.join().unwrap() + c.join().unwrap() + d.join().unwrap();
    let guard = (*counter).lock().unwrap();
    let final = *guard;
    println("{}", final);
    if s != 4 { return 2; };
    if final != 1000 { return 1; };
    return 0;
}

实测输出：恰好 1000，退出码 0。克隆是显式做的（counter.clone()）再移动进被派生的闭包；guard 的用法——lock().unwrap()、读、写、析构——与 Rust 同形。

共享状态：Arc<RwLock<i32>>

一个写者加 2 一百次，两个读者断言它们观察到的每个值都是偶数：

Rust 对应程序已编译运行，输出 200 200 200（最终值与两个读者最后看到的值）；SLA 程序输出最终值 200。

// Rust
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    let lock = Arc::new(RwLock::new(0i32));
    let w = Arc::clone(&lock);
    let hw = thread::spawn(move || {
        for _ in 0..100 { *w.write().unwrap() += 2; }
    });
    let mut readers = vec![];
    for _ in 0..2 {
        let r = Arc::clone(&lock);
        readers.push(thread::spawn(move || {
            let mut seen = 0;
            loop {
                let v = *r.read().unwrap();
                assert_eq!(v % 2, 0);
                if v > seen { seen = v; }
                if v >= 200 { break; }
            }
            seen
        }));
    }
    hw.join().unwrap();
    let a: i32 = readers.pop().unwrap().join().unwrap();
    let b: i32 = readers.pop().unwrap().join().unwrap();
    println!("{} {} {}", *lock.read().unwrap(), a, b);
}
// output: 200 200 200

@import "sa_std/io/print.sai"

fn writer(lock: Arc<RwLock<i32>>) -> i32 {
    let i = 0;
    while i < 100 {
        let g = (*lock).write().unwrap();
        let cur = *g;
        *g = cur + 2;
        i = i + 1;
    }
    return 1;
}

fn reader(lock: Arc<RwLock<i32>>) -> i32 {
    let seen = 0;
    let done = 0;
    while done == 0 {
        let g = (*lock).read().unwrap();
        let v = *g;
        if v % 2 != 0 { panic(4101); };
        if v > seen { seen = v; };
        if v >= 200 { done = 1; };
    }
    return seen;
}

fn main() -> i32 {
    let lock = Arc::new(RwLock::new(0));
    let w = lock.clone();
    let r1 = lock.clone();
    let r2 = lock.clone();
    let hw = thread::spawn(^|| writer(w));
    let h1 = thread::spawn(^|| reader(r1));
    let h2 = thread::spawn(^|| reader(r2));
    let sw = hw.join().unwrap();
    let s1 = h1.join().unwrap();
    let s2 = h2.join().unwrap();
    let g = (*lock).read().unwrap();
    let final = *g;
    println("{}", final);
    if sw != 1 { return 2; };
    if s1 != 200 { return 3; };
    if s2 != 200 { return 4; };
    if final != 200 { return 1; };
    return 0;
}

这个程序通过了验证，打印 200、退出码 0。但要如实报告：在 对照页更长的实测系列里，同样的写者/读者形态 28 次运行中 22 次打印 200，另外 6 次以运行时 panic（code 17）结束——RwLock 混合形态目前对时序敏感，而上面的通道交接与 Mutex 计数器在每一轮都精确。新代码在这一点改变之前，优先用通道与 Mutex。

本页要点

  • 借用不跨任务边界；拥有的值可以——通道端与 Arc 克隆。
  • go + Chan::new(0) + sa_task_join 是最轻的任务形态；recv() 产出 (value, closed)。
  • Arc<Mutex<i32>> 四个工作者得到恰好 1000。
  • RwLock 读写混合能到达 200，但在更长运行中对时序敏感（28 次中 22 次干净）；通道与 Mutex 每一轮都精确。
