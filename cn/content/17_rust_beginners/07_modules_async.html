模块与异步

模块：@import 一个文件，导出标 pub

文件级模块不需要声明 mod 树。被导入的文件用 pub 标出它导出的东西，导入方用相对路径 @import 把文件拉进来。被导入的 helper：

pub fn create_id() -> u64 {
    return 100;
}

导入方：

@import "helper.sla"
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn main() -> i32 {
    let id = create_id();
    println("{}", id);
    return 0;
}

实测输出：100，退出码 0。本章每个程序都以同样方式导入标准库——来自 sa_std/... 的声明文件（.sai）与实现文件（.sa）——而生成的 sla_std 薄包装是 std 的主流导入面；见 标准库一章。与 Rust 相比，心智模型是“一个文件、一个模块、显式的 pub 表面”——更像包含一个头文件，而不是维护一棵模块树。

异步：async fn 与 .await

async fn 返回一个 future（future 类型的拼写是 future<T>），.await 驱动它。在已验证的形态里，连 main 都可以直接 await 一个顶层调用：

@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

async fn step_one() -> i32 {
    return 1;
}

async fn run_async() -> i32 {
    let value = step_one().await;
    return value + 1;
}

fn main() -> i32 {
    let result = run_async().await;
    println("{}", result);
    if result != 2 { return 1; };
    return 0;
}

实测输出：2，退出码 0。读法与 Rust 的 async/.await 相同；不同的是它周围的一切——这里的任务是运行时自己的（上一页的 go 与通道机制），不是你外接的执行器。与 Rust 的实测异步对比见 标准库、错误处理与 async 对比。

本页要点

  • 文件模块：相对路径 @import "relative/path.sla" 加被导入文件里的 pub fn；没有模块树仪式。
  • 标准表面以同样方式导入；sla_std 薄包装是 std 的主流导入形式。
  • async fn + .await 读法与 Rust 相同，跑在运行时自己的任务机制上。
