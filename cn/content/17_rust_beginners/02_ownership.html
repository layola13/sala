所有权：移动与借用

SLA 保留了 Rust 的核心契约：每个值只有一个所有者，所有权在编译期强制执行。改变的是借用的表达方式——Rust 有两种借用类型，SLA 只有一种。本页先讲移动，再讲借用模型；完整的实测论述（含任务边界规则）见伴侣页 没有 &mut 是设计而非缺失。

按值传递即移动

带堆字段（这里是 String）的结构体不是 Copy，按值传给函数即移动——调用方的绑定被消耗，与 Rust 完全一致。

// Rust
struct User {
    id: u64,
    name: String,
}

fn greet(user: User) -> u64 {
    user.id
}

fn main() {
    let user = User { id: 100, name: String::from("Alice") };
    println!("{}", greet(user));
}
// 输出：100
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

struct User {
    id: u64,
    name: String,
}

fn greet(user: User) -> u64 {
    return user.id;
}

fn main() -> i32 {
    let user = User { id: 100, name: format("Alice") };
    println("{}", greet(user));
    return 0;
}

实测输出：100，退出码 0。注意 SLA 的字符串用 format("Alice") 构造，见上一页。

移动后使用是编译错误

这条规则在两种语言里都有牙齿。下面的程序把 user 移动给 user2，然后再读原来的绑定：

@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

struct User {
    id: u64,
    name: String,
}

fn main() -> i32 {
    let user = User { id: 100, name: format("Alice") };
    let user2 = user;
    println("{}", user.id);
    return 0;
}

检查器在生成任何代码之前就拒绝它：

Type Check Error: failed to verify types: UseAfterMove: identifier `user` was already consumed (error.UseAfterMove)

这是 rustc E0382（“use of moved value”）在 SLA 中的对应物。阶段相同——编译期，绝不是运行时惊喜——被移动的绑定在作用域余下部分保持死亡。

一种借用类型，读写通用

这是教科书里的 &mut 例子：一个函数通过借用读一个数，另一个函数通过借用给它加 10。Rust 前者需要 &i32、后者需要 &mut i32；SLA 两者都用 &i32：

@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn read(value: &i32) -> void {
    println("{}", *value);
}

fn modify(value: &i32) -> void {
    *value += 10;
}

fn main() -> i32 {
    let number = 100;
    read(&number);
    modify(&number);
    println("{}", number);
    return 0;
}

实测输出：先 100，后 110，退出码 0。直接翻译不需要 Cell / RefCell 绕道。读写权限不写在签名里；降低（lowering）之后，SA Referee 按借用背后实际的 load/store 指令判定 Locked_Read / Locked_Mut。

RustSLA
读函数签名read(&i32)read(&i32)
写函数签名modify(&mut i32)modify(&i32)
把读者改成写者签名要改成 &mut，所有调用方跟着改签名不变，只改函数体
谁判定读写类型系统，在签名处SA Referee，按实际指令

实际后果：一个实现开始通过借用写入时，函数签名保持稳定。Cell / RefCell 仍然存在，但它们是给真正共享的内部状态用的——不是借用修改的必经收费站。代价是签名不再告诉你函数是否写入；这个权衡以及它所属的 Phase 2 计划，见 &mut 对照页与 所有权与借用：Referee 对借用检查器。

本页要点

  • 传递或赋值一个非 Copy 值即移动它；之后再使用是编译期 UseAfterMove 错误。
  • SLA 只有一种借用类型 &T，读写通用；没有 &mut。
  • SA Referee 按实际指令判定 Locked_Read / Locked_Mut，所以读者变写者时签名不变。
  • 通过借用修改不需要 Cell / RefCell。
