错误处理、闭包与宏

Result：构造它，匹配它

用户代码可以直接构造并返回 Result<i32, String>，用 Ok(...) 与 Err(...)，再用 match 处理——与 Rust 同形。? 运算符同样可用，下面第二组程序演示错误传播，两边都已编译运行。

// Rust
fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        return Err(String::from("division by zero"));
    }
    Ok(a / b)
}

fn main() {
    match divide(10, 2) {
        Ok(value) => println!("{}", value),
        Err(error) => println!("{}", error),
    }
    match divide(10, 0) {
        Ok(value) => println!("{}", value),
        Err(error) => println!("{}", error),
    }
}
// 输出：5，然后：division by zero
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        return Err(format("division by zero"));
    };
    return Ok(a / b);
}

fn main() -> i32 {
    match divide(10, 2) {
        Ok(value) => { println("{}", value); },
        Err(error) => { println("{}", error); },
    };
    match divide(10, 0) {
        Ok(value) => { println("{}", value); },
        Err(error) => { println("{}", error); },
    };
    return 0;
}

实测输出：先 5，后 division by zero，退出码 0。错误字符串用 format(...) 构造，见第一页。标准库里可失败的 extern 函数也以同样方式报错误——返回一个用 Ok / Err 匹配的 Result——所以库错误与用户错误共用一种处理风格。

用 ? 传播错误

两种语言都用 ? 传播 Result。Rust 版输出 Ok(30) 然后 Err("bad number")；SLA 版以自身格式输出同样两种情况（ok 30、err bad number）。两个程序都已编译运行。

// Rust
fn parse(s: &str) -> Result<i32, String> {
    s.parse::<i32>().map_err(|_| String::from("bad number"))
}
fn compute(a: &str, b: &str) -> Result<i32, String> {
    Ok(parse(a)? + parse(b)?)
}
fn main() {
    println!("{:?}", compute("10", "20"));
    println!("{:?}", compute("x", "20"));
}
// output: Ok(30) / Err("bad number")
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/core/result.sa"

fn parse(value: i32) -> Result<i32, String> {
    if value < 0 { return Err(format("bad number")); };
    return Ok(value);
}
fn compute(a: i32, b: i32) -> Result<i32, String> {
    let x = parse(a)?;
    let y = parse(b)?;
    return Ok(x + y);
}
fn main() -> i32 {
    match compute(10, 20) {
        Ok(v) => { println("ok {}", v); },
        Err(e) => { println("err {}", e); },
    };
    match compute(-1, 20) {
        Ok(v) => { println("ok {}", v); },
        Err(e) => { println("err {}", e); },
    };
    return 0;
}
// output: ok 30 / err bad number

Option

Option<i32>、Some(7) 与 None 都是真实存在、可匹配的：

Option<i32>、Some(7) 与 None 都真实可匹配。下面两个程序都已编译运行，都先输出 7 再输出 none。

// Rust
fn find(flag: bool) -> Option<i32> { if flag { Some(7) } else { None } }

fn main() {
    match find(true) { Some(v) => println!("{}", v), None => println!("none") }
    match find(false) { Some(v) => println!("{}", v), None => println!("none") }
}
// output: 7 / none
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn find(flag: bool) -> Option<i32> {
    if flag {
        return Some(7);
    };
    return None;
}

fn main() -> i32 {
    match find(true) {
        Some(v) => { println("{}", v); },
        None => { println("none"); },
    };
    match find(false) {
        Some(v) => { println("{}", v); },
        None => { println("none"); },
    };
    return 0;
}

实测输出：先 7，后 none，退出码 0。

闭包

闭包用 Rust 的管道语法、带类型标注的参数，并捕获周围的绑定：

// Rust
fn main() {
    let factor = 10;
    let multiply = |x: i32| x * factor;
    println!("{}", multiply(5));
}
// 输出：50
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn main() -> i32 {
    let factor = 10;
    let multiply = |x: i32| x * factor;
    println("{}", multiply(5));
    return 0;
}

实测输出：50，退出码 0。进入并发页之前要知道一条边界：跨任务边界的闭包不得捕获外层位置的借用——这是会被检查拒绝的，被拒形态见 &mut 对照页。

宏：带类型的宏，输出参数在最前

SLA 的用户宏不是 macro_rules!。宏是带类型的——参数有类型、宏体像函数体一样被检查——并且它的第一个参数是输出参数：宏把结果写进这个参数，调用点读起来就像一次返回该输出的函数调用。

Rust 的 macro_rules! 是不同机制——基于模式而非类型——但卫生性相同：宏内部声明的 temp 不会碰到调用者的 temp。实测 Rust 程序输出 6 然后 5；SLA 程序输出 42。

// Rust
macro_rules! add_one { ($v:expr) => {{ let temp = 1; $v + temp }}; }

fn main() {
    let temp = 5;
    println!("{}", add_one!(temp));
    println!("{}", temp);
}
// output: 6 / 5
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

macro doubled(out_result: i64, x: i64) {
    out_result = x + x;
}

fn main() -> i32 {
    let v: i64 = 21;
    let a = doubled(v);
    println("{}", a);
    if a != 42 { return 1; };
    return 0;
}

实测输出：42，退出码 0。这个定义可以这样读：“doubled 接受一个 i64 输入 x，通过最前面的输出参数 out_result 产出结果。”调用 let a = doubled(v); 绑定的就是这个输出。更完整的宏对照——@derive、@overload，以及与 Rust 模式宏的区别——见 宏与元编程对比。

本页要点

  • Result 与 Option 的构造与匹配与 Rust 程序员的预期完全一致；错误字符串用 format(...) 构造。
  • 闭包用 |x: i32| expr 语法并捕获外层绑定；借用仍不得跨任务边界。
  • SLA 用户宏带类型、像函数一样被检查，并以输出参数打头；调用点形如函数调用。
