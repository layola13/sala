一、用户定案：周边语法成套引入「底层」（2026-10-29）

用户定案（2026-10-29 10:20）：一切配合 goroutine 周边的语法都要引入 SA 底层，成套引入、不零敲碎打。

「底层」的口径（主会话收敛，承 2026-10-27 底座定案）：机制进 sa_std 运行时核心（调度器 / 通道 / select / sync / netpoller 胶水 / 边界 trap 承接点），语法面进 SLA 一等语法（go/spawn、channel、select、defer、recover 监督）；SA 规约本身（寄存器 + 所有权/能力规约）不动，仍是一切前端的共同目标，不为任何单一前端让路。

周边全集 = 已裁定的 goroutine 本体（见 13 号文档）+ defer + goroutine 边界 recover/监督 + context 式取消约定（std 规范、非语法，见第三节）。

二、候选清单与 Jev 排序（2026-10-29）

排序（2026-10-29，jev-1.14.0，逐项 noul，裁定文件 ~/workspace/jev-designs/go_features_ranking.json），数值为「早引入强度」：

  • goroutine 边界 recover / 监督语义：0.73（第一）——是三台 per-connection 改造的上线门槛。
  • 编译期嵌入（go:embed 式）：0.58——独立小批，与并发程序正交。
  • defer：0.56——与嵌入同分量级。
  • 隐式接口：0.29（末位）——先普查 SLA 既有泛型 / trait 面再单独裁定。

打包裁定：defer + recover 随 SLA goroutine 语法批同批设计交付（0.73）。embed 为独立小批，随时可插。

三、各候选的设计要点

  • defer：作用域退出时按 LIFO 执行登记的清理动作——是任意动作、不止 drop（owned 值的自动释放已有 drop 机制，defer 覆盖的是 drop 之外的清理）；与 sync 原语的 lock(); defer unlock() idiom 配套交付。
  • recover：仅在 goroutine 边界承接 trap——记日志、重启或降级，使单条连接的故障不拖死整个进程。明示：不是通用异常系统、不替代 Result 错误处理，普通代码的错误仍走 Result + 传播符。
  • 编译期嵌入（embed）：编译期读文件、落数据段，供单二进制部署携带静态资源/模板；路径纪律与构建可复现性待该批设计时处理，不预设。
  • 隐式接口：结构满足（有方法集即实现）+ 消费方定义小接口。是语言级承诺，须普查先行（SLA 既有泛型 / trait 面的对齐盘点），普查后再单独裁定，不阻塞 goroutine 程序。
  • context 式取消约定：不是语法，是 std 规范——一个可 select 的 Done 通道（或等价形态）沿调用链传递取消信号，随通道批一起立规范。

四、落选记录

  • Go error 语法：不引入。SLA 已有 Result + 传播运算符且更优；只取其「错误是值」的原则一条——该原则本已在 SLA 内。
  • iota、命名返回值等多重小糖：不引入。SLA 有等价物，引入只增表面积。
  • struct 嵌入：不引入。与所有权组合时语义易浑，显式字段转发足够。
