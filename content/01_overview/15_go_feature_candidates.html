1. User Decision: Bring the Surrounding Syntax into the “Low Level” as a Set (2026-10-29)

User decision (2026-10-29 10:20): all syntax that works together with goroutines is to be brought into the SA low level, as a complete set, not piecemeal.

The stance on “low level” (main-session convergence, carrying the 2026-10-27 base decision): the mechanisms go into the sa_std runtime core (scheduler / channels / select / sync / netpoller glue / boundary trap catch points), and the syntax surface goes into first-class SLA syntax (go/spawn, channel, select, defer, recover supervision); the SA specification itself (registers + the ownership/capability specification) does not move — it remains the common target of all frontends and does not yield to any single frontend.

The complete surrounding set = the already-ruled goroutine core (see Document 13) + defer + goroutine-boundary recover/supervision + the context-style cancellation convention (a std specification, not syntax; see Section 3).

3. Design Points of Each Candidate

  • defer: when a scope exits, run the registered cleanup actions in LIFO order — these are arbitrary actions, not just drop (automatic release of owned values already has the drop mechanism; defer covers cleanup beyond drop); it is delivered together with the lock(); defer unlock() idiom for the sync primitives. (Landed: block-scope LIFO + argument snapshots; see Example 4 in Section 15 of Document 13.)
  • recover: catches traps only at the goroutine boundary — log, restart, or degrade, so that a fault on a single connection does not drag down the whole process. Explicitly: this is not a general exception system and does not replace Result error handling; errors in ordinary code still go through Result + the propagation operator. (Landed: boundary trap + supervisor.sla supervision restart; see Examples 5 and 6 in Section 15 of Document 13.)
  • Compile-time embedding (embed): read files at compile time and place them in a data section, so a single-binary deployment can carry static assets/templates; path discipline and build reproducibility are handled when that batch is designed, not preset.
  • Implicit interfaces: structural satisfaction (having the method set means implementing it) + small interfaces defined by the consumer. This is a language-level commitment and requires the census first (an alignment inventory of SLA's existing generics / trait surface); after the census it is ruled separately, and it does not block goroutine programs.
  • Context-style cancellation convention: not syntax but a std specification — a selectable Done channel (or an equivalent form) that carries the cancellation signal along the call chain, specified together with the channel batch. (Landed: the sa_std/ctx.sla idiom; see Example 7 in Section 15 of Document 13.)

4. Rejection Record

  • Go error syntax: not introduced. SLA already has Result + the propagation operator, and they are better; only its one principle, “errors are values”, is taken — and that principle is already inside SLA.
  • iota, named return values, and other assorted small sugars: not introduced. SLA has equivalents; introducing them would only add surface area.
  • Struct embedding: not introduced. Its semantics get muddy when composed with ownership; explicit field forwarding is enough.

6. Assessment of the Help to the Three Target Projects (main-session assessment, 2026-10-29)

General outline: the help is mainly in concurrency structure, robustness, and development speed, not in single-machine throughput numbers. The 99% gaps of the three machines were previously all attributed elsewhere than the concurrency model, and goroutines do not directly raise the performance numbers.

  • slanginx (helped the most): its F2 concurrent serve lacked a native form; goroutines provide the per-connection sequential handler, the reverse-proxy bidirectional pump (two goroutines + a channel), and context cancellation of upstreams; recover supervision means a trap on a single connection does not kill the process — a robustness tier it currently does not have at all. What it does not help: the residual suspicion about the per-request memory slope sits inside the std http/string text machinery and belongs to the F-perf line; multi-core serve going from nothing to something counts as moderately positive, and hot-spot optimization is still another line.
  • slaredis (large structural help; throughput help limited, possibly even slightly negative): the hand-written state machine of a poll loop + sharded wait sets can disappear wholesale; it unlocks the blocking-command feature class (BLPOP in an event loop has to suspend a connection + a timeout queue; in a goroutine it is sequential code); expiry handling and the AOF write pipeline (a dedicated goroutine + a channel feeding batches) become natural. But its measured performance plateau is only 0.12–0.19 of Redis, attributed to std data structures and per-command overhead, and goroutines do not close that gap; under high-frequency small commands, context switching is slightly more expensive than a compact poll loop.
  • db (moderate-to-small help, at the access layer, not the engine): the epoch snapshot model already scales reads to the core count (an 8-thread column-sum measurement of 15,386/s) without relying on goroutines. It benefits in two places: the SLA service layer for the relay-station quota-checking scenario (concurrent query goroutines each pin a snapshot, deductions converge through a channel to a single writer — the language-level shape of group commit, currently hand-built locks and queues); and applications using db concurrently from SLA no longer hand-manage threads. The point-read latency gap against SQLite sits in per-exec verification, which goroutines do not touch.
  • Common to all three machines: three sets of hand-built concurrency converge into one language-level model, and the bug surface and maintenance surface shrink in step; defer drops “forgot to release the resource” leaks by one tier on all three machines; the supervision semantics give the two network servers a unified crash isolation.
  • Honest reservation: v1 is cooperative scheduling — pure computation that never yields starves its companions; scheduler maturity and tail latency cannot compare with Go's ten years of polishing — this must be watched with measurements in the three-machine rework acceptance, not assumed to be as smooth as Go by default.

Convergence in one sentence: slanginx gets a heart transplant, slaredis gets its state machine dismantled plus blocking commands unlocked, and db gets a concurrency license for its access layer; the 99% performance of the three machines still belongs to each one's own std hot-spot line.

Landing Record for Ordering Two (2026-10-30)

All pushes below were independently rechecked by the main session with ls-remote; the numbers are from each line's final report.

slanginx landed: main e19f058 → 07157a6c8de55f284f24f2e351bbf64fa91bb3f5. The finalized form of goroutine serve: the dispatcher (the main task) accepts with a short poll at ACCEPT_POLL_MS=1, directly spawns a supervised conn_worker, joins on the completions chan at reclamation time to read traps, a 64-slot connection pool owned exclusively by the dispatcher, a watchdog covering the gap of a trapped worker with no completion, and generational rotation at GEN_EVENT_BUDGET=20000. Two measured reshapes (deviations from the original PLAN, registered on record): (1) a per-connection supervisor goroutine hit the cumulative ceiling of about 300k for spawn/join from a non-main task (periodic PANIC 60901), so supervision was taken back into the main task, with the semantics equivalently preserved; (2) an acceptor goroutine feeding a chan hit pump stalls on the std surface's accept (stalls of 6–9 s under load, zero CPU), so accept returned to the dispatcher. Gates (four-part reading): unit 25/25 all passing by name, acceptance 49 PASS / 0 FAIL, a 120,000-request load smoke test with 0 errors and an access log of exactly 120,000 lines, and malformed input (a garbage request line / a 60 KB header) had its connection disposed of while the process survived. Same-window bench against nginx (ratios c1/c10/c50): small 3.8%/6.0%/4.5%, large 7.6%/14.2%/15.7%, proxy 36.3%/80.9%/40.9% (the G7 sequential version: small 26.3%/5.9%/4.4%, large 44.3%/15.3%/5.3%); reading: c10/c50 are at the same level as the baseline (large c50 actually ahead), the dispatcher's ceiling of about 5.5k rps is of the same magnitude as the sequential version's serial ceiling; c1 is a clear weak surface — poll-slice quantization + the serial spawn chain cap a single connection at about 760 rps, and the sequential version's high c1 ratio came from zero-handoff inlining; the trade-off is written into the delivery document. Endurance: under the default 8 MiB stack, 600,000 requests with 0 errors, ENDURANCE_PASS, past the sequential version's death point of 523,128, so the process-death surface is closed; VmStk bounded throughout. Slope: 15,100 → about 6,500 B/req (endurance average); the three application-layer causes were eliminated by construction; the residue is about 4,231 B retained per spawn by the runtime, which belongs to the runtime surface. The DEF handover package is ready (the stack-ratchet probe_b main piece + four supplements: detached spawn retention, a task stack of about 256 KiB overflowing into a process abort that cannot be supervised, the non-main-task spawn/join ceiling and defer-on-trap not executing, and the accept pump stall), awaiting the main session forwarding it to the DEF line.

db landed: sa_plugin_db master c02b4ec → 9b61981 (a new sla/ concurrent access layer: query goroutines each pin a snapshot and read, deductions converge via a Chan into a single-writer goroutine for group commit — batched by batch size/window, one commit per batch, a watchdog marks writer death as a service-level fatal, close drains the inbox; the Zig engine untouched), access acceptance 9/9 (SAB backend), and the quota service example passing end to end; the OTP executor skeleton went into sci's sa_std (sci main e7c18568 → 9c874290, two commits for sa_std/executor.sla + executor_test.sla). Same-window numbers for the access layer (line's final report): point reads about 0.95–1.13k qps, direct pinned reads 5.50M qps — the bottleneck has moved from the engine to the access path itself (one goroutine + one Chan round trip per query); group-commit deduct 82 rps @4 clients (2,000 deductions, 500 commits, batch merging in effect); the engine median reproduces the G3 write figure of 114.7/s. The Section 6 judgment of “issuing the access layer a concurrency license” was fulfilled, and the new attribution of the read-throughput gap (access-path overhead) is on record.

slaredis landed: main 957eaa0 → c0e4788a058f15af2cabf8a91ca263e04d67d794 (chain: 8b3f5fd the goroutine model → fcd8be6 made the default → two docs errata commits 53092b0 / c0e4788). The finalized form: per-connection goroutines + a single executor goroutine exclusively owning the Store via one FIFO Chan + dedicated goroutines for the AOF writer and expiry sweeping + supervisor supervision (if the core dies, the process exits loudly with code 71 and recovers by AOF replay, never silently restarting alone). One deviation from the letter of the PLAN, registered on record: socket IO is concentrated in an IO driver on the main goroutine's frame — a blocking net wait inside a spawned goroutine starves the others, and calling poll_wait inside a spawned goroutine starves chan delivery process-wide (measured defects; see defect registrations A / B below); the deviation moves only the byte plumbing, and the charter's fixed points are unchanged. The fourth surface is closed: the goroutine model has no reap path, connection state lives entirely in heap blocks and never moves, and bulk close = a pointer swap-remove in the driver table + each connection goroutine exiting on its own, with no move operation that scales with the number of live connections; the acceptance gate smoke_1000 was ALL PASS (1,200 connections opened, sampled PINGs all +PONG, SET/GET consistent across connections, the process surviving the bulk close of connections 100..1199, and new connections' PING and data checks passing), and the chained sequence (100 connections held for 10 s → goroutine_stress → smoke_1000 → another 5,000 connections opened, held, and PINGed) was all green; 5,000 resident connections at about 50.4 KiB/connection (the 256 KiB goroutine stack is virtual and counts only when its pages are touched). Gates: the pre-work drift scan showed zero drift (the import surface 12/12 files byte-identical, 25/25 externs in place, the sci side rebuilt with zig build sa-std-static + nm checked 15 sa_task_* symbols); acceptance ALL PASS with the 209-name set identical by name to the poll baseline, zero tests lost; the poll regression on the same binary was ALL PASS + poll_stress 13/13; goroutine_stress 13/13 (the 13 poll scenarios restated one by one, the retirement registry complete, no scenario discarded). Same-window bench against Redis 7.0.15 (the in-repo script's stance, the median of each cell, poll and goroutine run back to back in two rounds in the same window): at P=1, the base group under goroutines was about 6.0–6.2k ops/s, uniform across all commands (poll 12.7–16.2k), gor/poll 0.38–0.48, and the ratio against Redis 0.065–0.077 (poll 0.12–0.20); the uniformity is precisely the handoff-bound fingerprint — four chan handoffs per command (inbox → connection, cmd → executor, done → connection, io_out → driver) plus driver rotation, p50 about 8.0–8.3 ms (poll 2.8–3.6 ms); pipelining ×16 narrows it to 0.72–0.80×; client scaling under goroutines went c1 2,429 → c10 4,832 → c50 5,862 ops/s, with the saturation point in the delivery pipeline rather than in command execution (single-client RTT 0.41 ms vs poll 0.075 ms). fsync=always was consistent across three windows: both models at about 200 ops/s (host disk sync about 5 ms serial; without group commit that is the whole story, and the model difference is noise), Redis about 4.7–5.7k (group commit, about 23×); after each round the records were verified to exist in the AOF file. A diagnostic supplementary test (a 10k key space, not a gate scenario): set poll 4,393 / goroutine 3,340, get poll 16,540 / goroutine 5,696. Reading (the charter's stance): the structural gains (elimination of the fourth-surface class, connection isolation, supervision) have been bought; the throughput gap is attributed to std data structures and per-command overhead + the newly quantified handoff term, the latter belonging to runtime scheduler maturity (the DEF line), not to command code. Nine surfaces in the runtime defect registry (forwarded to the DEF line): A, net-wait starvation between goroutines (when ≥2 goroutines block on net IO, only about one waiter is served and the rest of the data is delivered only after the first waiter exits; tuning the carrier count has no effect); B, calling a readiness wait (poll_wait) inside a spawned goroutine starves chan delivery process-wide (the same loop on the main frame is normal, which is why the driver sits on the main frame); C, a chan operation inside a never-returning loop body ratchets stack_alloc per iteration without rewinding and leaks the fixed stack (a bare recv overflows 256 KiB in a few thousand iterations, select leaks in proportion to the number of arms; same family as slanginx's stack-ratchet DEF-4; writing it into a called function rewinds cleanly, and the whole repo works around it with the “thin loop + step function” engineering rule); D, &(*p) borrowing a boxed value struct is unsound (in fact a shallow temporary borrow: scalar field reads are wrong and callee modifications land in a phantom; an early build silently disabled AUTH because of this; the sound form is borrowing an owned value field in place inside a heap block); E, pushing into a heap struct's Vec field inside a goroutine loop overflows the stack (suspected to share C's root; the trigger boundary is for the DEF line to map); F, SIGPIPE kills the process (a client closing mid-reply kills the whole process; both models are equally exposed, and there is no signal API within the drift surface; a genuine production exposure); G, a listener handle must use the listener-specific nonblocking extern (the stream version fails to start on it); H, one case of a codegen crash with no location (triggered by a tuple-destructuring + borrow-inside-select form, passing after restructuring; the triggering construct is undetermined, and both forms are recorded); I, a goroutine hot loop eats the fixed stack (an EOF socket keeps spinning read-interested; same family as C; the shipped driver is immune by construction). Errata: two sets of bench-attached numbers in the first pushed version (the fsync=always comparison and the diagnostic supplementary test) came from that line misreading interleaved background output; they have been corrected against the surviving raw output, with one errata commit each (namely 53092b0 / c0e4788 above), and the relevant sections of the delivery record docs/GOROUTINE_DELIVERY.md carry ERRATUM notes; all other numbers come from foreground verbatim output, and the main-line conclusions — the fourth surface closed, the 209-name set, the form and the main-grid deltas — are unaffected. With this, the Ordering Two goroutine rework of the three machines has fully landed.

7. Implicit-Interface Census Conclusions and the Jev Ruling (2026-10-29)

Per the Section 2 ranking, implicit interfaces are ruled separately after a census. The census is complete (2026-10-29, four sources: the sala documentation, the sa_plugin_sla demos, the sa_plugin_sla tests corpus, and sci's sa_std inventory; the census report is at ~/workspace/impliface-census/CENSUS.md).

Census conclusion: SLA's interface-satisfaction judgment is purely nominal, with zero structural component.

  • Satisfaction judgment = an explicit impl registry: the checker registers each impl Trait for Type under the key "{trait}|{type}" (type_checker.zig:2365-2375); a type whose method set fully matches but which has no impl block written = does not satisfy that trait. All three impl-completeness checks are present; there are no orphan / coherence rules.
  • Trait bodies are signature-only: no default implementations, no associated types / constants. Super-trait support is on record; dyn Trait is true dynamic dispatch (a 16-byte fat pointer); but the vtable is emitted per impl by the two backends — with structural satisfaction (no impl) there is no vtable to point at, and a new, dual-backend-isomorphic (interface, type) vtable synthesis path would have to be built; that is the structural proposal's largest hard cost.
  • The usage surface is extremely thin: of 1572 .sla files, only 15 declare a trait and 5 use dyn, all from Rust-alignment rosetta demos and unit tests; sci's sa_std (.sai / .sla) declares zero traits. Within the four sources there is no structural-satisfaction consumer waiting; the original motivation, go2sa, has been paused by user order (see Document 14).

Decoupled registry item (kept separate from this section's ruling, not disposed of in a bundle): generic bounds are an empty shell. <T: Trait> is parsed by the parser and then discarded outright (parser.zig:1026 consumes only the identifier and does not save it; the AST's generics store only names); neither the checker nor monomorphization has any representation of a bound — writing a bound has no effect, and there are only 2 actual uses in the corpus. This is a silent-misleading point; the stance is registered first as above; the follow-up direction = a loud diagnostic (a bound that has no effect must error / warn), scheduled as an independent small batch, not bundled with the implicit-interface ruling.

Jev ruling (2026-10-29, jev-1.14.0, item-by-item noul, ruling file ~/workspace/jev-designs/implicit_interfaces_ruling.json):

  • A, do not do it: 0.83 — keep purely nominal satisfaction.
  • B, structural only on the dyn side, limited to read-only method sets: 0.05 — requires building a new dual-backend vtable synthesis.
  • C, full structural (including implementing the bound system): 0.04 — also requires first carrying the full price of implementing generic bounds.
  • D, an explicit conform Trait for Type; declaration: 0.81 — after the compiler checks the method set it goes through the existing nominal registration and vtable emission; the user is spared writing forwarding impl blocks, the two backends change not at all, and the declaration point keeps the explicit doctrine.

Main-session disposition (default agreement with Jev): structural (implicit) interfaces are not adopted — A wins, and B / C are explicitly rejected. D is not an implicit interface but a boilerplate-saving convenience inside the nominal system; it is registered as an independent candidate with no schedule, to be discussed again when a real consumer appears (such as a go2sa revival). Also noted for slars consistency: the slars charter has Rust-style nominal traits and shares lowering and the dual codegen with SLA, so unilateral structural satisfaction in SLA would create a satisfaction-semantics fork in the shared layer — this point also supports non-adoption.

Supplementary note (2026-10-29): the decoupled registry item above, “generic bounds are an empty shell”, has been ruled separately. A census of its appearance surface (at ~/workspace/bounds-local/CENSUS_USES.md) exhaustively covered the whole tree's .sla files: bounds actually appear only in two rosetta places (31_trait_static_dispatch, 170_marker_traits, both Rust comparison demos that do not depend on the bound being checked), and in tests and sla_std there are zero; probe evidence shows a bound's name is not even checked for existence (<T: NoSuchTrait> also checks with rc=0). Jev ruling (2026-10-29, jev-1.14.0, ruling file ~/workspace/jev-designs/bounds_diagnostic_ruling.json):

  • Option 1: turn it into an error, and in the same batch fix the two rosetta demos 31 / 170 into bound-free form, with the demo.md notes and the syntax-matrix stance corrected in sync: 0.93.
  • Option 2: turn it into an error, but exempt the rosetta demos: 0.11.
  • Option 3: warning only: 0.07.
  • Option 4: implement the bound system for real (parser saves it + the checker solves it): 0.06.

Main-session disposition (default agreement with Jev): adopt Option 1. Writing a bound produces a loud error; since the appearance surface is only the 2 rosetta places and tests / sla_std are zero, turning it into an error has zero collateral-damage surface. The implementation line is in progress (local staging ~/workspace/bounds-local; its completion and gate status follow its final report); the original erroneous stance in the syntax matrix of Document 09 (“bounds are used for trait method lookup only at monomorphization time”) has been corrected in sync.
