一、用户定案：周边语法成套引入「底层」（2026-10-29）

用户定案（2026-10-29 10:20）：一切配合 goroutine 周边的语法都要引入 SA 底层，成套引入、不零敲碎打。

「底层」的口径（主会话收敛，承 2026-10-27 底座定案）：机制进 sa_std 运行时核心（调度器 / 通道 / select / sync / netpoller 胶水 / 边界 trap 承接点），语法面进 SLA 一等语法（go/spawn、channel、select、defer、recover 监督）；SA 规约本身（寄存器 + 所有权/能力规约）不动，仍是一切前端的共同目标，不为任何单一前端让路。

周边全集 = 已裁定的 goroutine 本体（见 13 号文档）+ defer + goroutine 边界 recover/监督 + context 式取消约定（std 规范、非语法，见第三节）。

三、各候选的设计要点

  • defer：作用域退出时按 LIFO 执行登记的清理动作——是任意动作、不止 drop（owned 值的自动释放已有 drop 机制，defer 覆盖的是 drop 之外的清理）；与 sync 原语的 lock(); defer unlock() idiom 配套交付。（已落地：块作用域 LIFO + 参数快照，见 13 号文档第十五节例 4。）
  • recover：仅在 goroutine 边界承接 trap——记日志、重启或降级，使单条连接的故障不拖死整个进程。明示：不是通用异常系统、不替代 Result 错误处理，普通代码的错误仍走 Result + 传播符。（已落地：边界 trap + supervisor.sla 监督重启，见 13 号文档第十五节例 5、例 6。）
  • 编译期嵌入（embed）：编译期读文件、落数据段，供单二进制部署携带静态资源/模板；路径纪律与构建可复现性待该批设计时处理，不预设。
  • 隐式接口：结构满足（有方法集即实现）+ 消费方定义小接口。是语言级承诺，须普查先行（SLA 既有泛型 / trait 面的对齐盘点），普查后再单独裁定，不阻塞 goroutine 程序。
  • context 式取消约定：不是语法，是 std 规范——一个可 select 的 Done 通道（或等价形态）沿调用链传递取消信号，随通道批一起立规范。（已落地：sa_std/ctx.sla 惯用法，见 13 号文档第十五节例 7。）

四、落选记录

  • Go error 语法：不引入。SLA 已有 Result + 传播运算符且更优；只取其「错误是值」的原则一条——该原则本已在 SLA 内。
  • iota、命名返回值等多重小糖：不引入。SLA 有等价物，引入只增表面积。
  • struct 嵌入：不引入。与所有权组合时语义易浑，显式字段转发足够。

六、对三台目标项目的帮助评估（主会话评估，2026-10-29）

总纲：帮助主要在并发结构、健壮性与开发速度，不在单机吞吐数字。三台的 99% 缺口此前归因都不在并发模型，goroutine 不直接抬性能数字。

  • slanginx（帮助最大）：其 F2 并发 serve 本缺原生形态，goroutine 给出 per-connection 顺序处理器、反向代理双向泵（两个 goroutine + 通道）、context 取消上游；recover 监督使单连接 trap 不杀进程，是现完全没有的健壮性档位。不帮的部分：每请求内存斜率的残余怀疑在 std http/string 文本机器内部，属 F-perf 线；多核 serve 从无到有算中等偏正，热点优化仍是另一条线。
  • slaredis（结构帮助大、吞吐帮助有限甚至可能微负）：poll 循环 + 分片等待集的手工状态机可整体消失；解锁阻塞命令类功能（BLPOP 在事件循环里要挂起连接 + 超时队列，在 goroutine 里是顺序代码）；过期处理与 AOF 写入管道（专用 goroutine + 通道喂批）变自然。但其性能平台期实测仅为 Redis 的 0.12–0.19，归因在 std 数据结构与每命令开销，goroutine 不关此缺口；高频小命令下上下文切换比紧凑 poll 循环略贵。
  • db（帮助中等偏小，在接入层不在引擎）：epoch 快照模型已把读扩到核数（8 线程列和实测 15,386/s），不靠 goroutine。受益两处：中转站查额度场景的 SLA 服务层（并发查询 goroutine 各自钉快照、扣减经通道汇到单写者，即 group commit 的语言级形状，现为手搓锁与队列）；应用从 SLA 并发使用 db 不再手管线程。点读对 SQLite 的延迟缺口在 per-exec 校验，goroutine 不碰。
  • 跨三台共同项：三套手搓并发收敛为一套语言级模型，bug 面与维护面同步收缩；defer 使「资源忘了放」类泄漏问题三台同降一档；监督语义给两个网络服务器统一的崩溃隔离。
  • 诚实保留：v1 是协作式调度，纯计算不让出会饿死同伴；调度器成熟度与尾延迟比不了 Go 十年打磨——须在三台改造验收中实测盯住，不默认与 Go 一样顺滑。

一句话收敛：slanginx 是补心脏，slaredis 是拆状态机加解锁阻塞命令，db 是给接入层发并发驾照；三台的性能 99% 仍各自归 std 热点线。

七、隐式接口普查结论与 Jev 裁定（2026-10-29）

按第二节排序，隐式接口候普查后单独裁定。普查已完成（2026-10-29，四出处：sala 文档、sa_plugin_sla demos、sa_plugin_sla tests 语料、sci 的 sa_std 清单；普查报告存 ~/workspace/impliface-census/CENSUS.md）。

普查结论：SLA 的接口满足判定为纯名义式，零结构化成分。

  • 满足判定 = 显式 impl 注册表：检查器把每个 impl Trait for Type 以 "{trait}|{type}" 键登记（type_checker.zig:2365-2375）；类型的方法集全对得上但没写 impl 块 = 不满足该 trait。impl 完整性三查俱在；无孤儿 / 一致性规则。
  • trait 本体为签名-only：无默认实现、无关联类型 / 常量。超 trait 支持在册；dyn Trait 是真动态分发（胖指针 16 字节）；但 vtable 由两后端按 impl 逐个发射——结构化满足（无 impl）即无 vtable 可指，须新造双后端同构的（接口，类型）vtable 合成路径，这是结构化方案的最大硬成本。
  • 使用面极薄：1572 个 .sla 文件中仅 15 个声明 trait、5 个用 dyn，全部来自 Rust 对齐 rosetta demo 与单元测试；sci 的 sa_std（.sai / .sla）零 trait 声明。四出处内没有任何在等的结构化满足消费方；原动机 go2sa 已按用户令暂停（见 14 号文档）。

解耦登记项（与本节裁定分开，不捆绑处置）：泛型约束是空壳。<T: Trait> 被 parser 解析后直接丢弃（parser.zig:1026 只消费标识符不保存；AST 的 generics 只存名字），检查器与单态化均无 bound 表示——写了约束也不生效，语料中实际用例仅 2 处。此为静默误导点，口径先行入册如上；后续方向 = 响亮诊断（约束不生效须报错 / 警告），作独立小批另行排期，不与隐式接口裁定捆绑。
