CXU 完整 SLA 重构路线图

状态已立项（2026-10-25 用户定调：详细规划 SLA/SA、完整重构 CXU、安排优先级、随即开工）。依据是同章的就绪度审核。本页是执行计划的权威版本：分期、优先级、验收标准与状态都在这里滚动更新；每完成一项即勾状态并注明提交。

总目标与原则

  • 目标：CXU（codex-react-ui）的服务端（约 5.9 万行 TS）、各 CLI 桥（约 6.5 万行 TS）与 Web 前端（约 8.8 万行 TSX）全部以 SLA 重写，最终形态为 SLA 原生后端 + SAX/WASM 前端；Electron 桌面壳在 P4 单独裁决。
  • 行为对齐：重构以现有 TS 版为行为基准（HTTP/WS API 面、桥协议、配置格式不变），前端在 P3 之前可原样指向新后端使用；差异必须显式记账，不做静默改动。
  • 地基优先：先补 sa_std 与 SLA 编译器的阻塞项，再写业务；基础核心一律内置 sa_std，插件只做封装（既有方针）。
  • 并发模型定死：后端并发走线程 + mpsc，不押注 async（跨 async fn 嵌套 await 尚未收敛，见成熟度总表）。
  • 无静默回退：撞到 UnsupportedSabDirectFeature 或缺失能力，记账到本页缺口表并先补地基，不绕路糊过去。
  • 节奏：串行推进（本机与 Colab 资源约束），每项完成即提交推送，Colab 侧 15 分钟检查点照旧。

P1 后端试点纵切（codex 桥）

  • 形态：新 SLA workspace（布局效 scodex-mini 的 packages 分包）：config（TOML/env）、bridge-core（双向 spawn + JSON-RPC 分帧/多路复用）、http-ws-server（基于 sa_std 内置服务器的路由与会话层）、codex-bridge（对 codex app-server 的完整协议适配）、store（SQLite 经 db 插件的会话/历史持久化）。
  • 验收：真实 codex CLI 经 SLA 后端跑通一轮完整对话（发起、流式事件、工具调用、打断、恢复）；现有 React 前端不改代码指向 SLA 后端可正常使用（API 面子集对齐）；与 TS 版同场景行为对照表逐项勾验。
  • 产出：一份「撞墙清单」——试点期撞到的全部 Unsupported/缺失能力与绕行成本，回填 P0/P2 排期。

P2 后端全面迁移

  • 其余 CLI 桥逐个迁（claude、opencode 双后端、agy、auggie、cline、command-code、grok、pi、mini 等），复用 P1 的 bridge-core；每个桥沿用「只能经 SDK/标准面」的纪律（对应 SLA 侧即 sa_std + sla_std）。
  • 服务端其余面：free-key server、账户与认证（bcrypt/keyring 落地）、postgres（如实证在用）、静态文件与产物服务、隧道/公网入口形态对齐、配置 schema 同步工具。
  • 验收：TS 版服务端下线前，全部桥与 API 面对照测试绿；双版本并行期以同一前端交叉验证。

P3 前端（SAX 应用框架化 → 逐屏迁移）

  • 先框架后界面：SAX 补应用级能力——状态管理与数据绑定（脱离静态占位模型）、路由、表单/快捷键体系、airlock 高频流更新的压测与优化（token 流场景）、虚拟化列表。
  • 重组件逐个裁决：代码视图与 diff（可基于 tree-sitter 大纲/高亮自建）、终端（PTY 已在后端，前端渲染要 xterm 级能力，WASM 自建或 JS 岛共存二选一并记账）、Monaco 级编辑器是独立子课题（先以轻编辑 + JS 岛过渡，不假装等价）。
  • 验收：按屏迁移，每屏与 React 版做功能对照表；全部主流程（对话、终端、文件、设置、任务）走通后才谈 React 下线。

P4 桌面壳与发布

  • Electron 壳去留裁决：保留（只换页面产物）或以原生/Web 形态替代；Windows 打包、签名、PTY 原生件、混淆与安装包流程在此期对齐 TS 版现状。
  • npm 分发与插件渠道沿用既有形态（后端产物即 sa 插件/独立二进制两种形态在开工时定）。
