一、支线三探针：总判与定位

三条支线的共同定位（用户 2026-10-29 18:32–18:38 先后定）：不立项、不落代码、仅讨论与研究；研究的价值不在方向本身先行，而在以外部目标为探针，照出我方栈（SLA / SA / sa_std / SAX）自身未明文的语义与缺失面——sla2ts 线更被明确订正为「挖掘底层不足为首要目的，安全性 / 保真不是考虑的优先级」。三份研究报告存本机 ~/workspace/sla2mobile/FEASIBILITY.md、~/workspace/sax-crossplatform/FEASIBILITY.md、~/workspace/sla2ts/FEASIBILITY.md，登记册原件存 ~/workspace/foundation-gaps/REGISTER.md；本页第三节即登记全表的落字版。

  • 探针一 · 移动转译（sla2swift / sla2kotlin）——总判：有条件可行。发射层级唯一可行 = 单态化后 + 检查后 AST（lowering 前）：泛型已实例化（泛型映射与约束空壳问题整体消失）、并发构造仍是原生节点、所有权信息可见，且正是现有 syntax_lowering 与双 codegen 的共同输入形态；SA 寄存器层发射对客户交付不可行（产物不可读）。两目标难度不对称：Kotlin 侧整体顺（Channel / select 近直映，主要成本在所有权拷贝纪律）；Swift 侧所有权面更贴（~Copyable 近 1:1），但标准库无通道、无 select，actor 自建通道 + 多路等待是全案最重的单件工程。直映面含 async/await、状态码模型、trait 静态分发；String 两侧均须支持面字节串类型承接（SLA 是 UTF-8 字节串语义）；拒绝面 = 原始指针 / 布局依赖 / 宏定义 / 子集外 extern。支持面量级 Swift 约 4–7 千行、Kotlin 约 2–3.5 千行；双目标 v1 约 2–4 人月（未校准估计）；验收法 = 三方差分对拍（SA 原生 vs Swift vs Kotlin 同程序）。
  • 探针二 · SAX 跨平台 UI（五面：web / Windows / iOS / Android / TUI）——总判：有条件可行。三条件全在 SAX 语义层：① 布局 / 样式语义入 SAX（现状布局全靠浏览器 CSS、SAX 自身零布局语义，是头号地基）；② 原语契约补语义 / 无障碍通道与能力协商通道；③ 声明式子集剖面成文。路线以 (c) 宿主胶水泛化为骨干（web 链即活证：约 25 个宿主 extern、JS 桥只用 8 类 DOM 操作），(a) 原生控件映射降为其宿主实现策略，(b) 自绘被文本引擎零存量卡死只作 sidecar。落地顺序建议：web 基线 → TUI（最便宜的新面、首验地基）→ Windows via WebView2 → WinUI 原生后置 → iOS / Android 最后（与转译线耦合最深）。移动交叉倾向：SAX 声明式子集转译落 SwiftUI / Compose（设备侧运行时交付的是 SA 黑盒，与客户只收源码的裁定相悖），命令式 dom_* 逃逸须响亮拒绝并成文为 profile。
  • 探针三 · sla2ts（SLA → TypeScript）——首要产出：26 条底层不足（TS-1…TS-26，见第三节附表）；可行性只作次要速判：差分测试资产用途成立（回报最直接——对拍分岔的归因过程正是 26 条的取证过程）；npm 纯逻辑交付与迁移回退路条件成立；前端共享与 CXU 已定的 wasm 路线冲突、不成立。发射层级 (b) 复核成立且更硬：现行管线单态化（:683）先于检查（:723)，层级 (a) 在管线中根本不存在；数字表示（number vs BigInt）须按具体类型定型。
  • 附 · slats 定性（消歧）：GitHub 仓 layola13/slats（HEAD b5ff4b83）不是 sla2ts——它是把 tsrs（TypeScript 编译器的 Rust 重写）移植进 SLA 的工程，方向与 sla2ts 相反（以 SLA 为实现语言写一个 TS 编译器，属 X→SLA 流入家族）。真转完的只有 span-map 管线（spanmap 15/15)，其余为 pending 镜像桩。它浮现的两个我方缺陷已登记为候选 16 / 17（待核）。
