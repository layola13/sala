1. Scope and Method

Scope (2026-11-17 13:05, ruled by the user): a fix that turns a silent error into a loud rejection counts as fixing a bug, not a new feature, and is not subject to the new-feature freeze; the census results are submitted to the user for review first, and only after review passes is a DEF created and a repair line dispatched. The motivation is of the same family as transfer: silent fallbacks (swallowing errors, literal default values, skipping via empty arms) turn errors that should be loudly rejected at compile time into runtime leaks, false-green evidence, or stale state.

Method: read-only grep over the two repositories' src/*.zig for five forms — large-switch empty arms else => {}, catch {}, catch |_| with a default value, literal orelse, and emitter implicit no-ops / rc=0 work skips; hits were counted first, and then the key surfaces (ownership / layout / offsets / capability bits / emission / verification) were read in context one by one for classification. Pinned versions: sci 0c4cb7be × sa_plugin_sla 42085bb9 (both trees clean, tag 0.1.9 lineage). All classifications are based on static reading, with no reproduction probes; items marked “latent / scalability” need a probe from the owning line to grade them before deciding whether to fix them.
