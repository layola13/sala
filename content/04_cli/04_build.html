sa sla build

sa sla build compiles a .sla source file into a verified SA assembly text file. After reading this page you will know how to control the output path, and where the artifact lands when --out is not specified.

Syntax

usage: sa sla build [file] [-p <package>] [--out <file>]

Parameters

NameDescription
fileThe input .sla source file; when omitted, the member entry point is resolved via the workspace (see the “sa sla check” page).
--out, -oThe output .sa file path. When omitted, the input extension is replaced with .sa by default: main.sla → main.sa (for non-.sla input, <file>.sa), written next to the source file.
-p, --packageSelect the member package in workspace mode.
-h, --helpShow usage and return 0.
NoteWhat this command produces is .sa assembly in text form — this is SLA's production-path output, and all frontends uniformly output only SA text. To produce SAB bytes (a sealed optimization direction, explicit opt-in only), use sa sla sab build.

Examples

# 输出到 /tmp
SA_PLUGIN_DEV=1 sa sla build demos/rosetta/13_array_sum/main.sla --out /tmp/13_array_sum.sa

# -o 与 --out 等价；省略时写在源文件旁
SA_PLUGIN_DEV=1 sa sla build tests/test_unit_basic.sla --out /tmp/test_unit_basic.sa
SA_PLUGIN_DEV=1 sa sla build src/main.sla          # 生成 src/main.sa

# workspace 成员
SA_PLUGIN_DEV=1 sa sla build -p my_app --out /tmp/my_app.sa

Output locations

  • With an explicit --out/-o: written to that absolute or relative path; the parent directory must already exist.
  • When unspecified: written to <stem>.sa in the same directory as the source file.
  • This command does not write .sla-cache/sab/; managed SAB artifacts are produced only by explicit SAB commands.

On success, stdout prints:

Sla Compiler: Successfully compiled main.sla to /tmp/main.sa.
