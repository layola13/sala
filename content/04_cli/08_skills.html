sa sla skills and stability

sa sla skills lists the capabilities the SLA plugin exposes to the host, and can generate skill files for coding agents; sa sla stability validates downstream stability metadata manifests. After reading this page you can obtain a machine-readable capability list and generate an agent skill.

sa sla skills

usage: sa sla skills [--json]
NameDescription
(no arguments)Text mode: print the capability sections, and write the skill files to .codex/skills/sla/SKILL.md and .claude/skills/sla/SKILL.md in the current directory.
--jsonOutput only the machine-readable capability JSON to stdout, writing no files. When the host invokes it with the global --json, this mode takes effect automatically.
-h, --helpShow usage and return 0. Unknown options report an error and return 1.
# 文本模式 + 生成 agent skill 文件（在项目根目录运行）
SA_PLUGIN_DEV=1 sa sla skills

# 只看机器可读清单
SA_PLUGIN_DEV=1 sa sla skills --json
SA_PLUGIN_DEV=1 sa --json sla skills        # 宿主全局 --json 等效

Output locations: in text mode, .codex/skills/sla/SKILL.md and .claude/skills/sla/SKILL.md are generated in the current working directory; JSON mode produces no files at all.

sa sla stability

Validates a downstream stability metadata manifest, without assigning any semantics to the downstream labels. The subcommand has two forms:

UsageDescription
sa sla stability schema [--json]Output the JSON schema of the stability metadata to stdout. --json is accepted only for consistency; the output itself is already JSON.
sa sla stability verify <manifest.json> [--json]Validate a downstream manifest file; by default it outputs a human-readable report, and with --json a machine-readable report. Returns 0 when validation passes, 1 when it fails.
# 先导出 schema 作为编写参考
SA_PLUGIN_DEV=1 sa sla stability schema > /tmp/stability_schema.json

# 校验一个清单
SA_PLUGIN_DEV=1 sa sla stability verify stability.json
SA_PLUGIN_DEV=1 sa sla stability verify stability.json --json
Noteverify must be given a manifest path; when missing it reports Missing stability manifest path and prints usage. The evidence field in a manifest often references a verification command such as SA_PLUGIN_DEV=1 sa sla test lib/parallel.sla --test-backend sab.
