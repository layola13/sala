4. Core conclusions

  • Correctness: the same SA program produces consistent output on all four ways (MEM OK); 24B×1M OOMs only on JS due to the 16MB hard cap, as designed.
  • Speed: native is fastest; wasm/node is about 2~3x native; sa→js+node about 7~10x; sa→js+bun is slowest on BigInt loops (under the same workload, u64 accumulation is 19.2x the u32 one, see the peer page §3; bun's BigInt ops are markedly slower than node's). After the literal fix, the u32 loop on bun is already within 4.1x native.
  • Memory: RSS is dominated mainly by the runtime startup baseline (node starts at ~50MB, bun at ~35MB); native is the most economical per byte.
  • Basis statement: all JS numbers on this page come from artifacts compiled from SA source; the hand-written JS comparison series in historical versions has been removed under the “SA only, no hand-written mjs” rule.
  • Next step: for the Bun official bench peer test, see the peer page; slot-to-local-variable promotion for bulk memory operations is the next optimization point.
