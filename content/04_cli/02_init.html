sa sla init

sa sla init creates a minimal SLA binary project skeleton. After reading this page you can generate a compilable new project with a single command.

Syntax

usage: sa sla init [path]

Parameters

NameDescription
pathOptional. The project directory; when omitted, the current directory .. If the directory does not exist it is created automatically (including the src/ subdirectory). Only one path may be given; extra arguments or unknown options starting with - cause an error exit.
-h, --helpShow usage and return 0.

Generated files

FileContent highlights
<path>/sa.modFirst line # generated by sla init, followed by one line package "<name>". <name> is the basename of the path; when the path is . or no name can be obtained, app is used.
<path>/src/main.slaMinimal entry point: fn main() -> i32 { return 0; };
<path>/.gitignorePre-populated with .sla-cache/, .zig-cache/, .sa_cache/, zig-out/, *.out, *.sa.bc.
Warninginit does not overwrite existing files: all three files are written in “create new” mode, and if a file with the same name already exists at the target location it reports File Error: failed to create ... and returns non-zero.

Example

Create a new project in /tmp/sla_app and verify it immediately:

SA_PLUGIN_DEV=1 sa sla init /tmp/sla_app
cd /tmp/sla_app
SA_PLUGIN_DEV=1 sa sla check src/main.sla
SA_PLUGIN_DEV=1 sa sla build-exe src/main.sla -o /tmp/sla_app/hello

Output locations

init itself only generates the three source files above and produces no build artifacts. The managed SAB artifacts produced by later compilations live in the project's .sla-cache/sab/, and that directory has already been written into .gitignore automatically.
