CLI Commands in Detail

Through the database capability section, the db plugin registers 14 sa db subcommands with the host CLI, covering schema initialization, data import, indexes, snapshot/restore/repair/verification/merge, locking, and the registration and execution of qmod queries. This page gives the syntax, parameters, artifacts, and exit behavior of each one; all of the commands are implemented in the plugin's src/plugin.zig.

Common conventions

  • The table root directory is fixed to the current working directory. Every command passes . internally as the root to the table layer, so they must be run in the directory where the target table lives.
  • The argument count is strictly checked. Extra arguments return error.UnexpectedArgument, missing ones return error.MissingSourcePath; both go through the unified error output and end with exit code 1.
  • Development-mode prefix. A plugin installed with --dev needs SA_PLUGIN_DEV=1 to be loaded; the examples in README_cn.md and docs/qmod_examples.md all carry this prefix.
  • A unified table-information output format. On success most commands print four lines: row_count, segment_count, epoch, and locked (true/false).
  • A unified error output format: two lines, the first error[SA-DB-CLI]: <message>, the second the indented help: <hint>, with exit code 1.

Table creation, import, and indexes

sa db init <schema.sadb-schema>

Reads and compiles a schema file (16 MB limit), and generates a .sai interface file of the same name in the same directory as the source file. The table name is taken from the file name with the .sadb-schema suffix removed, and must be a valid identifier.

The generated .sai preserves all of the schema's #defs verbatim; if TABLE_ROW_BYTES is not declared it adds the computed value, and then adds a <table>_ROW_BYTES alias:

# 输入 members.sadb-schema
#def MAX_ROWS = 50000
#def COL_ID_STRIDE = 8 // u64
#def COL_PLAN_STRIDE = 8 // u64
#def COL_STATUS_STRIDE = 8 // u64
#def COL_POINTS_STRIDE = 8 // u64

$ SA_PLUGIN_DEV=1 sa db init members.sadb-schema
members.sai

$ cat members.sai
// generated by sa db init
#def MAX_ROWS = 50000
#def COL_ID_STRIDE = 8
#def COL_PLAN_STRIDE = 8
#def COL_STATUS_STRIDE = 8
#def COL_POINTS_STRIDE = 8
#def TABLE_ROW_BYTES = 32
#def members_ROW_BYTES = 32

sa db ingest <table> <csv|jsonl>

Compiles CSV or JSONL data into columnar segments and appends them to the table, printing the table information on success. The first CSV line is the column names, and the column order must match the schema:

$ cat rows.csv
ID,PRICE
1,9.5
2,10.25

$ SA_PLUGIN_DEV=1 sa db ingest flash_sale rows.csv
row_count: 2
segment_count: 1
epoch: 1
locked: false

sa db index-u64 <table> <column-index> [unique]

Builds a persisted index for the u64 column with the given column ordinal. column-index is a decimal integer; the sixth argument must be the literal unique (any other value reports unexpected DB argument). With unique it becomes a true uniqueness constraint: creation rejects existing duplicate values, and a later write producing a duplicate key gets a constraint violation, with the active manifest staying at the previous valid epoch.

SA_PLUGIN_DEV=1 sa db index-u64 members 0          # 第 0 列普通索引
SA_PLUGIN_DEV=1 sa db index-u64 members 0 unique   # 同一列唯一索引
NoteThe CLI's index-u64 covers only single-column u64. Indexes for u8/u16/u32/i8/i16/i32/i64/f32/f64, composite keys, and blobs must be created through the SA API's sa_db_create_*_index or the macros DB_CREATE_*_INDEX; see API Group 5.

Operations and recovery

None of the following six commands accepts extra arguments, and on success they print the same set of four lines of table information.

CommandBehaviorTypical failure
snapshot <table>Backs up the current metadata, structure, and all data segments to .sa/db/snapshots/<table>/<epoch>/Path not writable
restore <table> <epoch>Rolls back to the specified snapshot generation; epoch is parsed as a u64, and a non-number reports an invalid DB schema format class of errorsnapshot not found
recover <table>Scans the versioned metadata files and rebuilds the manifest to the highest valid epoch; handles a manifest corrupted or missing after an interrupted commit, and cleans up stale pending markersverify failed
verify <table>Verifies the schema hash, segment hashes, segment block-level hashes, index hashes and shape/ordering, dictionary hashes and entry counts, blob store hashes, the recorded byte counts, and the expected size of rows * column_strideverification failed
compact <table>Rewrites multiple scattered column segments merged into a single segment, improving read throughput; rebuilds the persisted indexesTable is locked
lock / unlocklock sets the table read-only, rejecting writes and imports; unlock first re-verifies consistency and then clears the read-only flagtable is locked
# 归档流程：先校验，再快照，最后锁定
SA_PLUGIN_DEV=1 sa db verify   flash_sale
SA_PLUGIN_DEV=1 sa db snapshot flash_sale
SA_PLUGIN_DEV=1 sa db lock     flash_sale

# 锁定后再写入会被拒绝：
# error[SA-DB-CLI]: DB table is locked
#   help: unlock or restore the table before writing

SA_PLUGIN_DEV=1 sa db unlock   flash_sale
SA_PLUGIN_DEV=1 sa db restore  flash_sale 3

qmod queries: register and exec

sa db register <query.sa>

Compiles query source code and registers it in the qmod registry, assigning a SHA-256 fingerprint. Registration performs a capability check: an instruction accessing an unauthorized table or column will be refused registration (capability escalation).

$ SA_PLUGIN_DEV=1 sa db register sum_ids.query.sa
Compiled: sum_ids.query.sa
Hash: a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f60718293a4b5c6d7e8f90
Registered: .sa/db/qmods/a1b2c3d4....qmod
imports: 1
grants: 1

The artifacts are the <sha256>.qmod payload and the accompanying <sha256>.meta.json permission metadata. Registering the same source again with different grants or an entry point yields a duplicate register.

sa db exec <hash> [--params <file>]

Executes a registered qmod. The parameters have only three legal forms: <hash>, or <hash> --params <file>. The hash must be a 64-character hexadecimal string, otherwise it reports invalid DB query hash.

$ SA_PLUGIN_DEV=1 sa db inspect a1b2c3d4....      # 先看注册元数据
$ SA_PLUGIN_DEV=1 sa db exec a1b2c3d4....
Executed: main
result_u64: 8

The details of the exit behavior are worth noting:

  • When the function's return code is 0 it prints Executed: <function_name>, and if the result can be represented as an unsigned integer it prints another line, result_u64: <n>.
  • The process exit code equals the qmod function's return code. When it returns non-zero, no result lines are printed.
  • --params points to a binary parameter file; a layout or length mismatch reports invalid DB params format.
  • If the table metadata is modified concurrently during execution, you get a stale metadata.

sa db inspect <table|hash> and sa db status <table>

status is an alias for inspect; both go through the same implementation. The parameter dispatch rules:

  • Exactly 64 hexadecimal characters → treated as a qmod hash, and the registration metadata text is printed;
  • Length 64 but containing non-hexadecimal characters → reports invalid DB query hash;
  • Anything else → treated as a table name, verified, and the four lines of table information are printed.
SA_PLUGIN_DEV=1 sa db status flash_sale    # 表视角
SA_PLUGIN_DEV=1 sa db inspect flash_sale   # 等价
SA_PLUGIN_DEV=1 sa db inspect <hash>       # 查询模块视角

Minimal end-to-end flow

The sequence below comes from README_cn.md §7 and the plugin's own docs/qmod_examples.md, and can be reproduced in full in an empty directory:

# 前置：插件已 zig build 并 --dev 安装
cat > flash_sale.sadb-schema <<'EOF'
#def MAX_ROWS = 8
#def COL_ID_STRIDE = 8 // u64
#def COL_PRICE_STRIDE = 4 // f32
EOF

cat > rows.csv <<'EOF'
ID,PRICE
1,9.5
2,10.25
5,120.00
EOF

SA_PLUGIN_DEV=1 sa db init   flash_sale.sadb-schema   # 生成 flash_sale.sai
SA_PLUGIN_DEV=1 sa db ingest flash_sale rows.csv      # row_count: 3
SA_PLUGIN_DEV=1 sa db status flash_sale               # 观察段数与 epoch
SA_PLUGIN_DEV=1 sa db lock   flash_sale               # 进入只读归档
SA_PLUGIN_DEV=1 sa db verify flash_sale

For how to write the qmod query side and declare grants, see the Macro Usage and a Complete Example page; for the equivalent operations at the API layer, see The Eight SA API Groups; for performance and limits, see Limits, Performance, and Best Practices.
