SA API 八大分组

db 插件对 SA 暴露两层接口：db.sai 里的 native extern 声明（约 300 个 sa_db_* 符号） 和 db.sal 里的同名宏 facade（DB_*）。这一页按功能把 native 调用分成八大组， 给出签名与语义；每个签名都摘自仓库根目录的 db.sai。宏的展开写法与可直接编译的示例见 宏用法与完整示例。

命名与调用约定

  • 表级调用共享同一前缀：(&root: ptr, root_len: u64, &table_name: ptr, table_name_len: u64, ...)。 下文用 <table prefix> 代表这五个参数。
  • 返回值统一是状态码（-> u32），业务结果通过 &out_* 出参指针写回。 宏负责替你 stack_alloc 槽位并 load 回来。
  • 句柄类调用（事务、列会话、读快照）第一个参数是 handle: ptr，不再带 root/表名。
  • 分页契约统一：列表型查询都接受 offset/limit， 并返回 out_written 与 out_total。total 是过滤后的总匹配数， 因此分页不会因为先过滤再截断而丢行。

分组 1：建表与表级写入

// 初始化表：schema_path 是磁盘上的 .sadb-schema 文件，schema_source 是其文本内容
sa_db_init_schema(<table prefix>, &schema_path: ptr, schema_path_len: u64,
                  &schema_source: ptr, schema_source_len: u64, &out_info: ptr) -> u32

// 删除整张表（写锁文件会被保留以维持锁语义）
sa_db_remove_table(<table prefix>, &out_info: ptr) -> u32

// 批量列式导入：columns 是 SaDbColumnInput 数组
sa_db_ingest_columns(<table prefix>, row_count: u64,
                     columns: ptr, columns_len: u64, &out_info: ptr) -> u32

// 插入一条固定宽度行，布局必须与当前 schema 的列 stride 完全一致
sa_db_insert_row(<table prefix>, &row: ptr, row_len: u64, &out_info: ptr) -> u32

// 对一段连续行的某 u64 列做原地加法更新
sa_db_update_u64_add(<table prefix>, column_index: u64, start_row: u64,
                     update_count: u64, delta: u64, &out_updated: ptr) -> u32

语义要点：

  • init_schema 同时接收路径与内容，便于内存根（:memory:）场景不落盘也能建表。
  • insert_row 内部把行切成列切片后走同一条列 ingest 提交路径，所以同样推进 epoch 并重建持久化索引。
  • 所有写入都会推进表 epoch 并重建已有索引。

分组 2：按唯一键的行写路径

这一组的共同前提是目标列已经建立了同类型的唯一索引，因此具备主键语义而非普通匹配。 以 u64 为例：

// upsert：key 存在则原子替换，out_inserted=0；不存在则追加，out_inserted=1
sa_db_upsert_row_u64_key(<table prefix>, column_index: u64, expected: u64,
                         &row: ptr, row_len: u64, &out_inserted: ptr, &out_info: ptr) -> u32

// update：严格更新，key 缺失返回 SA_DB_ERR_NOT_FOUND，绝不追加
sa_db_update_row_u64_key(<table prefix>, column_index: u64, expected: u64,
                         &row: ptr, row_len: u64, &out_info: ptr) -> u32

// delete：按唯一键删除一行，重写剩余行到新列段
sa_db_delete_u64_key(<table prefix>, column_index: u64, expected: u64, &out_info: ptr) -> u32
键形态upsert / update / delete 后缀额外参数典型用途
u64 / i64*_u64_key / *_i64_keyexpected自增主键、编码日期/时间戳/金额分的 signed 键
u32 / i32 / u16 / i16 / u8 / i8*_{u32,i32,u16,i16,u8,i8}_keyexpected（对应宽度）状态码、渠道、仓库号、行号、小型外键、优先级
(u64,u64)*_u64_pair_keycolumn_index2, key1, key2(order_id,line_no)、(product_id,warehouse_id)
(u64,i64)*_u64_i64_pair_keycolumn_index2, key1, key2(i64)(customer_id,order_day)、(status_id,due_day)
blob 精确值*_blob_eq_key&store_name, store_name_len, &value, value_len单据号、客户/供应商编码、SKU、外部 ID

三条硬性校验规则（违反即失败且不推进 epoch）：

  • upsert/update 的 expected 必须等于行数据里 key 列实际编码出的值，否则返回 SA_DB_ERR_INVALID_FORMAT。blob 形态下则是行的 blob_handle 必须指向与 key 参数相同的字节。
  • update/delete 在键缺失时返回 SA_DB_ERR_NOT_FOUND。
  • 批量引入重复键时返回 SA_DB_ERR_CONSTRAINT，active manifest 保持在上一个 epoch。
注意哈希只用于缩小候选集。blob_eq 路径会把索引命中的候选行拿回真实 blob 字节做比对， 因此哈希碰撞不会选中错误的行。

分组 3：单表事务 tx_*

sa_db_tx_begin(<table prefix>, &out_handle: ptr) -> u32
sa_db_tx_insert_row(handle: ptr, &row: ptr, row_len: u64, &out_info: ptr) -> u32
sa_db_tx_insert_rows(handle: ptr, &rows: ptr, rows_len: u64, row_count: u64, &out_info: ptr) -> u32
sa_db_tx_add_columns(handle: ptr, row_count: u64, columns: ptr, columns_len: u64, &out_info: ptr) -> u32
sa_db_tx_dict_intern(handle: ptr, &dict_name: ptr, dict_name_len: u64,
                     &value: ptr, value_len: u64, &out_id: ptr, &out_inserted: ptr, &out_info: ptr) -> u32
sa_db_tx_blob_put(handle: ptr, &store_name: ptr, store_name_len: u64,
                  &value: ptr, value_len: u64, &out_id: ptr, &out_info: ptr) -> u32
sa_db_tx_commit(handle: ptr, &out_info: ptr) -> u32
sa_db_tx_rollback(handle: ptr) -> u32
  • 所有 upsert/update/delete 键形态都有对应的 tx_* 变体，参数只是把 <table prefix> 换成 handle。
  • 事务期间操作的是内存中的事务镜像；在 tx_commit 之前不会有新的表 epoch 或 manifest 发布。
  • commit 时按需写出变更行段、事务引用的版本化字典/blob artifact、重建全部持久化索引，然后一次性推进 manifest。
  • 纯字典或纯 blob 的事务也是合法的，会推进 epoch 但不重写行段。
  • 恢复机制：commit 先写 <table>.tx.<epoch>.pending， 在事务版本化 meta 落盘后再写可校验的 .commit 标记。recover 会忽略只有 pending 的 meta、 校验 commit 标记里的 meta hash 与字节数，并在 manifest 陈旧或损坏时补全已提交事务。
  • commit 失败（例如批次里出现重复唯一键）时旧 manifest 仍然可见，事务句柄被关闭； tx_rollback 直接丢弃镜像，不发布任何行或 blob handle。
  • 这是单表、单写者模型；读句柄仍只看到已提交快照。

分组 4：列批量会话 coltx_*

sa_db_coltx_begin(<table prefix>, &out_handle: ptr) -> u32
sa_db_coltx_add_columns(handle: ptr, row_count: u64, columns: ptr, columns_len: u64) -> u32
sa_db_coltx_commit(handle: ptr, &out_info: ptr) -> u32
sa_db_coltx_rollback(handle: ptr) -> u32

面向批量的写入会话，与 tx_begin 的关键差别是不在整个会话期间持有全局变更互斥：

  • add_columns 校验一批固定宽度列数据，在提交路径之外完成段文件暂存与哈希计算，产物仅本会话可见。
  • ABI 句柄注册表使用共享锁加每会话引用计数，不同 coltx 会话的暂存 I/O 不会再被一把全局互斥串行化。
  • coltx_commit 只取一次表写锁，把所有已暂存批次发布为新段、重建索引、推进一次 manifest。
  • coltx_rollback 丢弃所有暂存文件。

README 明确建议：多线程 ERP 导入和大成员表装载应优先走这条路径，而不是并发裸调 sa_db_ingest_columns。

索引类别加速的查询约束与限制
整数族 u8…u64 及 signed 对应点查 find、范围 range、计数 count_cmp、get、min/maxsigned 用有符号排序，负数排在 0 之前
f32 / f64同上拒绝 NaN 与 ±Inf（SA_DB_ERR_INVALID_FORMAT），因其排序不是稳定业务数据
u64_pair / u64_i64_pair精确 tuple 点查、固定首键 + 第二键范围分页、固定首键全列表unique=1 约束整个 tuple；第二键为 signed 时保持有符号顺序
blob_eq精确文本/blob 过滤；unique 时支持按值取整行约束的是真实字节而非哈希
blob_tokenASCII token 全匹配，大小写不敏感token 模型限定 ASCII 字母/数字/下划线；回快照字节二次确认
blob_prefixtoken 前缀（typeahead 形态），大小写不敏感只在 token 起始处匹配，前缀最长 64 字节
blob_contains字节级子串包含三元组候选索引，needle 至少 3 字节才走索引；空串与 1–2 字节保持扫描路径以保证精确语义

索引在 ingest / 行写 / compact / qmod 写入后都会重建；相关 blob store 追加值时也会重建绑定该 store 的 exact 索引。 range 类查询要求目标列已有持久化索引，这样才能用二分边界而不是全表扫描。

低基数字符串字典

sa_db_dict_intern(<table prefix>, &dict_name: ptr, dict_name_len: u64,
                  &value: ptr, value_len: u64, &out_id: ptr, &out_inserted: ptr, &out_info: ptr) -> u32
sa_db_dict_intern_many(<table prefix>, &dict_name: ptr, dict_name_len: u64, values: ptr, values_len: u64,
                       out_ids: ptr, out_ids_len: u64, out_inserted: ptr, out_inserted_len: u64, &out_info: ptr) -> u32
sa_db_dict_lookup(<table prefix>, &dict_name: ptr, dict_name_len: u64,
                  &value: ptr, value_len: u64, &out_found: ptr, &out_id: ptr) -> u32
sa_db_dict_value_len(<table prefix>, &dict_name: ptr, dict_name_len: u64, id: u64, &out_found: ptr, &out_len: ptr) -> u32
sa_db_dict_value_copy(<table prefix>, &dict_name: ptr, dict_name_len: u64, id: u64,
                      &out_buf: ptr, out_buf_len: u64, &out_found: ptr, &out_written: ptr) -> u32
  • 把非空字节串（如 active、paid、warehouse_a）映射到命名字典内稳定的 1-based u64 ID； ID 0 预留给上层表达 null/unknown。
  • 重复 intern 返回既有 ID 且不推进表 epoch；行里存的仍是普通 u64， 因此可以直接复用 u64 索引、范围读、投影与 row API。
  • 字典本身是版本化表 artifact，随 snapshot/restore/verify/recover/lock/unlock/remove 一致维护。
  • 它不是通用 varchar/blob 存储，定位是稳定标签集合的去重。

通用变长 blob 存储

sa_db_blob_put(<table prefix>, &store_name: ptr, store_name_len: u64,
               &value: ptr, value_len: u64, &out_id: ptr, &out_info: ptr) -> u32
sa_db_blob_value_len(<table prefix>, &store_name: ptr, store_name_len: u64, id: u64, &out_found: ptr, &out_len: ptr) -> u32
sa_db_blob_value_copy(<table prefix>, &store_name: ptr, store_name_len: u64, id: u64,
                      &out_buf: ptr, out_buf_len: u64, &out_found: ptr, &out_written: ptr) -> u32
  • 向命名 store 追加一个值并返回稳定的 1-based handle；0 预留给 null/missing 语义。
  • 空值合法；重复相同字节会得到不同 handle——这条路是给 varchar/blob 数据用的，不做低基数去重。
  • 行内只存 8 字节 blob_handle，真实字节在 store 里，因此行查询保持固定宽度。

                          &column_indices: ptr, column_indices_len: u64,
                          &out_bytes: ptr, out_bytes_len: u64,
                          &out_written_rows: ptr, &out_required_bytes: ptr) -> u32
sa_db_get_row_handle(handle: ptr, row_index: u64, &out_row: ptr, out_row_len: u64) -> u32

                             &out_row: ptr, out_row_len: u64) -> u32
  • sort_rows_* 校验每个候选行都在范围内，等值键保持输入顺序，输出稳定分页； float 变体遇到 NaN/Inf 返回 SA_DB_ERR_INVALID_FORMAT。
  • project_rows_handle 输出按输入行序逐行打包、行内按请求列序拼接； buffer 过小返回 SA_DB_ERR_CURSOR_OVERFLOW 并填充 required_bytes； 空输入合法，返回 written_rows=0 与 required_bytes=0，让空页也走同一路径。
  • get_row_handle 按快照行号复制完整定宽行；get_row_*_key_handle 要求存在匹配的唯一索引（u64/i64/u32/i32/u8/i8/u16/i16/(u64,u64)/(u64,i64)/唯一 blob_eq）， 直接按键取整行，省掉一次 find。

这些 helper 不引入新的物理格式：金额编码为 scaled i64，日期为 epoch days， 时间戳为 epoch ms/us，布尔规范化为 0/1，可空字段用 sidecar null bitmap。 README 给出的两个换算样例是 DB_DECIMAL_FROM_PARTS(1, 1, 0, 2) 把 -1.00 编码为 -100， 2024-02-29 编码为 epoch day 19782。schema 注解写法如 // i64 decimal(2) nullable、// i64 date、// u8 bool； scale 上限为 18。无注解的旧 schema 得到 SA_DB_LOGICAL_NONE、scale 0、nullable 0。
