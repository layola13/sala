Project Structure Conventions

This page gives the standard directory layout and naming conventions for a SAX UI project, based on the real structure of D:\projects\sla\codex_ui (38 .sax files / 39 components). Organizing files in this layout keeps the build commands, style concatenation, and navigation-bar style consistent.

The Entry app.sax and Screen Mounting

app.sax does only three things: it declares the boolean state for each screen, renders each screen's <section> mutually exclusively according to that state, and provides the development navigation bar. Screens are not aware of each other; all composition relationships (such as TopBar + HistorySidebarPanel + ChatWaterfallPanel + ComposerDock inside the workbench) are written inside their respective screen components.

NoteThe four settings sections — member permissions / usage / security / plugins — have no separate tab files; instead they reuse the four independent screens MembersPermissionsScreen, UsageBillingScreen, SecuritySettingsScreen, and PluginSettingsScreen, which are entered directly via the navigation bar.

The Development Navigation Bar

The navigation bar is <nav className="cxu-devnav">, fixed centered at the bottom of the viewport, containing buttons for all 16 top-level screens: Workbench, ChatGPT shell, CLI check, Legal consent, Login, Settings, Setup guide, Member permissions, Security, Usage billing, Plugins, Launch adapters, Project group chat, Free model, Official login, and Agent roster. Each button corresponds to a goto_xxx handler that sets the target state to true, the other 15 to false, and then calls render(). It replaces the state-machine gates and dialog switches of the original React application, and is the only means of switching between screens in a pure-UI project.
