SAX Syntax Rules

This page collects the hard syntax boundaries for writing .sax files under the sa_plugin_react compilation pipeline, based on the measured conclusions in codex_ui/SYNTAX_RULES.md. You should master these rules before writing or changing any .sax file, otherwise you will hit errors directly at the parse / lower stage.

Components and State

  • Components are written as <Component name="Xxx">…</Component>; one file can contain multiple Components (for example, top_bar.sax defines both TopBar and TaskTabStrip).
  • State is declared in a <state> block, one variable per line; the typical form is a boolean flag: flag = 0 as i1, or initially true, flag = 1 as i1.
  • Tags starting with a capital letter are resolved by name to other components; cross-file components enter the same namespace via --include. Lowercase tags are native HTML elements.

Text Position ({...} Between Tags) — Only Two Forms Allowed

FormAllowed?
{var} — a single state variable interpolationAllowed
{n + 1} — an arithmetic expressionAllowed
Ternary {cond ? 'a' : 'b'}Not allowed (reports InvalidTextExpression)
String literal {'text'}Not allowed
Comparisons {a > b}, {a == b}Not allowed

When text needs to switch with state, the project convention is to write the static branch text that matches the initial value of that state: if <state> has x = 1 as i1, use the true-branch text; if x = 0 as i1, use the false-branch text.

Attribute Position (name={...}) — Lenient

The attribute position is much more lenient than the text position, and it is also the dominant style in this project:

  • String literal: color="primary"
  • Ternary: color={flag ? 'success' : 'default'}
  • Template concatenation: className={"x" + (f ? " y" : "")}
  • Brace templates embedded in a quoted value: className="cxu-tab-body{tab ? '' : ' cxu-hidden'}" — legal and heavily used; conditional class-name switching relies entirely on it.
  • A whole attribute can also be a static-string ternary: aria-hidden="{open ? 'false' : 'true'}".
WarningAn empty or whitespace-only attribute value (value="", label=" ") reports InvalidAttribute; simply delete that attribute.

Handler Function Bodies (an SLA Subset) — Straight-Line Statements Only

fn pick_tab0() {
  tab0 = true; tab1 = false; tab2 = false;
  render();
}
  • Allowed: boolean assignment flag = true;, negated assignment flag = !flag; (the standard way to toggle a boolean), numeric assignment page = page + 1;; multiple assignments can be written on one line separated by semicolons.
  • render(); must be the last statement.
  • if/else (in any form), loops, and comparison-conditional statements are not allowed — they report SyntaxError.
  • Event binding is written onClick={handler}.

Other Hard Rules

  • HTML comments are forbidden <!-- --> (reports UnexpectedToken).
  • Every opening tag must be written on a single line; there must be no line breaks inside a tag.
  • Literal brace-wrapped strings/ternaries are forbidden in the text position; brace templates inside attribute values are the legal form.
  • Encoding is always UTF-8 without BOM; when editing, make targeted line edits only — do not reformat the whole file.
  • Component names and state variable names must not be changed arbitrarily — other files reference them by name.
NoteA single-include build (sa vite build app.sax --include one file) exits early because the entry point references undefined components, and the included file is not actually checked, so such a PASS is not trustworthy. For a reliable single-file verification method, see the react/vite Plugin Integration and Local Preview page.
