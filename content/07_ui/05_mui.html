The mui Component Library

This page introduces the SAX version of the Material component library provided by sa_plugin_mui: its source form, how to bring it in at compile time, and how to use these components in .sax files.

An SA-First Source Library

sa_plugin_mui is a Material UI component library for SA/SAX, implemented in an SA-first direction: the components themselves are written in SAX source, mui/material.sax, and the React/SAX compilation chain consumes it through the generic --include component-source composition mechanism. The plugin's Zig part is only responsible for the plugin description and shared-asset installation; it implements no component behavior, theme logic, or class-name generation. Upstream material-ui serves only as a reference for the React model (default props folded into ownerState, slots, utility classes, theme tokens); it is not a runtime dependency.

  • mui/material.sax — all core Material components (the v1 inventory is locked to the default exports of @mui/material, excluding hooks/helpers) plus Lab-style components (LoadingButton, Timeline, Masonry, TabContext/TabList/TabPanel, SimpleTreeView/TreeItem, the SpeedDial family, etc.).
  • mui/icons_material.sax — pure-SAX icon wrappers depending on the same SvgIcon surface; it currently covers dashboards/navigation and common actions, around 30 icons such as SearchIcon, NotificationsIcon, SettingsIcon, MenuIcon, CloseIcon, AddIcon, EditIcon, DeleteIcon, HomeIcon, LogoutIcon.
  • Common layout/data components include: Button, IconButton, Chip, Paper, Typography, Stack, Grid, AppBar, Tabs/Tab, Select/MenuItem, List/ListItemButton, the Table family, Switch, TextField, Alert, the Dialog family, Avatar, CssBaseline, InitColorSchemeScript, GlobalStyles, etc.

How to Bring It In

The MUI library files do not live in your project directory; instead they are attached at build time with two --include flags (paths pointing at the plugin repository):

MUI=D:/projects/sla/sa_plugin_mui

sa vite dev app.sax --react \
  --include $MUI/mui/material.sax \
  --include $MUI/mui/icons_material.sax \
  ...其余 include... \
  --title "Codex UI" --css app.css --out-dir .zig-cache/dev --port 5173

Include resolution order: first relative to the entry .sax file, then SA_REACT_INCLUDE_PATH, the shared directory inferred from SA_PLUGINS_PATH, and the share directory of an installed plugin ($SA_PLUGINS_HOME/installed/<plugin>/current/share). So you can also pass just --include mui/material.sax and let it resolve from the installed mui plugin's shared directory.

Using It in .sax

MUI components are just capitalized tags, mixed with your own components in the same namespace. The typical usage attaches global CSS classes and static attributes to them:

<Chip color="warning">⚡ Fast</Chip>

<Select value="full-access">
  <MenuItem selected>完全访问</MenuItem>
  <MenuItem>自动批准</MenuItem>
</Select>

<Paper className="cxu-dock-menu{menu_open ? '' : ' cxu-hidden'}">
  <List dense>
    <ListItemButton onClick={close_menu}><span>📎 上传文件</span></ListItemButton>
  </List>
</Paper>
  • A root node's className is merged after the generated utility classes (applies to common root-slot components such as Button, Paper, Card, Chip, Alert, Dialog).
  • The appearance baseline is hand-defined by the project's theme.css (such as .MuiButton-contained, .MuiChip-colorSuccess); see the The Styling System page.
  • Wrapper/layout components can use <Slot contextProps="..." /> to project default values onto their direct children; a Provider that needs to penetrate transparent wrapper layers declares contextScope="descendants" explicitly.
  • Current className support is incremental: static object props (such as classes={{ root: "..." }}) and slotProps are projected into same-named state; dynamic object values, custom slot component replacement, styleOverrides, portals, and focus traps are still future work.

Installation and Building

# 在插件目录构建出 DLL 后安装（privileged 插件需 --dev 跳过 TTY 确认）
cd D:/projects/sla/sa_plugin_mui && zig build -Doptimize=Debug
sa plugin install --dev D:/projects/sla/sa_plugin_mui
sa plugin list          # 查看已安装插件
NoteRunning privileged plugins (react, the mui dependency chain, etc.) requires the environment variable SA_PLUGIN_DEV=1, otherwise you get “privileged plugin ... is blocked in formal runtime mode”. For toolchain details, see react/vite Plugin Integration and Local Preview.
