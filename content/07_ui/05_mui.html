组件库 mui 概览

这一页介绍 sa_plugin_mui 提供的 SAX 版 Material 组件库：它的源码形态、如何在编译时引入， 以及在 .sax 文件里使用这些组件的写法。

SA-first 的源码库

sa_plugin_mui 是 SA/SAX 的 Material UI 组件库，实现方向是 SA-first： 组件本体写在 SAX 源码 mui/material.sax 里，React/SAX 编译链通过通用的 --include 组件源码组合机制消费它。插件的 Zig 部分只负责插件描述与共享资产安装， 不实现任何组件行为、主题逻辑或类名生成。上游 material-ui 仅作为 React 模型的参考 （默认 props 归入 ownerState、slots、工具类、主题令牌），不是运行时依赖。

  • mui/material.sax —— 全部核心 Material 组件（v1 清单锁定为 @mui/material 默认导出，不含 hooks/helper）以及 Lab 风格组件（LoadingButton、Timeline、Masonry、TabContext/TabList/TabPanel、SimpleTreeView/TreeItem、SpeedDial 系列等）。
  • mui/icons_material.sax —— 纯 SAX 的图标封装，依赖同一 SvgIcon 表面；当前覆盖仪表盘/导航与常见动作，如 SearchIcon、NotificationsIcon、SettingsIcon、MenuIcon、CloseIcon、AddIcon、EditIcon、DeleteIcon、HomeIcon、LogoutIcon 等 30 个左右。
  • 常用布局/数据组件包括：Button、IconButton、Chip、Paper、Typography、Stack、Grid、AppBar、Tabs/Tab、Select/MenuItem、List/ListItemButton、Table 系列、Switch、TextField、Alert、Dialog 系列、Avatar、CssBaseline、InitColorSchemeScript、GlobalStyles 等。

引入方式

MUI 库文件不参与你的工程目录，而是在编译命令里用两个 --include 挂进来（路径指向插件仓库）：

MUI=D:/projects/sla/sa_plugin_mui

sa vite dev app.sax --react \
  --include $MUI/mui/material.sax \
  --include $MUI/mui/icons_material.sax \
  ...其余 include... \
  --title "Codex UI" --css app.css --out-dir .zig-cache/dev --port 5173

include 解析顺序：先相对入口 .sax 文件，其次 SA_REACT_INCLUDE_PATH、 由 SA_PLUGINS_PATH 推断的共享目录、已安装插件的 share 目录（$SA_PLUGINS_HOME/installed/<plugin>/current/share）。 因此也可以只传 --include mui/material.sax 让它从已安装的 mui 插件共享目录解析。

在 .sax 中使用

MUI 组件就是大写标签，与自己的组件混用在同一命名空间。典型用法是给它们挂全局 CSS 类和静态属性：

<Chip color="warning">⚡ Fast</Chip>

<Select value="full-access">
  <MenuItem selected>完全访问</MenuItem>
  <MenuItem>自动批准</MenuItem>
</Select>

<Paper className="cxu-dock-menu{menu_open ? '' : ' cxu-hidden'}">
  <List dense>
    <ListItemButton onClick={close_menu}><span>📎 上传文件</span></ListItemButton>
  </List>
</Paper>
  • 根节点 className 会合并到生成的工具类之后（对 Button、Paper、Card、Chip、Alert、Dialog 等常见根槽组件生效）。
  • 外观基线由工程的 theme.css 手工定义（如 .MuiButton-contained、.MuiChip-colorSuccess），见样式体系一页。
  • 包装/布局类组件可用 <Slot contextProps="..." /> 把默认值投影给直接子组件；需要穿透透明包装层的 Provider 用 contextScope="descendants" 显式声明。
  • 当前 className 支持是增量的：静态对象 props（如 classes={{ root: "..." }}）与 slotProps 会被投影成同名状态；动态对象值、自定义 slot 组件替换、styleOverrides、portal、焦点陷阱仍是后续工作。

安装与构建

# 在插件目录构建出 DLL 后安装（privileged 插件需 --dev 跳过 TTY 确认）
cd D:/projects/sla/sa_plugin_mui && zig build -Doptimize=Debug
sa plugin install --dev D:/projects/sla/sa_plugin_mui
sa plugin list          # 查看已安装插件
注意运行 privileged 插件（react、mui 依赖链等）需设置环境变量 SA_PLUGIN_DEV=1， 否则报 "privileged plugin ... is blocked in formal runtime mode"。工具链细节见react/vite 插件集成与本地预览。
