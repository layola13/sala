Creating a SAX UI Project from Scratch

This page ties the previous pages together into a minimal runnable checklist: starting from an empty directory, write the entry point and one screen, add a theme CSS file, and finally see it in the browser with the vite plugin.

Step 1: Prepare the Environment

# 编译器已加入 PATH（D:/projects/sla/sci/zig-out/bin/sa.exe）
# 首次使用需安装插件（各插件目录需先 zig build 出 zig-out/bin/*.dll）
sa plugin install --dev D:/projects/sla/sa_plugin_sax
sa plugin install --dev D:/projects/sla/sa_plugin_http_server
sa plugin install --dev D:/projects/sla/sa_plugin_react
sa plugin install --dev D:/projects/sla/sa_plugin_vite
sa plugin install --dev D:/projects/sla/sa_plugin_mui
sa plugin list

# 运行 privileged 插件必需（已持久化到用户环境变量，新终端可省略）
export SA_PLUGIN_DEV=1

Step 2: Create the Directories and Styles

Create a new project directory (called my_ui in this example) and place things in three locations by convention: app.sax in the root, screens in screens/, and style sources in the root and styles/. First create a minimal theme.css declaring tokens and shared primitives:

:root {
  color-scheme: dark;
  --cxu-bg: #070a0e;
  --cxu-paper: #10161d;
  --cxu-text: #f9fafb;
  --cxu-muted: #a8b3bf;
  --cxu-line: rgba(255, 255, 255, 0.09);
  --cxu-primary: #61f3f3;
  --cxu-secondary: #ffab00;
}
* { box-sizing: border-box; }
html, body { margin: 0; background: var(--cxu-bg); color: var(--cxu-text); font-size: 14px; }
#app { min-height: 100vh; }
.cxu-hidden { display: none !important; }
.cxu-row { display: flex; align-items: center; gap: 8px; }
.cxu-grow { flex: 1; min-width: 0; }
.cxu-caption { color: var(--cxu-muted); font-size: 11px; }

As the project grows, split it into theme.css + styles/*.css following the 12-file division of labor on the “The Styling System” page, and keep generating app.css in the concatenation order.

Step 3: Write the First Screen, screens/hello_screen.sax

Follow the syntax rules: tags on a single line, state as i1 booleans, handlers with only straight-line assignments plus render(), and no comments:

<Component name="HelloScreen">
  <state>
    greeted = 0 as i1
  </state>

  <div className="cxu-row">
    <button className="MuiButton-root MuiButton-contained" onClick={say_hello}>打招呼</button>
    <span className="hello-msg{greeted ? '' : ' cxu-hidden'}">你好，SAX！</span>
  </div>

  fn say_hello() {
    greeted = true;
    render();
  }
</Component>
NoteThe text position cannot contain a ternary such as {greeted ? '你好' : ''} — here “static branch text + cxu-hidden” is used instead, which is this project's standard practice. If you want to use MUI components (such as the Button corresponding to the MuiButton-* class names above), you need to include the mui library files at compile time; plain HTML tags do not need that.

Step 4: Write the Entry Point, app.sax

<Component name="MyUiApp">
  <state>
    nav_hello = 1 as i1
  </state>

  <div className="cxu-app">
    <section className="cxu-screen{nav_hello ? '' : ' cxu-hidden'}">
      <HelloScreen />
    </section>

    <nav className="cxu-devnav">
      <button onClick={goto_hello}>首页</button>
    </nav>
  </div>

  fn goto_hello() {
    nav_hello = true;
    render();
  }
</Component>

From then on, each time you add a screen: create a new .sax in screens/, add a nav_xxx state and a <section className="cxu-screen{...}"> in the entry point, add a button and a goto_xxx handler to the navigation bar, and add the file to the include list of the build command.

Step 5: Start the Hot-Reload Preview

cd my_ui
MUI=D:/projects/sla/sa_plugin_mui

sa vite dev app.sax --react \
  --include $MUI/mui/material.sax \
  --include $MUI/mui/icons_material.sax \
  --include screens/hello_screen.sax \
  --title "My UI" --css app.css --out-dir .zig-cache/dev --port 5173

Open http://localhost:5173 in the browser. Changing any .sax or CSS automatically rebuilds and refreshes; compilation errors are shown on the page as an overlay. When you need deployable output, use sa vite build ... --out-dir dist instead. For single-file syntax verification and post-change consistency checks, see react/vite Plugin Integration and Local Preview.

Self-Check Checklist

  • All opening tags are on a single line, with no HTML comments and no empty attribute values.
  • Text interpolation has only {var} and arithmetic; ternaries appear only in the attribute position.
  • Handlers contain no if/else and end with render();.
  • Every capitalized component tag has a corresponding definition or comes from the mui library; component names are not duplicated.
  • Newly introduced cxu-* classes are defined in the CSS source files; files are encoded as UTF-8 without BOM.
