错误码与诊断

这一页解释 SA 的诊断体系：公开 trap 名称、JSON 诊断 TrapReport 的字段， 以及运行时 ABI 退出码。读完可以看懂一次失败编译的 JSON 输出并定位到具体阶段。

基本规则

  • Trap 名是稳定的公开标识符；trap 枚举的序号不是公开数字编码，不要按枚举顺序推断含义。
  • 输出是 JSON-first 的结构化诊断，而不是裸字符串。
  • 语义/语法失败由 src/common/trap.zig 定义的 trap 名描述。

TrapReport 字段

字段含义
trap公开 trap 名称
line / source_line展开后行号 / 源码行号（均从 1 起）
register / registers主寄存器名 / 相关寄存器列表
expected_mask / actual_mask期望与实际的能力掩码（及对应人类可读名）
upstream_loc上游源位置 {file,line,col} 或 null（来自 #loc）
function / is_ffi_wrapper当前函数声明全文 / 是否为气闸包装函数
message / hint主消息 / 可选修复建议

  "registers": [],

常见 Trap 分类（已发射，非 roadmap-only）

类别Trap触发场景
语法 / 结构ForbiddenSyntax出现 {}、if、while 等禁用语法；宏/导入类错误也多映射到此
DuplicateDef / DuplicateLabel重复 #def；同一函数内重复 label
FallthroughForbidden基本块没有以终结指令结束
所有权 / 借用UseAfterMove访问已被消费的寄存器（"moved value is no longer usable"）
BorrowConflict / DoubleMutableBorrow / ReadWriteConflict对锁定中的源做冲突访问或二次独占借用
MemoryLeak / EarlyReturnLeak函数退出或 ? 早返回路径上仍有活跃寄存器
StackEscape / InteriorPtrEscape栈分配逃逸原生边界；内部指针跨越 FFI 边界
契约CapabilityMismatch调用点前缀不满足被调用方契约
FallibleContractMismatch对非可失败值用 ?，或可失败返回路径不匹配
ConstMutation / FfiOwnershipViolation / IllegalUnsafeContext改写 @const；对 FFI 视图做 ^/!；气闸指令出现在 @ffi_wrapper 外
原子InvalidAtomicOrdering / AtomicOrderingMismatchflattener 阶段的序组合非法；Referee 阶段同地址 RMW 序不允许
其他ImportResolutionFailed、MacroRecursionLimit（深度 > 256）、UnsupportedType、ArenaOOM 等见官方 errorcode 文档全表
注意GasExceeded、 SnapshotVersionMismatch、VTableSignatureMismatch 目前是保留命名空间， 尚未接入当前管线（roadmap-only），遇到问题不要指望它们出现。

阶段归属速判

  • 报错来自 flattener 映射（多为 ForbiddenSyntax 一族）→ 文本解析/宏展开阶段。
  • 带掩码字段的结构化 JSON → Referee（src/referee/verifier.zig 是主要发射者）。
  • error: <name> 形式 → 解释器 / driver 内部错误，目前不是 SA Trap JSON。
