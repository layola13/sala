extern Host Bindings (Staged Simulation)

An unknown extern that is called generates a trap stub by default (sa_trap("extern …")). A known extern, by contrast, generates a staged host binding: the same simulated semantics as on the interpreter/JS side (fake fds, echo signals, byte-level npm decisions on guest memory), not real libc calls — the output is deterministic and host-independent, and the demo assertions are exactly about these fake values.

2. State and Implementation Constraints

  • The http state is a single shared bounded table (sa_http_objs[16], where the handle is the unique alloc offset, naturally free of cross-talk and with no malloc), emitted only when an sa_http_* binding is rendered; find/slot/drop enter the helper catalog and go through reference gating; every binding body references at least one helper, so the table can never be in an “emitted but used by nobody” state.
  • All out-params are written back via sa_store_u64 (with its own bounds check); an unknown handle always returns 1 (resp_status returns 0 as in JS); canned strings use in-function static const byte arrays.
  • The unified signature is (sa_u64 a0, …), with unused parameters filled precisely with a bitmask of (void) casts (misalignments such as mmap using a1 but not a0 are covered); every binding contains SA_GAS_CHECK(1); helpers referenced by a binding (sa_alloc, sa_checked_addr, etc.) are pre-rendered and scanned into the used set before the preamble, so trimming is unaffected.
  • Note: #npm_bind is still JS-only; the C-side npm family is a native staged implementation — do not confuse it with node behavior (totalmem/parallelism return fixed fake values, as long as they satisfy assertions of >0 / >=1).
