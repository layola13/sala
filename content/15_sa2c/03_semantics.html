语义对齐：别名、f32 与间接调用

以下规则全部与解释器及 JS 后端（combinedKind/aliasCallee）镜像， JS 即 oracle；unknown 形状保持历史强制 signed lowering，只有静态可知的形状会变行为。

1. 兼容别名 div/rem/gt/lt/shr 的 kind 选择

按操作数 kind 决策：float 优先，其次 signed，否则 unsigned：

别名floatunsigned其他（含 unknown）
divsa_fdivsa_udivsa_sdiv
remsa_srem（同 JS）sa_uremsa_srem
gt / ltsa_fcmp_gt / sa_fcmp_ltsa_ugt / sa_ultsa_sgt / sa_slt
shrsa_lshrsa_lshrsigned→sa_ashr，否则 sa_lshr

结果 width 跟随所选 helper（udiv/urem/lshr→无符号 64， fcmp→1），链式别名能正确传播解析后的 domain。 文本立即数同样参与 kind 判定（i64→signed，u64→unsigned，可解析 float→float）。

2. f32 domain

  • fadd/fsub/fmul/fdiv 与 fcmp_*：两侧静态 f32→32 位 helper； 一侧 f32、另一侧非确证 f64→32 位 helper + 未确证边截断（verifier 保证 domain 一致， 截断即 identity；典型来源是间接调用返回值）；其余走 f64（f32 边提升）。
  • f32 结果的 width 记录与发射严格同步，否则下游 fcmp 选错 domain。
  • 32 位显式 lshr 窄化：sa_lshr(sa_srcmask(v,W,0), sa_band(b,31))， i32 0xFFFFFFFF 按 u32 移位（demo 347 类）。ashr 因符号扩展与算术移位可交换，无需处理。
  • ftable 返回 domain 全体一致时，间接调用结果 width 被精确播种 （如单回调 f32 表），fneg32/both32 得以选中；非一致保持 unknown。

3. 间接调用分发（含修复史）

统一签名使函数指针表精确（下标与 fn_idx/vtable 常量编码一致）。 旧实现先算 uint64_t idx = f - 1000000 再判 idx >= 0， 无符号比较恒真，空表时间接调用全部进 trap；现实现：

if (f < 1000000ULL) { sa_trap("bad indirect callee"); }
{ sa_u64 idx = f - 1000000ULL;
  if (idx >= (sa_u64)(sizeof(sa_ftable) / sizeof(sa_ftable[0])))
    { sa_trap("bad indirect callee"); }
  if (sa_ftable[idx] == 0) { sa_trap("null indirect callee"); }
  return sa_ftable[idx](a0, a1); }

空表退化为 sa_ftable[1] = {0}（零长数组是 GNU 扩展，且会使边界检查恒假）。 pthread_spawn 在宿主侧经 dispatcher 同步跑 entry，因此调它的程序同样强制带分发表。
