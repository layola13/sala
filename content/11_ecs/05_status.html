issue035：rescan summary repeated field load 的 UseAfterMove

  • 日期 / 状态：2026-07-16，fixed and verified。
  • 现象：generated-SA 后端在编译聚焦的 ready-batch rescan 测试时报 error[UseAfterMove]（函数 @sla__ecs_executor_ready_batch_rescan_summary_deep3，寄存器 tmp_3969）； 默认后端与 sa sla check 都通过——故障在 SLA SA 文本代码生成，不在 ECS 调度行为本身。
  • 下游复现：tests/test_ecs_lib_executor_multi_threaded_deep_isolated.sla 过滤用例 mt_deep_ready_batch_rescan_records_three_skipped_slots。
  • 根因：SA 文本的字段下探把生成的寄存器名当作所有权启发式； 被赋值的聚合局部变量可能解析成 tmp_* 寄存器，但它仍是局部绑定， 不应在每次字段投影后被释放。与 issue034 共享同一字段基址生命周期根因。
  • 修复：src/lowering_rules.zig 新增 fieldBaseResultNeedsRelease() 共享规则——当生成的 tmp_* 寄存器 是标识符的解析绑定时保持存活，真正的临时字段基址照旧释放； src/codegen.zig 在元组字段、手动 drop 结构体字段、普通结构体字段三处使用该规则。

issue038：scope completion 栈槽聚合调用的 UseAfterMove

  • 日期 / 状态：2026-07-16，fixed。
  • 现象：默认 / direct-SAB 后端在聚焦的 scope-completion 测试上报 error[UseAfterMove]（寄存器 sla__ecs_scope_completion_complete_pending_at_i32__param_0_queue）； sa sla check 成功。同一缺陷也在更早的 scope-completion 测试中复现， 说明与新引入的 panic/catch 用例无关。
  • 下游复现：lib/task_scope_completion.sla 过滤用例 scope completion pending first task blocks result drain。
  • 最小复现形状：把含两个 Vec 字段的 QueueState 传给只读 helper，之后继续读写原聚合；direct SAB 发出 @sla__queue_len(^sla__complete_pending__param_0_queue)， 移动前缀调用提前消费了参数。
  • 根因：direct-SAB 调用下探可以通过浅拷贝外层 ABI 槽来保住后续还要使用的普通聚合， 但其资格判定拒绝了任何含标准 owner（如 Vec）的聚合——即使 owner 只是外层聚合内部的一个指针 ABI 槽——于是回退成移动原聚合。
  • 修复规则：顶层标准 owner 保持不可复制； 只有「普通外层聚合为了临时按值调用实参而浅拷贝嵌套 owner 槽」这一种情况被允许， 且浅拷贝只直接存储嵌套 owner 槽，不递归复制其内部。

issue044：repeated let 函数指针别名的 CodegenError

  • 日期 / 状态：2026-07-17，fixed。
  • 现象：默认与 generated-SA 后端在执行前失败： SAB Error: failed to lower SLA through SA-compatible SAB path: error.CodegenError； generated-SA 定位到的第一个失败单态化函数是 ecs_parallel_task_pool_scope_run_tasks_shared_serial_i32_i32。
  • 下游复现：tests/test_ecs_parallel_runner_scope_executor_isolated.sla 过滤用例 sharing scope executor ticks scope；既有回归 tests/test_ecs_mut_parallel.sla 的 task pool scoped task set external only stays off pool 同样失败。
  • 触发形状：从 Vec 取函数指针，在两个循环里各自 let run = runs[i] 再调用 run(...)。
  • 根因一：重复 let 绑定经生成绑定别名下探， 而函数指针调用路径直接用源码原名查 local_binding_types； 推导出的函数指针类型登记在活动别名之下，查询返回 null， 于是发出裸 CodegenError。应使用别名感知的 localBindingTypeForName。
  • 根因二：修完查询后 generated-SA 又暴露 error[MemoryLeak]: live registers remain at function exit—— 生成寄存器持有了传给 Vec.push 的函数指针 vtable 地址； 特化的 vec(...) / Vec.push(...) 路径用了只看 AST 标识符节点的 callArgNeedsRelease，须改用 callArgResultTempNeedsRelease。
  • 修复提交：adf98e2（别名感知查找）、e2406dc（释放生成临时）。
