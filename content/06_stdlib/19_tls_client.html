tls_client.sai: TLS Client

A TLS client in pure Zig (backend std.crypto.tls.Client, source src/runtime/sa_tls_client.zig, in the sci repository's cross-platform branch). A TLS connection is an opaque u64 handle (0 = invalid), and connect() completes TCP dialing + the TLS handshake in one go. Verification is always on: the hostname is sent as SNI and checked against the peer certificate, and the certificate chain is validated with a process-level CA bundle (the operating system trust store, to which add_ca_file can append) — there is no switch to turn verification off.

Error Codes

CodeMeaning
0OK
-1unsupported (backend unavailable)
-5I/O error
-12Out of memory
-22Invalid argument (including an invalid handle)
-100Certificate verification failure (hostname mismatch / untrusted chain); in this case out_handle is 0
WarningTrust-anchor rule (std.crypto.Bundle behaviour): a bundle keeps only the first certificate it sees for a given subject. Pinning a second, different certificate with the same subject will be silently ignored (it returns OK but nothing changes). When you need to re-pin, regenerate a certificate with a distinguishing field in its subject.
