process: Child Processes

This page introduces the core functions in sa_std/process.sai: starting and waiting for a child process, capturing its output, sending signals, and reading information about the current process. After reading it, you will be able to invoke an external command from a program and retrieve its exit code and output.

Handle Model

A process handle is an opaque u64 resource that must be closed with sa_std_process_close after use. argv is a borrowed pointer to an array of SaProcessArgv records.

Advanced Variants

The contract also provides a set of extended entry points, increasing by optional capability: ..._command_ext (working directory, arg0, process group, setsid), ..._command_ext_pidfd (Linux pidfd), ..._command_ext_uid_gid (switching uid/gid), ..._command_ext_groups (supplementary groups), ..._command_ext_chroot (chroot), each in the three forms run / spawn / spawn_stream; the accompanying sa_std_pidfd_kill/_send_signal/_wait/_try_wait are used for pidfd operations. Options are enabled through paired has_xxx: u32 flags.

WarningThe variants with uid/gid, chroot and pidfd are platform-dependent (mainly POSIX) capabilities; cross-platform programs should not assume they are available.

Call Form at the SA Layer

%status = call @sa_std_process_exec_capture(&%argv, %argv_len, &%code, &%out_h, &%err_h)
%close  = call @sa_std_process_close(%handle)
