env: Environment Variables and Directories

This page lists the extern functions exported by sa_std/env.sai: reading and writing environment variables, obtaining the working directory / home / temporary directory, reading arguments and the environment in bulk as JSON, and the XDG directory family. After reading it, you will be able to handle configuration sources and path lists in a program.

Environment Variables

SignatureDescription
sa_env_get(key: ptr, key_len: u64) -> u64Get a variable's value, returning an owned buffer handle (an empty handle when not set)
sa_env_has(key: ptr, key_len: u64) -> i32Whether the variable exists
sa_env_set_var(key: ptr, key_len: u64, value: ptr, value_len: u64) -> i32Set a variable
sa_env_remove_var(key: ptr, key_len: u64) -> i32Remove a variable
sa_env_args_json() -> u64Command-line arguments, as a JSON array buffer
sa_env_vars_json() -> u64All environment variables, as a JSON object buffer

The Buffer Trio

@extern sa_env_buffer_data(buffer: u64) -> &ptr
@extern sa_env_buffer_len(buffer: u64) -> u64
@extern sa_env_buffer_free(^buffer: u64) -> i32

All env functions returning u64 follow this convention: first read the contents with _data/_len, then release with _free.

Call Form at the SA Layer

The externs in the contract correspond directly to runtime symbols; for example, checking whether a variable exists and getting its value looks like:

%has = call @sa_env_has(&%key, %key_len)
%buf = call @sa_env_get(&%key, %key_len)
%ptr = call @sa_env_buffer_data(%buf)
%len = call @sa_env_buffer_len(%buf)
NoteSla code must first @import "sa_std/env.sai" to use these functions; the handle returned by sa_env_get must be released.
