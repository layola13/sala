.NET net 表面 × sa_std 缺口普查

本页是跨语言 std 普查批的一份（同批：Rust 全 std、Go net、Python net、Java net、Android net、iOS net）。 .NET 的网络标准库分两层：现代核心（Sockets / HttpClient / SslStream / QUIC / WebSockets）与 一整层 WebRequest 时代的旧模型（WebClient / HttpWebRequest / ServicePoint / 缓存策略）， 后者连 .NET 自己都在持续标 Obsolete。本页把 System.Net.* 全部 19 个程序集的公共面 与 sa_std 网络面逐类型比对、四分类，并给出优先补齐短名单。

方法与清单规模

双边机械抽取（脚本与产物在 tools/dotnet_net_census/，可复跑）： .NET 侧解析 ref 源码的类型与成员声明及 [Obsolete] 标记；SA 侧解析 @extern / #def / [MACRO] 与 C 头声明。 .NET 侧共抽得 337 条类型记录（归并同名后 334 个类型）/ 4,194 个成员 （method 1,355、property 1,214、enum_member 1,134、ctor 374、field 100、event 17）。 分类粒度为类型级，逐类型结果在 gap_classification.tsv； 头部类型的成员级差异写在注记里。四分类口径与同批一致。

总结果：已有等价 32（9.6%）/ 可直接对应 140（41.9%）/ 需建模 62（18.6%）/ 模型不合 100（29.9%）。 按成员加权：671 / 1,927 / 915 / 681。模型不合的构成并不神秘：异常类型 17、委托 24、事件参数 14、 类型级已被 .NET 自己标 Obsolete 的 12，其余 33 为平台专属件（Windows 控制码、PAC 脚本、ExtendedProtection 等）。 剔除类型级 Obsolete 后看现代表面（322 个类型）：32 / 139 / 62 / 89。

分类口径

  • 已有等价：功能已被 sa_std 现有面覆盖（形态可不同：句柄 vs 对象、状态码 vs 异常）。
  • 可直接对应：sa_std 没有，但可直译补齐——纯函数、命名常量、参数袋、协议直译型客户端。 「只是没做」是这一类的全部含义。
  • 需建模：概念成立、底座原语多已备，但需要一层状态/对象模型（句柄表、配置对象、回调注册）。
  • 模型不合：依赖 SA 模型外的东西，或 .NET 自己已弃置的旧模型。家族规则： 异常类型（SA 以状态码 + SA_NET_ERROR_CODE_* + 错误码名建模，无异常对象）、 委托与 EventArgs（SA 以句柄 + poll/回调注册建模，无事件订阅）、平台专属件。

套接字：核心已备，长尾在平台件

Socket（191 个成员）的核心与 sa 的 net 面逐项对得上： connect/listen/accept、read/write/peek/vectored、选项族（nodelay、keepalive、TTL、收发缓冲、 linger、quickack、defer-accept 的 set/get 双向）、UDP send_to/recv_from 与组播加入/离开、 Unix 域（地址对象族 144 个符号含 abstract/unnamed 形态）——TcpClient / TcpListener / UdpClient / NetworkStream 同为已有等价。差异集中在 .NET 的三套异步形态 （APM / SocketAsyncEventArgs / Task 扩展，sa 以 netx 反应器与 poll 建模） 与 Windows 专属件（IOControlCode 34 值 WSAIoctl 码、TransmitFile、SendPackets）。

警告 地址族命名存在双定义陷阱（AJ2 普查已登记）：.sal 里 SA_NET_AF_IPV4=4 / IPV6=6 是 std 内部编号，而 sa_net_addr_family 返回 OS 值（AF_INET=2 / AF_INET6=10）。 AddressFamily / ProtocolFamily 因此只计「可直接对应」并注明须先解陷阱，不计已有等价。

HTTP 客户端：传输齐备，handler 层是最大建模块

sa_http_client_* 57 个符号覆盖建连、请求构造、头、体、同步/异步发送 （async + poll + take_response）、响应状态/头/体（含流式 body_reader）、SSE 与 WebSocket 升级连接。 但 .NET 的 HttpClient 真正的体量在 handler 层：SocketsHttpHandler（连接池、 池生命周期、ConnectCallback、明文流过滤）与 HttpClientHandler 的配置面里， cookie、proxy、重定向、自动解压四项在 sa 网络全表面关键词命中为 0。 System.Net.Http 的需建模 15 个类型几乎全属这一组——这是本普查第一优先的建模对象。 请求/响应对象（HttpRequestMessage / HttpResponseMessage）原语齐全、对象层需拼装； 内容族则多为已有等价（内存体由 req_set_body 覆盖、multipart 有 multipart.sai）， 例外是请求体流式写（StreamContent）在 sa http client 符号中未见。

HTTP 服务端与 SSE

sa 的 http_server 面（46 extern，含 v2 的 accept / resp_send / stream_write 与 sa_http_server_websocket_upgrade）是 accept 循环形态；.NET 的 HttpListener 是前缀路由 + 上下文队列 + 认证的对象模型——传输能力已备、对象层需建模，故 HttpListener 及其 Context/Request/Response 一组 8 个类型计需建模。 SSE 方向相反：sa 有 sa_http_client_sse_* 的 turn 型客户端（为 LLM 流式而建）， .NET 的 System.Net.ServerSentEvents 是通用增量解析器 SseParser—— sa 没有独立解析器面；解析器是纯状态机，计可直接对应。

TLS 与证书：传输已备，证书面为零

tls_client / tls_server / dtls 的传输面齐全（连接、读写、 ctx、accept、add_ca_file），另有 .NET 完全没有的 shaped 面（见下）。 但 SslStream 的对象层——把 TLS 包装到任意流上、协商选项、证书校验/选择回调、 SslCertificateTrust 信任库、密码套件策略——在 sa 侧无对应物： 全表面 cert|x509 关键词命中为 0（仅有 CA 文件一项配置）。 TlsCipherSuite 一个枚举就有 337 个值（本次抽取最大的单个枚举）， sa tls 没有任何套件命名面；ALPN 同理只有 shaped 协商结果 JSON、无命名常量。 这一组计：传输相关已有等价在 SslStream 行以建模注记呈现，选项/回调 8 个类型需建模， 命名面 11 个类型可直接对应。

QUIC 专节

.NET 的 QUIC 面（System.Net.Quic，13 个类型）与 sa 的对应是全普查最齐整的一组， 因为 sa_std 把 QUIC 传输与 HTTP/3 会话两层都做成了公开面：

.NETsa_std 对应分类
QuicListenersa_std_quic_server_listen / _accept / _poll已有等价
QuicConnectionsa_std_quic_client_connect / _server_accept / _conn_poll / _conn_close / _stream_open已有等价
QuicStreamsa_std_quic_stream_open / _read / _write已有等价（Stream 对象语义以句柄读写替代）
QuicConnectionOptions 等参数袋connect/accept 的参数结构可直接对应
QuicListenerOptions含 ConnectionOptionsCallback 协商委托需建模
QuicError（12 值）SA_QUIC_ERR_* 仅 3 值可直接对应（细粒度命名）

形态差异两点：.NET 的 QUIC 依赖 MsQuic 原生库，sa quic 是 std 内置； .NET 的 HTTP/3 只经 HttpClient 内部消费 QUIC、不公开会话 API， sa 反而把 sa_std_http3_session_create / _submit_request / _server_next_request 等 HTTP/3 会话层做成公开面——这一块是 sa 的多出面，不是缺口。

WebSocket、DNS、网络信息、邮件

WebSocket：客户端（ws_client：connect/send/recv/ping/close、 wss 继承 TLS 策略、add_ca_file）与服务端升级（http_server 的 upgrade 入口）均为已有等价； 缺的是选项层（ClientWebSocketOptions 含代理与证书回调，需建模）与命名常量 （opcode 与 WebSocketCloseStatus 无命名组——AJ2 已登记过 ws opcode 同类缺口）。 DNS：sa 只有反向查询 sa_std_net_addr_reverse_lookup 与错误码， 正向解析隐含在 connect 的主机名字符串里，没有 Dns 式的独立查询面与结果集 （IPHostEntry）——与 Android 线的短名单第一项是同一个跨语言一致缺口。 网络信息：System.Net.NetworkInformation 整域 44 个类型里 36 个可直接对应—— 网卡枚举、接口属性、统计快照、ICMP Ping 在 sa 侧全部为 0，但都是系统查询直译，无模型障碍。 邮件：sa 侧 SMTP/MIME 均为 0。SmtpClient 是协议直译型（计可直接对应， STARTTLS 复用 tls_client），MailMessage 及其附件/视图聚合 9 个类型需先建数据模型； FTP 同理（FtpWebRequest 协议直译可对应，sa 只有 SSH 的 SFTP）。

旧模型登记（不进补齐名单）

模型不合 100 个里的大头是 .NET 自己正在弃置的东西，如实登记、不移植： WebRequest / HttpWebRequest / WebResponse 可插拔协议模型、WebClient （官方 SYSLIB0014 不推荐；ref 中成员级 Obsolete 7 处）、ServicePointManager、 System.Net.Cache 的缓存策略 5 个类型、ExtendedProtection 6 个类型， 以及 WebClient 的事件/委托家族 18 个。计量上：类型级标 Obsolete 的 12 个、 成员级标 Obsolete 的 84 个（其中 Requests 程序集 24 个）。

sa 侧独有面（.NET 无对应）

  • SSH：客户端 + 服务端 + SFTP（ssh.sai 26 个 extern）——.NET 核心库至今无 SSH。
  • TLS 指纹面：sa_std_tls_shaped_* 的 JA3/JA4 ClientHello 塑形与协商结果导出。
  • DTLS 服务端、netx io_uring 反应器、WebSocket over Unix socket、HTTP/3 会话公开 API（见 QUIC 节）。

优先补齐短名单

  1. HTTP 客户端 handler 组建模（SocketsHttpHandler / HttpClientHandler / HttpClient 门面）： cookie、proxy、重定向、自动解压四项从 0 到有 + 连接池语义。本普查需建模的最大块，也是 CXU 与代理场景的高频面。
  2. DNS 正向解析独立面（Dns / IPHostEntry / DnsEndPoint）：地址与记录查询 + 结果集句柄； 与 Android 线短名单第一项跨语言互证。
  3. TLS 配置与证书面（SslClientAuthenticationOptions / SslServerAuthenticationOptions / SslCertificateTrust / CipherSuitesPolicy + 校验回调）：传输已备、配置为零，是 HTTPS 可信面的关键缺口。
  4. 命名常量批：HttpStatusCode（67）、请求/响应头名（41+30）、HttpMethod 补全、 WebSocket opcode 与 WebSocketCloseStatus、QuicError（12）、TlsCipherSuite（337）、 SocketOptionName（50）；动手前先解 AddressFamily 双定义陷阱。便宜、与既有常量补齐（AJ/AJ2）同轨。
  5. Cookie 三件套（Cookie / CookieCollection / CookieContainer）： 解析/格式化纯逻辑可先行，jar 状态随第 1 项落地。
  6. 本机网络信息面（NetworkInformation 的 36 个可直接对应类型）+ ICMP Ping： getifaddrs 与系统计数直译，运维/诊断场景。
  7. 通用 SSE 解析器（SseParser / SseItem / SseFormatter）：小而独立， 把现有 turn 专用 SSE 客户端泛化。
  8. 头值解析族 + CIDR：System.Net.Http.Headers 的 20 个结构化头值类型与 IPNetwork，全是纯函数，适合批处理。

覆盖边界

  • 以 ref 源码为公共面权威来源；仅存在于 src 实现、未进 ref 的表面不在普查内。
  • 嵌套类型按（命名空间，类型名）归并：337 条记录 → 334 个类型（Enumerator / JsonContent / SseParser 各一组同名重复）。
  • 泛型委托的抽取伪影 2 个（T、TContext）已在分类表中按伪影登记为模型不合，不假装是真实类型。
  • System.Net.Http.WinHttpHandler 程序集在普查范围内（Windows 平台 handler，归模型不合）； System.Net.Http.Json 的 JSON 扩展按组合胶水计可直接对应。
  • 分类为类型级；如 Socket 的长尾成员差异、SslStream 的传输/对象层之分， 以分类表注记为准，不另拆成员级计数。
