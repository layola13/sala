.NET net Surface × sa_std Gap Census

This page is one volume of the cross-language std census batch (same batch: Rust full std, Go net, Python net, Java net, Android net, iOS net). .NET's network standard library has two layers: the modern core (Sockets / HttpClient / SslStream / QUIC / WebSockets) and a whole layer of old models from the WebRequest era (WebClient / HttpWebRequest / ServicePoint / caching policies), the latter of which even .NET itself keeps marking Obsolete. This page compares the public surface of all 19 System.Net.* assemblies against the sa_std network surface type by type, in four categories, and gives a priority shortlist for closing gaps.

Method and Inventory Scale

Two-side mechanical extraction (scripts and artifacts in tools/dotnet_net_census/, re-runnable): the .NET side parses type and member declarations and [Obsolete] marks in the ref source; the SA side parses @extern / #def / [MACRO] and C header declarations. The .NET side extracted 337 type records (334 types after merging same names) / 4,194 members in total (method 1,355, property 1,214, enum_member 1,134, ctor 374, field 100, event 17). The classification granularity is type level; per-type results are in gap_classification.tsv; member-level differences for head types are written in the notes. The four categories use the same methodology as the rest of the batch.

Overall result: existing equivalent 32 (9.6%) / directly mappable 140 (41.9%) / needs modeling 62 (18.6%) / model mismatch 100 (29.9%). Weighted by members: 671 / 1,927 / 915 / 681. The composition of model mismatch is no mystery: exception types 17, delegates 24, event arguments 14, 12 types already marked Obsolete by .NET itself at type level, and the remaining 33 are platform-specific items (Windows control codes, PAC scripts, ExtendedProtection, etc.). Looking at the modern surface after removing type-level Obsolete (322 types): 32 / 139 / 62 / 89.

Classification Methodology

  • Existing equivalent: the functionality is already covered by sa_std's existing surface (the shape may differ: handles vs objects, status codes vs exceptions).
  • Directly mappable: sa_std does not have it, but it can be filled in by direct translation — pure functions, named constants, parameter bags, protocol clients of the direct-translation kind. “Simply not done yet” is the whole meaning of this category.
  • Needs modeling: the concept is valid and the underlying primitives are mostly ready, but a layer of state/object model is needed (handle tables, configuration objects, callback registration).
  • Model mismatch: depends on things outside the SA model, or is an old model .NET itself has abandoned. Family rules: exception types (SA models with status codes + SA_NET_ERROR_CODE_* + error code names, no exception objects), delegates and EventArgs (SA models with handles + poll/callback registration, no event subscription), platform-specific items.

Sockets: the Core Is Ready, the Long Tail Is Platform Items

The core of Socket (191 members) lines up item by item with sa's net surface: connect/listen/accept, read/write/peek/vectored, the option family (nodelay, keepalive, TTL, send/receive buffers, linger, quickack, defer-accept, both set and get), UDP send_to/recv_from and multicast join/leave, the Unix domain (the address object family, 144 symbols including abstract/unnamed shapes) — TcpClient / TcpListener / UdpClient / NetworkStream are likewise existing equivalents. The differences are concentrated in .NET's three async shapes (APM / SocketAsyncEventArgs / Task extensions; sa models with the netx reactor and poll) and Windows-specific items (IOControlCode's 34 WSAIoctl code values, TransmitFile, SendPackets).

Warning There is a double-definition trap in address family naming (already registered by the AJ2 census): in .sal, SA_NET_AF_IPV4=4 / IPV6=6 are std-internal numbers, while sa_net_addr_family returns OS values (AF_INET=2 / AF_INET6=10). AddressFamily / ProtocolFamily are therefore counted only as “directly mappable” with a note that the trap must be resolved first, not as existing equivalents.

HTTP Client: Transport Complete, the Handler Layer Is the Largest Modeling Block

sa_http_client_*'s 57 symbols cover connection setup, request construction, headers, body, synchronous/asynchronous sending (async + poll + take_response), response status/headers/body (including the streaming body_reader), SSE and WebSocket upgrade connections. But the real bulk of .NET's HttpClient is in the handler layer: SocketsHttpHandler (connection pools, pool lifetimes, ConnectCallback, plaintext stream filtering) and HttpClientHandler's configuration surface, where cookies, proxy, redirects, and automatic decompression all have 0 keyword hits across sa's whole network surface. Almost all of System.Net.Http's 15 needs-modeling types belong to this group — this is the census's first-priority modeling target. The request/response object primitives (HttpRequestMessage / HttpResponseMessage) are complete; the object layer needs assembly; the content family is mostly existing equivalents (in-memory bodies are covered by req_set_body, multipart has multipart.sai), the exception being streaming request body writing (StreamContent), which is not seen among the sa http client symbols.

HTTP Server and SSE

sa's http_server surface (46 externs, including v2's accept / resp_send / stream_write and sa_http_server_websocket_upgrade) is in accept-loop shape; .NET's HttpListener is an object model of prefix routing + context queues + authentication — the transport capability is ready and the object layer needs modeling, so HttpListener and its Context/Request/Response group of 8 types are counted as needs modeling. SSE goes the other way: sa has the turn-style client sa_http_client_sse_* (built for LLM streaming), while .NET's System.Net.ServerSentEvents is a general incremental parser, SseParser — sa has no standalone parser surface; a parser is a pure state machine and is counted as directly mappable.

TLS and Certificates: Transport Ready, the Certificate Surface Is Zero

The transport surface of tls_client / tls_server / dtls is complete (connections, reading/writing, ctx, accept, add_ca_file), plus a shaped surface that .NET does not have at all (see below). But SslStream's object layer — wrapping TLS onto an arbitrary stream, negotiation options, certificate validation/selection callbacks, the SslCertificateTrust trust store, cipher suite policies — has no counterpart on the sa side: cert|x509 keyword hits across the full surface are 0 (only the CA file as a single configuration item). The single TlsCipherSuite enum has 337 values (the largest single enum in this extraction), and sa tls has no suite naming surface at all; ALPN likewise has only the shaped negotiation result JSON, no named constants. This group is counted as: transport-related existing equivalents are presented in the SslStream row with modeling notes, 8 option/callback types need modeling, and 11 naming-surface types are directly mappable.

WebSocket, DNS, Network Information, Mail

WebSocket: the client (ws_client: connect/send/recv/ping/close, wss inheriting TLS policy, add_ca_file) and the server upgrade (http_server's upgrade entry point) are both existing equivalents; what is missing is the options layer (ClientWebSocketOptions including proxy and certificate callbacks, needs modeling) and named constants (opcodes and WebSocketCloseStatus have no named group — AJ2 already registered a similar ws opcode gap). DNS: sa has only the reverse query sa_std_net_addr_reverse_lookup and error codes; forward resolution is implicit in the host name string of connect, with no Dns-style standalone query surface or result set (IPHostEntry) — the same cross-language consistent gap as the first item on the Android line's shortlist. Network information: of the whole System.Net.NetworkInformation domain's 44 types, 36 are directly mappable — network interface enumeration, interface properties, statistics snapshots, and ICMP Ping are all 0 on the sa side, but all are direct translations of system queries, with no model obstacle. Mail: both SMTP and MIME are 0 on the sa side. SmtpClient is of the protocol direct-translation kind (counted as directly mappable, STARTTLS reuses tls_client), while MailMessage and its attachment/view aggregation of 9 types need a data model first; FTP is similar (FtpWebRequest can correspond by protocol direct translation; sa only has SSH's SFTP).

Old Model Registration (Not Entering the Closing Shortlist)

The bulk of the 100 model mismatches is what .NET itself is abandoning; registered honestly, not ported: the pluggable protocol model of WebRequest / HttpWebRequest / WebResponse, WebClient (officially not recommended, SYSLIB0014; 7 member-level Obsolete marks in ref), ServicePointManager, the 5 caching policy types of System.Net.Cache, the 6 ExtendedProtection types, and WebClient's event/delegate family of 18. In numbers: 12 types marked Obsolete at type level, 84 marked Obsolete at member level (24 of them in the Requests assembly).

Surfaces Unique to the sa Side (.NET Has No Counterpart)

  • SSH: client + server + SFTP (ssh.sai, 26 externs) — .NET's core library still has no SSH.
  • TLS fingerprint surface: JA3/JA4 ClientHello shaping and negotiation result export of sa_std_tls_shaped_*.
  • DTLS server, the netx io_uring reactor, WebSocket over Unix socket, the public HTTP/3 session API (see the QUIC section).

Priority Shortlist for Closing Gaps

  1. Modeling the HTTP client handler group (SocketsHttpHandler / HttpClientHandler / HttpClient facade): cookies, proxy, redirects, automatic decompression from 0 to present + connection pool semantics. The largest needs-modeling block in this census, and a high-frequency surface for CXU and proxy scenarios.
  2. A standalone DNS forward resolution surface (Dns / IPHostEntry / DnsEndPoint): address and record queries + result-set handles; cross-language corroboration with the first item on the Android line's shortlist.
  3. The TLS configuration and certificate surface (SslClientAuthenticationOptions / SslServerAuthenticationOptions / SslCertificateTrust / CipherSuitesPolicy + validation callbacks): transport is ready, configuration is zero — a key gap in the HTTPS trust surface.
  4. The named constant batch: HttpStatusCode (67), request/response header names (41+30), HttpMethod completion, WebSocket opcodes and WebSocketCloseStatus, QuicError (12), TlsCipherSuite (337), SocketOptionName (50); resolve the AddressFamily double-definition trap before starting. Cheap, and on the same track as the existing constant fill-ins (AJ/AJ2).
  5. The Cookie trio (Cookie / CookieCollection / CookieContainer): the parsing/formatting pure logic can go first; the jar state lands with item 1.
  6. The local network information surface (NetworkInformation's 36 directly mappable types) + ICMP Ping: direct translation of getifaddrs and system counters, for operations/diagnostics scenarios.
  7. A general SSE parser (SseParser / SseItem / SseFormatter): small and standalone, generalizing the existing turn-specific SSE client.
  8. The header value parsing family + CIDR: System.Net.Http.Headers' 20 structured header value types and IPNetwork — all pure functions, suitable for batch processing.

Coverage Boundaries

  • The ref source is the authoritative source for the public surface; surfaces that exist only in src implementations and never entered ref are outside the census.
  • Nested types are merged by (namespace, type name): 337 records → 334 types (Enumerator / JsonContent / SseParser each have one group of same-name duplicates).
  • Two extraction artifacts of generic delegates (T, TContext) are registered as model mismatch artifacts in the classification table, not pretending to be real types.
  • The System.Net.Http.WinHttpHandler assembly is within census scope (a Windows platform handler, classified as model mismatch); System.Net.Http.Json's JSON extensions are counted as directly mappable composition glue.
  • Classification is at type level; long-tail member differences such as Socket's, and SslStream's transport/object layer split, are governed by the classification table notes, with no separate member-level counts.
