Go net Standard Library × sa_std Gap Census (go1.27.3)

This page is the Go volume of the “cross-language std census” batch: taking the net family of the latest stable Go official source (go1.27.3) as the reference frame, it mechanically extracts its exported surface and compares it item by item against sa_std's network contract surface, producing a four-category gap table and a priority shortlist for closing gaps. The same batch also includes the Rust Full std Census, with consistent methodology, serving as mutual references.

How to read this: the low-level socket surface (TCP/UDP/Unix/multicast/vectored IO/fd adoption) and the HTTP send/receive backbone are already equivalent over a large area — this is the empirical side of sa_std's “basic cores built in” doctrine. The bulk of the gaps is not “the capability does not exist”, but two categories: the object model is not yet built (needs modeling 40%: Go's Client/Transport/Server/Config/ServeMux and other configuration and callback objects are, in SA, a managed runtime + handle function families, with no carrier for per-item configuration) and pure functions not yet done (directly mappable 24%: the semantics can land directly in sa_std, they are simply not yet implemented). Model mismatch is only 2.3%, and is concentrated in context propagation, channel signals, panic control flow and error chains — these are model conclusions, not defects.

Key Points by Package

PackageConclusion
netThe socket surface is the most complete: connect/listen/accept/read/write/peek/vectorization/timeouts/keepalive/linger/TTL/buffers/multicast/only-v6/reuseport/try_clone/from_raw_fd are all present. Gaps are at the periphery: DNS record-type queries (see the dedicated section), IP value semantics, network interface enumeration, raw IP sockets, MPTCP, listener deadlines and the SyscallConn callback surface
net/netipparse/format and socket address ascii conversion already have equivalents; the remaining 61 entries are almost all pure functions — address predicates (IsPrivate/IsLoopback…), value operations (Next/Prev/Compare/Unmap/Zone), the whole Prefix family — the highest value-for-effort block in the entire census
net/urlsa_std_url_parse is only a one-shot component output; the URL value object, the Values query map, percent encoding/decoding, userinfo, and relative reference resolution are all missing — every HTTP consumer will run into this
net/httpThe send/receive backbone is equivalent (client req/resp handles + SSE + WebSocket, server req/resp/streaming/upgrade). The structural difference is at the object layer: Client/Transport connection pools and policies, the Server configuration object, ServeMux routing (Go 1.22 method patterns), the Handler callback model. Point-like real gaps: Cookies in full, the proxy surface, CSRF (CrossOriginProtection, Go 1.25+), wire-format serialization, static file serving
crypto/tlsThe connection surface is equivalent (client/server/shaped fingerprint surface); the Config configuration object (the bulk of the 125 needs-modeling entries) plus session resumption, suite metadata, ECH, OCSP reading, and keying material export are gaps. Go's tls.QUIC* is a “handshake provider only”, while SA has a complete QUIC stack + HTTP/3 session surface (sa_std_http3_* in quic.sai); the shapes differ and are registered as modeled mappings
net/http/httputilReverseProxy is a core CXU scenario and currently has no ready-made counterpart: it needs to be assembled from client+server handles and a hook model decided. Dump and the standalone chunked codec are small direct gaps
net/smtp / net/mailEntire packages missing and entirely direct: the SMTP client (27 entries) depends on TCP/line protocol/TLS upgrade, all of which already exist; mail (19 entries) is a pure RFC 5322 parser. Self-contained, no design risk
net/rpc + jsonrpcA framework-level gap (58 entries needing modeling): service registry + codec interface + gob wire format. JSON-RPC's wire format can be carried by the existing JSON surface; the blocker is the rpc framework itself
net/textprotoLine-protocol tooling is missing as a whole (Reader/Writer/Conn, 34 direct entries); MIME multi-value headers and http.Header are the same gap. Pipeline ordering needs modeling (11 entries)
cookiejar / httptestThe jar is a state object + public suffix data table, to be planned together with the Cookie surface; httptest is a testing tool surface (31 entries), not a runtime gap, needed only when porting Go tests

DNS Dedicated Section

The 48 DNS-related entries inside the net package form their own section: existing equivalent 11 (LookupHost/LookupIP via sa_std_net_to_socket_addr_list, LookupAddr via sa_std_net_addr_reverse_lookup), directly mappable 22, needs modeling 14, model mismatch 1. The conclusion has three layers:

  • Host resolution already works: both A/AAAA forward and PTR reverse lookups are present; address lists are presented through handle iteration.
  • Record-type queries are missing as a whole block (the bulk of the 22 direct entries): LookupCNAME/MX/NS/SRV/TXT (including the Resolver methods of the same names) and the MX/NS/SRV record types, and the services-table query of LookupPort. sa_std has no DNS wire codec or query client — this is the largest complete gap in the net domain, and its landing shape is clear (UDP/TCP queries + message codec + system resolver configuration reading).
  • The resolver object is not to be built (14 entries needing modeling): Resolver's pluggable Dial, PreferGo, StrictErrors and the structured DNSError fields — SA's resolution is std built-in + a status-code model, an intentional model difference.

Priority Shortlist for Closing Gaps

Ordering principle: real usage surface first (CXU's proxy/HTTP services and clients, session flows), followed by whole blocks that are “pure functions, zero design risk, can land in bulk”.

The large items not on the list are registered honestly: the http object model (about 200 entries needing modeling) and the rpc framework (58 entries) are an architectural decision about “whether to introduce an object layer”, not part of a gap-closing batch; httptest (31 entries) is a testing tool surface, to be revisited when test-porting needs arise.

Model Mismatch List (32 entries, conclusive registration)

Composition: context.Context propagation/cancellation (DialContext, Request.Context, HandshakeContext, BaseContext/ConnContext factories, context keys, about 12 entries in total), channel signals (Dialer.Cancel, Request.Cancel, CloseNotifier), panic control flow (ErrAbortHandler), error-chain Unwrap (the various error types), redirect control-flow signals (ErrUseLastResponse), Control callback hooks for dialing/listening. These depend on Go runtime semantics and SA does not adopt them — registered as model conclusions, not defects to fix.

Re-running

All scripts and baseline artifacts are in tools/go_net_census/: the extractors (extract_go_net.py / extract_sa_net.py), the classifier (compare_go_net.py + cluster-by-cluster rules rules.py), the two-side inventories (go_net_api.json / sa_net_api.json) and the full classification table (gap_table.tsv, 1,378 rows, each individually checkable). Re-running with the same-version inputs and the checked-in artifacts is byte-identical (verified).
