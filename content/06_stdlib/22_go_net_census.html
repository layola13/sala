Go net 标准库 × sa_std 缺口普查（go1.27.3）

本页是「跨语言 std 普查」批次中 Go 的一册：以 Go 官方源码最新 stable （go1.27.3）的 net 家族为参照系，机械抽取其导出表面，与 sa_std 的网络契约面逐条比对，产出四分类缺口表与优先补齐短名单。 同批另有 Rust 全 std 普查， 口径一致、互为参照。

读法：底层 socket 面（TCP/UDP/Unix/组播/向量 IO/fd 收编）与 HTTP 收发主干 已大面积等价——这是 sa_std「基础核心内置」学说的实证面。缺口的主体不是 「能力不存在」，而是两类：对象模型未建（需建模 40%：Go 的 Client/Transport/Server/Config/ServeMux 等配置与回调对象，在 SA 里是托管 运行时 + 句柄函数族，逐项配置无承载）与纯函数没做 （可直接对应 24%：语义可直接落 sa_std，只是尚未实现）。模型不合仅 2.3%， 且集中在 context 传播、channel 信号、panic 控制流与错误链——属模型结论， 不是缺陷。

按包要点

包结论
net套接字面齐全度最高：connect/listen/accept/读写/peek/向量化/超时/保活/linger/TTL/缓冲/组播/only-v6/reuseport/try_clone/from_raw_fd 一应俱全。缺口在外围：DNS 记录型查询（见专节）、IP 值语义、网卡枚举、原始 IP 套接字、MPTCP、监听器期限与 SyscallConn 回调面
net/netipparse/format 与 socket 地址 ascii 互转已有等价；其余 61 条几乎全是纯函数——地址谓词（IsPrivate/IsLoopback…）、值运算（Next/Prev/Compare/Unmap/Zone）、Prefix 全家——是全普查性价比最高的一块
net/urlsa_std_url_parse 只是一次性分量出参；URL 值对象、Values 查询映射、百分号编解码、userinfo、相对引用解析全缺——每个 HTTP 消费者都会撞到
net/http收发主干等价（客户端 req/resp 句柄 + SSE + WebSocket、服务端 req/resp/流式/升级）。结构性差异在对象层：Client/Transport 连接池与策略、Server 配置对象、ServeMux 路由（Go 1.22 方法模式）、Handler 回调模型。点状真缺口：Cookie 全面、代理面、CSRF（CrossOriginProtection，Go 1.25+）、线格式序列化、静态文件服务
crypto/tls连接面等价（client/server/shaped 指纹面）；Config 配置对象（125 条需建模的主体）与会话恢复、套件元数据、ECH、OCSP 读取、密钥材料导出是缺口。Go 的 tls.QUIC* 是「仅握手提供者」，SA 是完整 QUIC 栈 + HTTP/3 会话面（sa_std_http3_* 在 quic.sai），形态不同、按映射建模登记
net/http/httputilReverseProxy 是 CXU 的核心场景，目前无现成物：需以 client+server 句柄拼装并裁定钩子模型。Dump 转储与 chunked 独立编解码器是小的 direct 缺口
net/smtp / net/mail整包缺失且整包 direct：SMTP 客户端（27 条）依赖的 TCP/行协议/TLS 升级都已有；mail（19 条）是纯 RFC 5322 解析器。自包含、无设计风险
net/rpc + jsonrpc框架性缺口（58 条需建模）：服务注册表 + codec 接口 + gob 线格式。JSON-RPC 的线格式可由现有 JSON 面承载，卡点在 rpc 框架本身
net/textproto行协议工具整体缺失（Reader/Writer/Conn 34 条 direct）；MIME 多值头与 http.Header 是同一缺口。Pipeline 定序需建模（11 条）
cookiejar / httptestjar 是状态对象 + 公共后缀数据表，随 Cookie 面一并规划；httptest 是测试工具面（31 条），非运行时缺口，移植 Go 测试时才需要

DNS 专节

net 包内与 DNS 相关的 48 条单独成节：已有等价 11 （LookupHost/LookupIP 经 sa_std_net_to_socket_addr_list、 LookupAddr 经 sa_std_net_addr_reverse_lookup）、 可直接对应 22、需建模 14、模型不合 1。结论分三层：

  • 主机解析已通：A/AAAA 正向与 PTR 反向都在；地址列表以句柄迭代呈现。
  • 记录型查询整块缺失（22 条 direct 的主体）：LookupCNAME/MX/NS/SRV/TXT （含 Resolver 同名方法）与 MX/NS/SRV 记录类型、LookupPort 的 services 表查询。 sa_std 没有 DNS wire 编解码与查询客户端——这是 net 域里最大的一块完整缺口， 落地形态明确（UDP/TCP 查询 + 报文编解码 + 系统解析器配置读取）。
  • 解析器对象不建（14 条需建模）：Resolver 的可插拔 Dial、PreferGo、StrictErrors 与结构化 DNSError 字段——SA 的解析是 std 内建 + 状态码模型，属有意的模型差异。

优先补齐短名单

排序原则：真实使用面优先（CXU 的代理/HTTP 服务与客户端、会话流）， 其次是「纯函数、零设计风险、可批量落」的整块。

#项规模理由
1Cookie 面：解析/序列化/SameSite/属性 + 请求响应读写16 direct（+ cookiejar 9 需建模）会话与登录流的核心面，目前全层零符号（实查）
2HTTP 代理面：Transport.Proxy / ProxyFromEnvironment / ProxyURL / CONNECT 头约 6 条 direct面极小、杠杆极大：CXU 自身是代理生态，客户端不出代理是硬伤
3DNS 记录型查询客户端（CNAME/MX/NS/SRV/TXT + 记录类型）22 条 direct 主体net 域最大整块缺口；邮件校验、服务发现都依赖
4IP/CIDR 值层：netip 谓词与值运算 + Prefix + net 的 IP/IPNet/IPMask约 100 条 direct纯函数批量落；同时是 slars/bc2sa 的 Rust net 类型映射地基
5URL 补全：Values 查询映射、百分号编解码、userinfo、相对引用解析约 30 条 direct每个 HTTP 消费者的日常面；url_parse 的自然延伸
6MIME 多值头 + textproto 行协议工具约 40 条 direct一并解锁 http.Header 保真与 smtp 类行协议客户端
7反向代理（httputil.ReverseProxy 的 SA 形态）32 条需建模建模类第一位：CXU 核心场景；前置是 handler/钩子模型的一次裁定
8SMTP 客户端整包27 条 direct自包含协议客户端，依赖面（TCP/行协议/TLS）都已就绪
9网卡枚举（Interfaces/InterfaceAddrs/Flags/MAC/MTU）17 条 direct小而完整；本地地址选择、局域网服务发现的前置
10TLS 元数据小面：套件清单查询、OCSPResponse、VerifyHostname、ExportKeyingMaterial约 11 条 direct证书运维与调试面；与 Config 对象建模解耦、可先行

未入名单的大头如实登记：http 对象模型（约 200 条需建模）与 rpc 框架 （58 条）是「要不要引入对象层」的架构裁定，不属补齐批次； httptest（31 条）是测试工具面，随测试移植需求再议。

模型不合清单（32 条，结论性登记）

构成：context.Context 传播/取消（DialContext、Request.Context、 HandshakeContext、BaseContext/ConnContext 工厂、context 键等约 12 条）、 channel 信号（Dialer.Cancel、Request.Cancel、CloseNotifier）、panic 控制流 （ErrAbortHandler）、错误链 Unwrap（各错误类型）、重定向控制流信号 （ErrUseLastResponse）、拨号/监听的 Control 回调钩子。这些依赖 Go 运行时 语义，SA 不采纳——登记为模型结论，不是待修缺陷。
