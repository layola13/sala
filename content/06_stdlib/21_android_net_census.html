Android net 表面 × sa_std 缺口普查

本页是跨语言 std 普查批的一份（同批：Rust 全 std、Go net、Python net、Java net、.NET net、iOS net）。 Android 的「net std」与桌面平台不同构：除 libcore 带来的 java.net/javax.net.ssl 外， 还有一整层桌面 std 不存在的平台连接模型（能力、计费、多网络、系统策略）。 本页把两者分开清点：可移植的协议/工具面按四分类与 sa_std 比对，平台模型单列登记、不混入缺口计数。

来源与版本

侧来源
Android 公共 API 签名面AOSP platform/prebuilts/sdk，分支 android16-release （HEAD 3b7daadc，2025-04-18），文件 36/public/api/android.txt（签名格式 2.0）—— 即 Android 16 / API level 36 的 SDK 公共 API 精确签名清单。新版 AOSP 的 frameworks/base 已不内嵌 current.txt，签名面以 prebuilts/sdk 的 per-level android.txt 为权威来源；frameworks/base 同分支 （HEAD 99b01a65）的 core/java/android/net 源码作辅证。
libcore 差异基线桌面 OpenJDK 源码树 java.base 的 java/net、javax/net、 javax/net/ssl 三包公共顶层类型（107 个）。
SA 侧基线sci main 8a943911 的 sa_std 网络面： 11 个 .sai 契约共 457 个 extern（net 222、http_client 57、http_server 46、quic 29、 ssh 26、tls_client 22、http2 14、ws_client 12、tls_server 11、dtls 11、netx 7）， 另 .sa 层 487 个 fn/宏（简化面 sa_net_* 与宏包装，只作注记、不逐项计入比对）。

NDK/bionic 的 socket 层是 POSIX、非 Android 特有，作边界注明、不展开。

方法与清单规模

双边机械抽取（脚本与产物在 tools/android_net_census/，可复跑）： Android 侧解析签名文件的 package/class/ctor/method/field 声明；SA 侧解析 .sai 的 @extern 声明。全量分类范围共 323 类 / 1,902 方法 / 544 字段（13 个包）； WiFi 与 Telephony 家族仅登记（312 类 / 2,069 方法），不逐项分类。 缺口四分类口径与同批一致：可直接对应 / 需建模 / 模型不合 / 已有等价。

平台特有模型（桌面 std 没有的层）

网络能力模型

NetworkCapabilities（30 方法、49 个字段常量）把连接「质量」做成一等公民： 能力位（NET_CAPABILITY_INTERNET / VALIDATED / CAPTIVE_PORTAL / NOT_METERED 等，经 hasCapability 查询）、transport 类型（hasTransport：蜂窝/WiFi/以太/VPN/蓝牙）、 上下行带宽估计、信号强度、订阅 ID 集合。NetworkRequest.Builder 以同一套能力位声明需求， 系统据此选路并以 ConnectivityManager.NetworkCallback 回调可用/丢失/能力变化。 桌面 std 的连接是「能不能连」的二值世界，没有这一层。

计费与多网络绑定

计费是选路输入：NET_CAPABILITY_NOT_METERED、ConnectivityManager.getMultipathPreference、 getRestrictBackgroundStatus 决定后台与多路径行为。多网络是句柄化的： Network 对象（12 方法）可 bindSocket(Socket/DatagramSocket/FileDescriptor) 把单个套接字钉到指定网络，getAllByName 在该网络上解析， bindProcessToNetwork / getProcessDefaultNetwork 设置进程默认网络； TrafficStats（39 方法）按 UID 做流量归因计量。sa_std 的连接是全局单栈， 此模型整体属平台服务、不进补齐名单。

平台强制策略

三项策略由 OS 强制、应用只能查询或顺应：cleartext 策略 （android.security.NetworkSecurityPolicy.isCleartextTrafficPermitted() 与 NetworkSecurityConfig 的 per-domain 配置决定明文 HTTP 是否放行）； Private DNS（系统级 DoT：LinkProperties.isPrivateDnsActive() / getPrivateDnsServerName() 暴露状态与服务器名，系统解析路径自带机会性 DoT， DnsResolver 的查询亦走该路径）；强制门户与验证 （CaptivePortal、VALIDATED 能力位影响应用可见的「已联网」语义）。 与 iOS 的 NWPath/ATS 是同一类平台层，可对照阅读。

覆盖边界

  • 成员级清单以签名文件为准；抽取器初版漏掉类头带注解（@Deprecated public class）的声明， 已修正并复跑（595 → 635 类 / 7,805 成员），rtp/sip 两包即此情形。
  • libcore 差异为顶层类粒度；方法级增减未逐项比对。
  • WiFi / Telephony 仅登记计数，未逐项分类。
  • android.security 不在抽取包范围内，策略一节的存在性由签名文件直接查证。
  • 结论只来自实际抽取的清单（tools/android_net_census/out/ 随页入库），无凭印象判定。
