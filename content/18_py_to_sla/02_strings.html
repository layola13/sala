Strings and f-Strings

psa string literals (single or double quotes, triple-quoted forms included) are supported by the census; a string bound to a variable is a dynamic string value. SLA string literals are byte strings; a literal bound with let can be printed, measured with len, and compared with str_eq (after importing sa_std/string.sa). String equality in SLA is a function call, not == on the text form.

Interpolation: f-String vs println/format

SLA has no f-string. The counterpart is placeholder formatting: println("name={}, age={}", name, age) for output, and format("age={}", age) to build a string value — the same format the Rust companion section uses to build a String.

psa-side status, per the census: f-strings are partially supported. Basic interpolation works (in print and, for int/bool/str values, as a general value); format specs and conversions ({x:03d}, {x!r}) were loudly refused at census time and have since been implemented as task 171-A, pending integration into the psa master. Interpolating a float is blocked by the same float-printing defect (xxiii) noted on page 1.

One measured SLA quirk, recorded rather than hidden: on the verified toolchain, passing a let-bound string variable as a format(...) argument renders garbage, while a string literal in the same position and the same variable in println both render correctly. The program below therefore builds its string from the integer value and interpolates the string through println.

psaSLA
name = "Ada"
age = 36
print(f"name={name}, age={age}")
msg = f"age={age}"
print(msg)
print(len(name))
print(name == "Ada")
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/string.sa"

fn main() -> i32 {
    let name = "Ada";
    let age = 36;
    println("name={}, age={}", name, age);
    let msg = format("age={}", age);
    println("{}", msg);
    println("{}", len(name));
    println("{}", str_eq(name, "Ada"));
    return 0;
}

Verified output (SLA): name=Ada, age=36, age=36, 3, true, exit code 0. The psa program prints the same lines with Python's spelling (True for the last line).

Key Points of This Page

  • psa strings are dynamic values; SLA string literals print, measure (len), and compare (str_eq) directly.
  • No f-string in SLA: println/format placeholders are the counterpart.
  • psa f-strings are partially supported: basic interpolation yes; format specs/conversions implemented as task 171-A, pending integration; float interpolation blocked by (xxiii).
  • Measured quirk: a let-bound string variable passed to format(...) renders incorrectly on the verified toolchain; literals and println are unaffected.
