Lists, Dicts, Sets, Indexing, Slicing, and Comprehensions

Lists ↔ Vec

psa list literals are supported in both a static same-type form and a dynamic heap form (heterogeneous elements included); the census marks the literal itself partially supported because a container literal passed directly as a call argument is still loudly refused. Indexing, index assignment, append, and len are supported. SLA's counterpart is Vec<T> (import sa_std/vec.sa): one element type, push for append, the same bracket indexing, and len.

psaSLA
xs = []
xs.append(10)
xs.append(20)
xs.append(30)
print(len(xs))        # 3
print(xs[0] + xs[2])  # 40
xs[1] = 25
print(xs[1])          # 25
total = 0
i = 0
while i < len(xs):
    total = total + xs[i]
    i = i + 1
print(total)          # 65
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/vec.sa"

fn main() -> i32 {
    let xs: Vec<i32> = Vec::new();
    xs.push(10);
    xs.push(20);
    xs.push(30);
    println("{}", len(xs));
    println("{}", xs[0] + xs[2]);
    xs[1] = 25;
    println("{}", xs[1]);
    let sum = 0;
    let i = 0;
    while i < len(xs) as i32 {
        sum = sum + xs[i];
        i = i + 1;
    }
    println("{}", sum);
    return 0;
}

Verified output (SLA): 3, 40, 25, 65, exit code 0.

Dicts ↔ HashMap

psa dict literals are dynamic, insertion-ordered dicts (census: supported, with string/int/bool/None keys). SLA's counterpart is HashMap (import sa_std/hashmap.sa). The shape of a lookup differs: psa m.get("c", 0) supplies the default inline, while SLA's get returns an Option, and .copied().unwrap_or_default() is the idiom that supplies the zero default. A missing key read as m["c"] in psa fails loudly (panic 77054); in SLA the same situation is just the None case of get.

psaSLA
m = {}
m["a"] = 1
m["b"] = 2
print(f"{m['a']},{m.get('c', 0)},{len(m)}")  # 1,0,2
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/hashmap.sa"
@import "sa_std/core/option.sa"

fn main() -> i32 {
    let m = HashMap::new();
    m.insert("a", 1);
    m.insert("b", 2);
    let ga = m.get("a").copied().unwrap_or_default();
    let missing = m.get("c").copied().unwrap_or_default();
    println("{},{},{}", ga, missing, len(m));
    return 0;
}

Verified output (SLA): 1,0,2, exit code 0.

Sets ↔ HashSet

psa set literals are supported (census, batch D5). SLA's counterpart is HashSet (import sa_std/hashset.sa): duplicates collapse on insert, membership is contains (psa's in), and len gives the size. This section verifies literals, deduplication, and membership on both sides; union / intersection / difference are method-and-loop work on both sides and are not asserted here.

psaSLA
s = {1, 2, 2, 3}
print(len(s))    # 3
print(2 in s)    # True
print(9 in s)    # False
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/hashset.sa"

fn main() -> i32 {
    let s = HashSet::new();
    s.insert(1);
    s.insert(2);
    s.insert(2);
    s.insert(3);
    println("{}", len(s));
    println("{}", s.contains(2));
    println("{}", s.contains(9));
    return 0;
}

Verified output (SLA): 3, true, false, exit code 0.

Indexing and Slicing

Indexing corresponds directly, except for negative indices: psa's a[-1] is written in SLA as a[len(a) - 1]. Slicing is where the sides genuinely differ. psa slicing is supported in full (static lists, dynamic lists, and strings, with CPython's index normalisation). SLA has no slice syntax and no slice method — the plugin's own demo corpus says so and writes the explicit loop instead: a slice is a fresh Vec filled by a range loop over the source indices, as below.

psaSLA
a = [10, 20, 30, 40]
print(a[0])   # 10
print(a[-1])  # 40
b = a[1:3]
print(f"{len(b)},{b[0] + b[1]}")  # 2,50
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/vec.sa"

fn main() -> i32 {
    let a: Vec<i32> = Vec::new();
    a.push(10);
    a.push(20);
    a.push(30);
    a.push(40);
    println("{}", a[0]);
    println("{}", a[len(a) as i32 - 1]);
    let b: Vec<i32> = Vec::new();
    for i in 1..3 {
        b.push(a[i]);
    }
    println("{},{}", len(b), b[0] + b[1]);
    return 0;
}

Verified output (SLA): 10, 40, 2,50, exit code 0.

Comprehensions

psa comprehensions — list, dict, and set comprehensions, plus generator expressions — are supported by the census. SLA has no comprehension syntax at all: the same computation is an explicit loop that pushes into a fresh Vec, with the comprehension's if clause becoming an if inside the loop.

psaSLA
squares = [i * i for i in range(5) if i % 2 == 0]
print(len(squares))  # 3
print(f"{squares[0]},{squares[1]},{squares[2]}")  # 0,4,16
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/vec.sa"

fn main() -> i32 {
    let squares: Vec<i32> = Vec::new();
    for i in 0..5 {
        if i % 2 == 0 {
            squares.push(i * i);
        };
    }
    println("{}", len(squares));
    println("{},{},{}", squares[0], squares[1], squares[2]);
    return 0;
}

Verified output (SLA): 3, 0,4,16, exit code 0.

Key Points of This Page

  • list ↔ Vec<T>, dict ↔ HashMap, set ↔ HashSet; len is spelled the same on both sides.
  • Lookup defaults: psa m.get(k, 0) ↔ SLA get(k).copied().unwrap_or_default().
  • Negative indices and slicing are psa-only forms; SLA writes len(a) - 1 and an explicit copy loop (no slice syntax exists).
  • Comprehensions are psa-only; SLA writes the loop out.
