Comments, Variables, Numbers, and Print

This section is the side-by-side companion for Python programmers: the left column of every table is a program in psa (the Python-syntax frontend, .psa source, compiled by the psa compiler), the right column is the same program written in SLA. It follows the same strict rule as the Rust companion section: every SLA code block in this section was actually compiled and run before it was written down (toolchain: sa 0.1.8 host + the SLA plugin in dev mode, SA text route, verified 2026-11-26). The output quoted under each program is the output the SLA program really printed. The psa-side support status of each construct is taken from the psa syntax census (sapy repository, 2026-11-25, updated 2026-11-26: 35 supported, 8 partial, 3 gaps of 46 constructs); where psa supports a construct only partially, or not yet, the page says so instead of smoothing it over. The psa programs themselves are written against that census.

Comments

psa keeps Python's # line comment. SLA uses //. One measured difference: SLA has no block comment — a /* ... */ block is rejected by the parser (verified probe: found '/', expected function, struct, enum, trait, impl, const, macro, extern block, module, or annotation declaration).

psaSLA
# a line comment
x = 1  # trailing comment
 
// a line comment
let x = 1;  // trailing comment

Variables, Types, Numbers, and Arithmetic

psa variables need no declaration and no type annotation; a name is bound by assignment and may be rebound. SLA binds with let — mutable by default, so reassignment needs no extra keyword — and the type is either inferred or written after the name. const is the immutable form. Every value has one static type, and statements end with ;.

Arithmetic reads the same, with one semantic difference to unlearn: Python's / is true division (17 / 5 == 3.4) and // is floor division. SLA's / on integers is integer division, so the counterpart of SLA 17 / 5 is psa's 17 // 5. psa supports the full operator set + - * / // % **; SLA has no ** operator (powers are written as loops or library calls).

psaSLA
LIMIT = 100

x = 10
y = 20
x = x + 5
print(x + y)      # 35
print(2 + 3 * 4)  # 14
print(17 // 5)    # 3
print(17 % 5)     # 2
print(LIMIT)      # 100
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

// Variables, types, numbers and arithmetic (line comment).
const LIMIT: i32 = 100;

fn main() -> i32 {
    let x = 10;
    let y: i32 = 20;
    x = x + 5;
    println("{}", x + y);
    println("{}", 2 + 3 * 4);
    println("{}", 17 / 5);
    println("{}", 17 % 5);
    println("{}", LIMIT);
    return 0;
}

Verified output (SLA): 35, 14, 3, 2, 100, exit code 0. The psa program prints the same five numbers.

Floats

Float arithmetic is direct on both sides. Two rendering facts differ. SLA prints an f64 with a fixed ten-decimal rendering (3.5000000000), where Python prints the shortest round-trip form (3.5). And on the psa side, printing a float is currently blocked by a compiler defect (census item (xxiii): a float argument to print fails loudly with panic 77030); the fix (shortest round-trip float formatting, substrate item S3) has landed in the SLA standard library and is waiting for psa-side confirmation — until then the psa column below states the Python semantics, and the limitation is recorded here rather than hidden.

psaSLA
a = 7.0
b = 2.0
print(a / b)        # 3.5 (see note above)
print(a * b + 1.5)  # 15.5
 
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn main() -> i32 {
    let a: f64 = 7.0;
    let b: f64 = 2.0;
    println("{}", a / b);
    println("{}", a * b + 1.5);
    return 0;
}

Verified output (SLA): 3.5000000000, 15.5000000000, exit code 0.

Print

psa's print takes any number of arguments (the census marks multi-argument print, including dynamic values, as supported; sep=/end= are supported with literal values). SLA prints through println with {} placeholders, one argument per placeholder, after importing sa_std/io/print.sai and sa_std/fmt.sai — every program in this section does exactly that. Booleans print as True/False in psa and true/ false in SLA.

Key Points of This Page

  • Comments: # in psa, // in SLA; SLA has no block comment (parser-verified).
  • psa binds by assignment, dynamically typed; SLA let is mutable by default, statically typed, const is immutable.
  • SLA integer / corresponds to psa //, not psa /; SLA has no ** operator.
  • SLA prints floats with ten decimals; psa float printing is currently blocked by defect (xxiii), fix landed in the SLA std, psa-side confirmation pending.
