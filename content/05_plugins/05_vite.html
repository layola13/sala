vite — SAX Hot-Reload Dev Server

Zig 0.17This plugin is built with Zig 0.17: the 0.17 branch builds with Zig 0.17 and passes the Zig unit tests; the old 0.14.1 branch is kept unchanged.

sa_plugin_vite is a thin orchestration plugin: it packages the "edit a .sax → the browser updates immediately" development experience as the sa vite dev command. It does not reimplement compilation or HTTP — compilation reuses sax/react, and static serving and SSE reuse the core API of http-server; it itself only handles file-tree watching, rebuild orchestration, and the live-signal endpoint.

Basic facts

  • Capability segments: vite.dev, vite.build, vite.preview; version 0.1.0.
  • Dependencies: sax (required), http-server (required, with 18 pinned sa_http_server_* symbols).
  • Interface contracts: vite.sai / vite.sal provide the dev-session handle ABI (8 externs including sa_vite_dev_new, sa_vite_dev_set_entry, sa_vite_dev_set_port, sa_vite_dev_run, sa_vite_dev_stop).
  • Minimized permissions: read the project directory, write only under $PROJECT/dist/**; network limited to local GET.

Commands

CommandDescription
sa vite dev <entry.sax> [--react] [--include file.sax] [--out-dir dir] [--port p] [--debounce-ms n] [--title t] [--css f] [--public-dir d]Start the dev server + recursive watching + hot reload; the port defaults to 5173, the debounce to 80ms
sa vite build <entry.sax> [--react] [--include file.sax] [--out-dir dir] [--title t] [--css f] [--public-dir d]One-shot build producing statically deployable artifacts, without injecting the live reload client
sa vite preview [dist-dir] [--port p]Preview already-built artifacts, without watching or rebuilding; dist-dir defaults to dist

--css copies the stylesheet into dist and injects a link (and watches it in dev mode); --public-dir recursively copies the static asset directory and watches it for changes in dev. Editing a .sax/include triggers a wasm recompile; editing css/public assets only refreshes the assets and pushes a reload, without recompiling wasm.

Hot-reload mechanism

Dev mode injects a same-origin script /__sax_live_client.js into the generated index.html; the browser receives reload/error events via /__sax_live (SSE); when a build fails, the page shows an error overlay instead of a blank screen.

# 示例（在 sa_plugin_vite 目录内）
sa vite dev examples/counter.sax --out-dir /tmp/sa-vite-demo/dist \
  --port 5199 --debounce-ms 20 --title "SA Vite Demo" \
  --css assets/demo.css --public-dir public
NoteRelationship to the JS/TS toolchain: user code is physically isolated from esbuild/tsc/node; the only browser-side JS is machine-generated glue (the SAX-generated airlock.js and the injected reload client), none of it handwritten. It is currently in Phase 2 state; for the implementation route, see the plugin repository's plan.md and API_COVERAGE.md.
