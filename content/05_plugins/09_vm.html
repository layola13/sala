vm — 动态解释器虚拟机

sa_plugin_vm 是独立的动态解释器 VM 插件：通过 SA 的动态命令分发 ABI 注册 vm 子命令， 拦截所有 sa vm ... 调用，对 .sa/.sal（以及 SAB v4 字节码模块）做递归预处理、 内存内编译为字节码并在宿主 OS 上直接解释执行——无需修改主线编译器。

基本事实

  • 能力段：vm；CLI-only 插件，无自己的 .sai/.sal。
  • 依赖（均可选，按需 dlopen 已安装插件）：http-client、http-server、deno、node， 且在 sap.json 中钉死了具体符号清单。
  • 权限较宽（项目 FS 全操作、本机网络、缓存目录），因此正式运行模式需要沙箱 permissions.lock， 本地验证统一加 SA_PLUGIN_DEV=1。

命令

Usage: sa vm <run|test> [--allow-ffi] [--sandboxed] [--stats] [--profile=N]
           [--policy=file.json] [--fuel=N] [--deadline-ms=N] [--mem-cap-bytes=N]
           [--max-call-depth=N] <file.sa|.sab>

SA_PLUGIN_DEV=1 SA_PLUGINS_PATH="$PWD/zig-out/lib/libvm.so" sa vm run tests/hello_world.sa
sa vm run --stats app.sa          # 各阶段计数器 + 执行统计
sa vm run --profile=10 app.sa     # 附带最耗时函数排行

执行模型

  • 两遍预处理：先扫全部 [MACRO]/#def 再展开，支持前向引用；递归解析 @import。
  • 栈帧解释循环：基本块偏移预计算，内部子程序递归调用，线性栈安全（帧分配随返回统一释放）。
  • 类型化 FFI 桥：@extern 签名经 libffi 分发；原始 libc FFI（dlopen/dlsym 等）仅在 --allow-ffi 下暴露； 内置 shim 有 fd_*、mmap、signal、pthread_*、sqlite3_*、sa_time_*。
  • 资源限制：--fuel（按基本块计费）、--deadline-ms、--mem-cap-bytes、 --max-call-depth、--policy policy.json；默认全关。违规退出码为 128+code（如 E_FUEL_EXHAUSTED → 229）， 并在 stderr 输出一行 sa-vm-event: {...}。
警告已知范围外项：inline assembly、SIMD intrinsics、多二进制包； 浮点运算以原始位存储，浮点比较尚不支持；线程模型是同步的；panic 无 backtrace。 策略引擎对 fs/http/env/process 的能力强制尚未接线（当前只强制 ffi/threads 拒绝）。
