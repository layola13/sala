3dengines — 3D Engine Plugin Family

Zig 0.17This plugin is built with Zig 0.17: the 0.17 branch builds with Zig 0.17 and passes the Zig unit tests; the old 0.14.1 branch is kept unchanged.

sa_plugin_3dengines is not a single plugin but a family of 3D engine plugins under one directory: each module builds independently and can be installed through its own sap.json; the overall architecture is being realigned against Bevy, and the completeness gate is the repository's BEVY_ALIGNMENT.md. This page only gives an overview; in-depth usage belongs to the UI chapter, and details are in its repository README.

Module composition (summary)

PluginRole
3d_time / 3d_input / 3d_colorBevy-style frame time/timers, key input state machine, RGBA packing and sRGB/linear conversion
3d_math / 3d_transform / 3d_geometryVectors/matrices/quaternions/AABBs, transform hierarchy, P3N3UV2 vertex writing and mesh AABB computation
3d_scene / 3d_camera / 3d_light / 3d_material / 3d_pbrScene node component masks and a declarative AST constructor, camera projection, ambient/directional/point/spot lights, material and PBR ABI
3d_render_wgpuWebGPU backend ABI and wasm import contract (8 imports such as sa3d_wgpu_request_renderer)
3d_gltf / 3d_xml / 3d_yaml / 3d_animation / 3d_particle / 3d_gizmos / 3d_ecs / 3d_app / 3d_shader / 3d_image, etc.Importers and the remaining engine subsystems (some are ABI layout only, behavior to be implemented)
3d (aggregate plugin)Aggregates the whole family and installs the SAX sidecar assets: sa3d.sai, sa3d.sal, sa3d_airlock.js, demos and lowering tools

Current capability boundaries

  • Usable milestones already reached: a working sa3d WebGPU sidecar, the first declarative Scene3D lowering path, and the first general WebGPU render submission surface.
  • Modules whose behavior is implemented and passes SA tests include 3d_time, 3d_input, 3d_color, 3d_geometry, 3d_scene, 3d_light, etc.; most other modules have only layout contracts.
  • Declarative scenes are currently limited to: one Scene3D, one PerspectiveCamera, one material kind, one CubeMesh; the general renderer only supports the P3N3UV2 vertex layout and ignores lighting records for now.

How to enable it

Once a SAX component declares renderer="sa3d", sa sax build automatically copies sa3d_airlock.js into the output directory. The aggregate plugin's CLI looks like:

sa 3d <info|skills|check|inspect-layout|airlock|new|check-demo> ...
sa 3d new my-scene        # 生成 app.sax + scene.sax3d 骨架

# 批量构建/验证（在 sa_plugin_3dengines 根目录）
node tools/build_all.mjs
node tools/verify_3d_modules.mjs
NoteEach module's tests have two layers: Zig descriptor tests + SA unit tests (sa test tests/*_layout_test.sa). The tests deliberately avoid browser/WebGPU calls and native f32 arithmetic, asserting floating-point fields with integer bit patterns. BEVY_PARITY_AUDIT.md explicitly cautions: passing zig build test only proves the ABI and the tests are self-consistent; it does not prove behavioral alignment with Bevy.
