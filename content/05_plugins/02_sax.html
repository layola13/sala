sax — SA UI Dialect Plugin

Zig 0.17This plugin is built with Zig 0.17: the 0.17 branch builds with Zig 0.17 and passes the Zig unit tests; the old 0.14.1 branch is kept unchanged.

sa_plugin_sax is SA's UI dialect plugin: it compiles a .sax component source file into an artifact package that a browser can open directly, producing real artifacts rather than placeholder stubs. This page only introduces what it can do and how to enable it; for component syntax and the UI development workflow, see the "SAX / MUI UI Development" chapter.

Basic facts

  • Capability segment: sax; version 0.1.0; no plugin dependencies.
  • Permissions: read/write/create in the project directory, environment variables HOME/PATH/SA_*, allowed to spawn /opt/zig/zig.
  • Commands: sa sax build <file> [--out-dir dir] (generate the artifact package), sa sax check <file> (parsing and trap checking), sa sax dev <file> [--out-dir dir], sa sax new <name> (create a new project).

Build artifacts

For an input such as demos/counter.sax, sa sax build generates:

  • app.wasm — the component logic (WASM);
  • airlock.js — the DOM bridge (the minimal glue between WASM and the DOM);
  • index.html — the entry page that loads the two above;
  • app.sa — the intermediate SA assembly.

The generated HTML carries a CSP that only allows WebAssembly to start, and DOM access is confined within the Airlock boundary; Airlock rejects <script>, innerHTML, and inline eval.

How to enable it

Under a local development checkout (run inside the sa_plugin_sax directory):

zig build test
SA_PLUGIN_DEV=1 SA_PLUGINS_PATH=$PWD/zig-out/lib/libsax.so \
  sa sax build demos/counter.sax --out-dir /tmp/sax-counter

If a component declares a browser sidecar renderer, the build also copies the corresponding broker into the output directory:

Renderer markerCopied file
renderer="wgpu" / sa_wgpu_ / WGPU_CUBE_wgpu_airlock.js
renderer="sa3d" / sa3d_ / SA3D_sa3d_airlock.js

SAX also accepts optional Sla event handlers (ordinary function syntax, compiled via sa_plugin_sla), and keeps the original SA label handler style:

fn inc() {
  count = count + 1;
  last = sax_get_time();
  render();
}

Components using Sla handlers release their state automatically in the destroy phase, with no need for an explicit !state_name line.

NoteFor browser smoke verification you can use the repository's bundled script: node tools/verify_sax_browser.mjs <dist> chromium (you can specify the browser and screenshot output with SAX_BROWSER_EXECUTABLE / SAX_BROWSER_SCREENSHOT).
