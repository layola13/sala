No &mut by Design: One Borrow Type, Referee-Judged Read/Write

SLA has no &mut. That is a deliberate design decision, not a missing feature: one borrow type, &T, covers both read and write, and the SA Referee judges Locked_Read / Locked_Mut from the actual load/store instructions behind the borrow. This page proves the claim with programs that were actually compiled and run — not with a design sketch. Toolchain: sa 0.1.9 + sa_plugin_sla 2b65a1dd, verified 2026-11-20. Demos: sa_plugin_sla/demos/mut_compare/ (01_borrow_read_write, 02_spawn_boundary). Code blocks below are excerpts from those demo files; the full files (with imports) are the verified artifacts.

The Same Program: Two Signatures in Rust, One in SLA

Take the textbook &mut example: one function reads a number, another adds 10 to it. Rust needs two borrow types; SLA needs one.

// Rust — read takes &i32, modify takes &mut i32
fn read(value: &i32) {
    println!("{}", value);
}

fn modify(value: &mut i32) {
    *value += 10;
}

fn main() {
    let mut number = 100;
    read(&number);
    modify(&mut number);
    println!("{}", number);
}
// output: 100, then 110
// SLA — read AND modify take &i32
fn read(value: &i32) -> void {
    println("{}", *value);
}

fn modify(value: &i32) -> void {
    *value += 10;
}

fn main() -> i32 {
    let number = 100;
    read(&number);
    modify(&number);
    println("{}", number);
    return 0;
}
// output: 100, then 110

Both programs print 100 then 110. The direct translation of the Rust &mut example needs no Cell / RefCell in SLA. Cell / RefCell are for genuinely shared interior state, not a toll-booth you must pass through to mutate through a borrow.

Why One Signature Is Enough

The permission is not declared; it is observed. After lowering, the Referee sees whether the borrowed view is only loaded from (Locked_Read) or also stored to (Locked_Mut). The signature therefore stays stable when an implementation changes from reading to writing, and no annotation has to be threaded through every caller. That stability is the design motive — one fewer prefix at every call site, and no signature churn for a body-local change.

A related form is worth recording because it used to fail for an unrelated reason: *value = *value + 10; (dereference plus a binary operator) was rejected before sa_plugin_sla 1d3b850c. The cause was the parser, not the checker: prefix *, &, ^ parsed their operand at precedence 6, so the binary operator folded into the operand and the expression parsed as *(value + 10). The fix parses prefix operands at precedence 8. The form is covered by demo 01 (modify_binop) and now checks, tests, and runs.

The Spawn Boundary: Borrows Do Not Cross Tasks

One borrow type does not mean borrows go everywhere. A borrow must not cross a task boundary — the borrowed place lives on the spawning task's stack, and the spawned task may outlive it. Both spawn forms reject this at check time:

// SLA — `go` form: rejected at check
fn modify(value: &i32) -> void {
    *value += 10;
}

fn main() -> i32 {
    let number = 100;
    let h = go modify(&number);
    number = 200;
    let st = sa_task_join(h);
    println("{}", number);
    return 0;
}
Type Check Error: failed to verify types: go: spawned function `modify`
takes a borrowed parameter, which would dangle across the goroutine boundary;
pass an owned value or a raw pointer instead (error.TypeMismatch)
// SLA — thread::spawn closure form: rejected at check (BorrowEscape)
fn modify(value: &i32) -> void {
    *value += 10;
}

fn main() -> i32 {
    let number = 100;
    let h = thread::spawn(^|| modify(&number));
    number = 200;
    let r = h.join().unwrap();
    println("{}", number);
    return 0;
}
Type Check Error: failed to verify types: thread::spawn: closure borrows
`number` from the enclosing scope, which would dangle or race across the
thread boundary; pass an owned value (such as an Arc clone) or a raw pointer
instead (error.BorrowEscape)

The closure form was a genuine hole until sa_plugin_sla 2b65a1dd: before that fix this file checked, built, and ran, printing 210 — the main task writing 200 while the spawned thread added 10 through the borrowed view, a live data race the checker silently allowed. The fix (DEF-SLA-SPAWN-CLOSURE-BORROW-ESCAPE) walks the spawned closure body and rejects borrows of enclosing-scope places, uses of outer bindings whose type contains a borrow, and assignments to outer places.

Rust refuses the same shape at compile time, with Send + 'static: a closure passed to thread::spawn may not capture a borrow of a stack place. The two languages agree on the rule; they differ only in where it is enforced — Rust in the type system, SLA in the spawn-boundary guard of the checker.

The Sanctioned Crossing: Ownership Transfer

What crosses a task boundary in SLA is an owned value, never a borrow. The standard shape is a channel handoff (demo 02): two channels, request and response, 50 ping-pong rounds. The worker owns both channel ends.

fn pp_worker(req: Chan<u64>, resp: Chan<u64>) {
    let i = 0;
    while i < 50 {
        let (v, closed) = req.recv();
        if closed { panic(9601); };
        resp.send(v + 1);
        i = i + 1;
    }
}

fn main() -> i32 {
    let req: Chan<u64> = Chan::new(0);
    let resp: Chan<u64> = Chan::new(0);
    let h = thread::spawn(^|| pp_worker(req, resp));
    let i = 0;
    let last: u64 = 0;
    while i < 50 {
        req.send(i as u64);
        let (r, closed) = resp.recv();
        if closed { panic(9602); };
        last = r;
        i = i + 1;
    }
    let jr = h.join();
    println("{}", last);
    req.destroy();
    resp.destroy();
    if last != 50 { return 1; };
    return 0;
}
// output: 50, exit code 0

Shared-state coordination is measured the same way, on the same toolchain. The Mutex, channel, and parallel-read rows produced exact results in every run; the RwLock mix is the exception — it usually produces 200 but intermittently ends in a runtime panic, so its result is reported below as a measured rate, not a stable exact value:

The Same Two Defects in the Rust Implementation

The two fixes above were not Zig-only. The Rust implementation of the SLA compiler (layola13/sla) was ported from the Zig one — including both bugs — and both were fixed there by the same shapes:

DefectZig pluginRust sla
Prefix */&/^ operands parsed at precedence 6, so *value = *value + 10 parsed as *(value + 10)1d3b850c (src/parser.zig, precedence 6 → 8)26b5137f (crates/sla-parser/src/prefix.rs, parse_expr(6) → parse_expr(8))
thread::spawn closure borrowing an enclosing-scope place was accepted2b65a1dd (src/type_checker.zig)b06c05ee (crates/sla-checker/src/check_spawn_guard.rs + hook in leaf_thread_spawn)

An early assumption that the dereference defect was a Zig-only checker bug was wrong: the Rust parser rejected the identical probe files with the identical diagnostic (TypeMismatch: operator requires matching operand types, actual borrow and i64), and the Rust candidate accepts them. The regression tests are byte-identical on both sides: corpus/tests/test_unit_deref_binop_operand.sla (3 @test), corpus/tests/test_error_spawn_closure_borrow_arg.sla, corpus/tests/test_error_spawn_closure_borrow_capture.sla.

Verified on the Rust binary built from sla main b06c05ee (box bd00ae7b9304, 2026-11-20; cargo build --release -p sla-cli, binary 6,923,920 B): demo 01 checks and tests green (test result: ok. 1 passed); the corpus dereference test passes 3/3; both spawn negatives reject with BorrowEscape — the direct capture as “closure borrows `number` from the enclosing scope”, the indirect capture as “closure captures borrowed value `r` from the enclosing scope” — and the go negative rejects too, under a differently worded diagnostic (GoBorrowPayload: spawn argument carries a borrow across the goroutine boundary). Demo 02 and the p3/p4/p5 probes check green on the Rust side as well.

A second go gate rejects struct-by-value spawn arguments outright (GoNonWordParam): the spawned entry receives exactly one word, so a spawned function's single parameter must be a pointer or word-sized scalar — primitives, pointers, fn-pointers, and Chan pass; structs (even word-sized ones), tuples, arrays, String, and Vec do not. Box larger values and pass the pointer (Box::new + Box::into_raw, as in corpus/tests/diagnostics/go_diag_borrow_payload.sla). This mirrors the Zig checker's goParamIsWordOrPtr gate, so the two implementations agree on the shape.

One asymmetry with Rust-the-language is worth recording. In Rust, the inline form thread::spawn(move || modify(&mut number)) compiles: closure-capture precision lets the closure capture a copy of the i32, and the +10 is lost — the compiled binary prints 200, not 210. The true Rust parallel of SLA's rejection pre-binds the borrow first (let r = &mut number; thread::spawn(move || modify(r))), which rustc 1.100.0 refuses with E0597 (number does not live long enough: the spawn argument requires a 'static borrow) and E0506 (cannot assign to number because it is borrowed). SLA rejects the inline form outright, with no capture-precision escape hatch.

await still parses its operand at precedence 6 in both implementations — deliberately untouched by either fix; it needs its own ruling.

What Stays Phase 2

Nothing on this page changes the phased plan in Ownership and Borrowing: Referee vs the Borrow Checker. The one case that still needs &mut is a static read/write set: an ECS parallel scheduler must know, before running, whether move_sys writes Pos while render_sys reads it. That is an engineering trigger for Phase 2, not a gap in the programs above — every case on this page is already decided correctly by the Referee at run time.

WarningThe easiest pitfall when migrating from Rust is treating &T as read-only: under SLA's current convention it covers both read and write, and you cannot tell from the signature whether a method will change state. This gap of “signatures do not express mutability” will only close after Phase 2 introduces &mut self.

Key Points of This Page

  • SLA has no &mut by design: &T covers read and write, and the SA Referee judges Locked_Read / Locked_Mut from the actual instructions.
  • The direct translation of a Rust &mut example needs no Cell / RefCell; signatures stay stable when an implementation starts writing.
  • *value = *value + 10 is accepted since the parser fix in sa_plugin_sla 1d3b850c.
  • Borrows do not cross task boundaries: the go form and the thread::spawn closure form are both rejected at check time; the closure form was a genuine hole until 2b65a1dd.
  • Values cross tasks by ownership transfer (channels) or by Arc + locks — measured exact: channel handoff 50 rounds, Mutex counter 1000, parallel reads 1000000 each; RwLock mix 200 in 22 of 28 runs (6 runs panic, code 17).
  • Phase 2 &mut is still reserved for the ECS scheduler's static read/write sets; see the ownership page.
  • Both defects existed in the Rust implementation too (the parser/checker were ported from Zig including the bugs) and were fixed there by the same shapes (26b5137f, b06c05ee); the demos verify green on both binaries.
