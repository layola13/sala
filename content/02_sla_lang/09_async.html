async/await 现状

SLA 已有 async fn/.await 语法与配套的 sa_std future 契约。 当前编译器已经为单次 await、连续两次 await、join2 以及若干动态 Pending/Ready 形态生成真实状态机；但这不是“所有 async 代码都已经有通用 runtime”。 本页记录可验证的 lowering 范围、手动驱动方式和仍未完成的边界。

源码快照（2026-09-03） 权威实现位于 sa_plugin_sla，不是本帮助站点本身： src/codegen.zig 按 join2 → two-await → single-await → dynamic planner 选择专用构造器；sa_std/core/future.sal 定义 FutureState 的动态 vtable 位于偏移 +48，动态状态必须通过 FUTURE_POLL_STATE 分发。不要把动态 outer future 交给只读取内联 ready 布局的 FUTURE_READY_POLL_STATE。

基本写法

async fn 声明异步函数；调用它得到一个 future 值，用后缀 .await 取结果。 future 的类型写作 future<T> （demos/rosetta/314_async_await_pending_resume/main.sla）：

@import "sa_std/future.sa"
@import "sa_std/core/waker.sa"
@import "sa_std/pin.sa"
@import "sa_std/core/box.sa"

async fn step_value(x: i32) -> i32 {
    let v = future::defer_ready(x).await;
    return v * 2;
}

async fn run() -> i32 {
    let first = step_value(10).await;
    let second = step_value(first + 1).await;
    return second;
}

Pending / Ready 与手动 block_on

future::defer_ready(v) 第一次 poll 返回 Pending，第二次返回 Ready(v)——这会让 async 状态机真正挂起并在重新 poll 时恢复。标准库没有内置 block_on 时，demo 使用轮询 + waker 的手写驱动：

fn block_on(future: future<i32>) -> i32 {
    let data: ptr = PTR_NULL();
    let raw = RAW_WAKER_NEW(data, data);
    let waker = WAKER_FROM_RAW(raw);
    let context = CONTEXT_FROM_WAKER(waker);
    let boxed = Box::new(future);
    let future_ref = *boxed;
    let pinned = stack_alloc();
    PIN_MUT_NEW(pinned, future_ref);

    while unix_now_ns() < deadline {
        let poll = FUTURE_POLL_STATE(PIN_MUT_GET_MUT(pinned), context);
        let ready = POLL_IS_READY(poll);
        if ready == true {
            let value: i32 = POLL_VALUE(poll);
            return value;
        };
        THREAD_SLEEP_MS(1);
    }
    panic(314);
}

跨线程的任务池

async 调用产生的 future 可以移动进线程闭包，由工作线程自行驱动； 结果通过 Arc<Mutex<i32>> 回传 （demos/rosetta/315_async_thread_pool/main.sla）：

@import "sa_std/sync/mutex.sa"
@import "sa_std/core/arc.sa"
@import "sa_std/thread.sa"

fn get_cell(c: Arc<Mutex<i32> >) -> i32 {
    let g = (*c).lock().unwrap();
    return *g;
}

fn pool_worker(f: future<i32>, out: Arc<Mutex<i32> >) {
    let r = block_on(f);
    let g = (*out).lock().unwrap();
    *g = r;
}

while let + await 组合

任务队列的常见形态（demos/rosetta/136_executor_task_queue/main.sla）：

let queue = vec(task_one(), task_two(), task_three());
let total = 0;

while let Some(task) = queue.pop() {
    let resolved = task.await;
    total = total + resolved;
}

成熟度与建议

  • async/await 已部分进入 direct-SAB 快路径，但覆盖是专用 lowering，不是任意 async 函数的通用 CPS/state-machine。当前已验证的重点是单 await、两次 await、join2、 局部 Future 重新赋值和 Pending/Ready 恢复；
  • 当前源码记录中，35 个 test_unit_async*.sla 通过 native SA， SLA→SA→VM 矩阵也是 35/35；strict direct SAB 为 34/35，线程池用例仍受 stack_alloc + PIN_MUT_NEW + FUTURE_POLL_STATE 组合限制。这个数字是 2026-09-03 的验证快照，发布前应重新运行；
  • 三次或更多连续 await 尚无通用 continuation lowering：尚未统一保存每个 stage、 pending inner future、跨阶段局部值和 cleanup。不能据此宣称“高级 async/await 已完成”；
  • sa_std/core/task.sa 的 executor 是任务数组上的轮询循环； run_until_complete 没有 Tokio 级 reactor、调度公平性、背压或结构化并发。 线程池示例是真实 OS 线程 + Arc<Mutex>，但仍由手写 block_on 和 sleep 驱动；
  • demo 009 的简化 block_on 在 future 未立即就绪时会 panic；需要真挂起请参考 demo 314 的轮询写法；
  • 不要假设 rosetta 树中的 async demo 全部端到端通过，按需单独验证： SA_PLUGIN_DEV=1 sa sla test demos/rosetta/314_async_await_pending_resume/main.sla。
注意编译器内部使用 continuation/state-machine lowering，但 SLA 不提供 Rust 式 Pin/Unpin 用户面语义；demo 中出现的 PIN_MUT_* 来自 sa_std 契约，不是语言关键字。HTTP client 的 async ABI 目前是句柄 + poll/cancel 的插件接口，不能等同于统一的 SLA Future executor。
