Extension Mechanisms

This page introduces the four means by which SLA extends a type's capabilities without introducing a heavy trait system: the restricted @overload operator overload block, using static extensions, the hygienic macro macro and the @expand_tuple arity template, and @derive(...) derivation. After reading this page, you can add arithmetic operations, comparison, and chained calls to a custom struct.

@overload: the restricted operator overload block

@overload 类型 { ... } declares operator implementations for a specified type. It is currently limited to the four arithmetic operators + - * /, is entirely rewritten in the frontend into static function calls, and introduces no runtime dispatch; a bare-written overload is not a legal entry point (demos/rosetta/312_operator_overload_block/main.sla):

struct Vec2 {
    x: i32,
    y: i32,
}

@overload Vec2 {
    fn +(self: Vec2, other: Vec2) -> Vec2 {
        return Vec2 { x: self.x + other.x, y: self.y + other.y };
    }
}

let a = Vec2 { x: 4, y: 6 };
let b = Vec2 { x: 1, y: 3 };
let c = a + b;   // (5, 9)
NoteWhether comparisons such as a == b go through overloading is still decided by the current whitelist constraints; they are not automatically opened within the @overload mechanism.

using static extensions

See the Modules and @import page. Key point: after using 模块名;, the pub fns in that module whose first parameter type matches can be called as methods in chained form:

using score_math;
let score = base.add_bonus(5).double();

macro: hygienic macros

macro 名称(参数) { ... } defines a macro expanded at compile time. SLA guarantees that local identifiers inside a macro body do not conflict with the outside (alpha renaming is done internally), and underneath it maps 1:1 to SA's [MACRO]/EXPAND structure. The following is from tests/test_edge_cases.sla:

macro add_one_macro(var_ref) {
    let temp = 1;
    var_ref = var_ref + temp;
}

fn test_macro_hygiene(val: int) -> int {
    let temp = val;
    add_one_macro(temp);   // 宏内的 temp 不会污染外层 temp
    return temp;
}

Macros can be imported across files for use (imported macros go through the shared lowering path) and can be defined nested; a duplicate declaration of the same name yields a redeclaration error (see tests/test_error_redeclaration_macro.sla).

NoteMacro expansion is textual replacement and must be aware of the caller variables' stack homing: if an actual argument is a function parameter or a let variable, after lowering it may be a stack slot address rather than a value. When the macro body uses a parameter in a value context it must explicitly load the value; in an address context (such as an OUT parameter passed to an extern) it uses the parameter itself to represent the slot address, without wrapping another temporary around it to take the address. For the semantic details, see Ownership: Address-of and Stack Homing.

@expand_tuple: the fixed-arity template

Used to batch-generate same-shaped tuple/arity declarations, avoiding hand-written AnyOf5/AnyOf6-style expansions. Available placeholders: $N (ordinal), $I (index), $T (current type), $TYPES/$TYPE_PARAMS, $ORD (mapped to field names such as first/second/third), and the iteration directive @each(T) { ... } and the join directive @join(T, ", ") { ... }. This is not Rust's macro_rules! or proc-macros (tests/test_unit_expand_tuple_macro.sla):

@expand_tuple(2, 4, T) {
fn tuple_sum$N(@join(T, ", ") { value_$I: i64 }) -> i64 {
    let sum = 0;
@each(T) {
    sum = sum + value_$I;
}
    return sum;
}
}

// 展开后可直接调用：
if tuple_sum2(10, 20) != 30 { panic(18001); };
if tuple_sum4(1, 2, 3, 4) != 10 { panic(18003); };
@expand_tuple(2, 3, T) {
struct OrdinalCarrier$N<@join(T, ", ") { $T}> {
@each(T) {
    $ORD: $T,
}
}
}
// 得到 OrdinalCarrier3 { first, second, third }

@derive: capability derivation

@derive(...) is attached to a struct and lets the compiler generate implementations such as comparison/copying. Spellings visible in real source:

@derive(ord)                    // syntax_sugar/spaceship_cmp：生成 <=> 支持
struct SortKey {
    group: i64,
    order: i64,
}
deriveEffectSource
ordSupports <=> returning an Ordering, chainable with .then(...)syntax_sugar demos
copy / eq / hash / debugThe corresponding capability derivationsThe combined spelling @derive(copy, eq, ord, hash, debug) visible in tests
PartialEqField-by-field equality comparisonVisible in tests
NoteThe full whitelist planned in the design documents (Add/Sub/Mul/Neg/MulScalar/Eq/Hash/PartialOrd/Ord and the ECS-related Component/Bundle/Resource/Event) is landing in stages; derive semantics are still not fully covered on some backend paths; see the Feature Maturity Matrix page for details.
