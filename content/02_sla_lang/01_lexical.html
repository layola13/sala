Lexical Structure and Basic Syntax

This page introduces the lexical rules of SLA source files (.sla): comments, keywords, literals, attributes, and how statements are organized. After reading this page, you can read the overall skeleton of a typical SLA file and know which tokens the language reserves.

Source file structure

An .sla file usually begins with several @import lines, followed by top-level declarations (struct/enum/fn/mod/impl, etc.), and may end with @test test blocks. The skeleton below is taken from demos/rosetta/01_hello_world/main.sla:

@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"
@import "sa_std/string.sa"

fn main() -> i32 {
    println("hello, saasm");
    return 0;
};

@test "rosetta 001 01_hello_world"() {
    if str_eq("hello, saasm", "hello, saasm") != true {
        panic(1);
    };
};

Comments

SLA uses line comments, the same as Rust/C:

// 这是行注释，到行尾结束

Keywords

SLA deliberately keeps an extremely small keyword set. The table below lists all reserved words recognized by the current lexer (checkKeyword in src/lexer.zig):

GroupKeywords
Types and declarationsstruct, union, enum, trait, impl, type, fn, macro, overload, mod, pub, extern, using, inline, unsafe
Control flowif, else, match, switch, return, for, in, while, break, continue
Binding and conversionlet, const, var, mut, as, dyn, async, await
Notemut is reserved by the lexer, but per the current design decision (Phase 1), &mut T/&mut self have not yet been introduced, and the let mut x spelling will never be introduced. See the Ownership and Lifetimes page for details.

Attributes (starting with @)

SLA's compile-time directives uniformly start with @ and appear before a declaration or block:

AttributePurpose
@import "...";Import a contract or an SLA source file; see the Modules and @import page for details
@test "名称"() { ... }Define a test block, run via sa sla test
@derive(...)Derive capabilities for a type, e.g. @derive(ord) (syntax_sugar/spaceship_cmp)
@overload 类型 { ... }An operator overload block, limited to + - * /
@expand_tuple(min, max, T) { ... }Template expansion for tuples/arity over a fixed range

Expressions and semicolons

SLA is an expression-oriented language: if/else and match can be returned as values, e.g. fn max(a: i32, b: i32) -> i32 { if a > b { a } else { b } } (demo 03_if_else). An if block used as a statement must carry a trailing semicolon (if ... {};; omitting it is a parse error); for/while blocks must not be followed by a semicolon (adding one is likewise a parse error). Both if spellings exist in the codebase (no semicolon in expression position, a semicolon in statement position); just compare with the use cases in the tree.
