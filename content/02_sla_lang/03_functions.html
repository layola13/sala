函数与控制流

这一页说明 fn 的写法、方法与关联函数、闭包，以及 if/else、 while、for in、break/continue 和 ? 错误传播。 读完这一页，你能写出结构完整、能通过 sa sla check 的 SLA 函数。

函数声明

函数用 fn 声明，参数带类型标注，返回值跟在 -> 之后。 默认绑定是可变的；const 用于不可变绑定。可见性用 pub 标注 （demos/rosetta/42_export_visibility/main.sla）：

pub fn exported_value() -> i32 {
    7
}

fn internal_value() -> i32 {
    5
}

方法、self 与 impl 块

impl 类型 { ... } 内的方法第一个参数写作 self 或 &self， 调用走方法语法（UFCS 静态展开）。以下取自 demos/rosetta/40_impl_block_state/main.sla 和 demo 311：

impl Account {
    fn deposit(self, amount: i32) -> Account {
        return Account { balance: self.balance + amount };
    }
}

// 调用
let updated = account.deposit(5);

impl Meter {
    fn double(self) -> i32 { return self.value.double(); }
}

闭包

闭包字面量写作 |参数| 表达式，可捕获外层局部值 （demos/rosetta/08_closures/main.sla）：

let offset = 5;
let add_offset = |x: i32| x + offset;
let result = add_offset(10);   // 15

if / else 表达式

if/else 产生值，可直接作为函数体尾表达式或用于字段初始化 （demo 03_if_else 与 45_config_merge）：

fn max(a: i32, b: i32) -> i32 {
    if a > b { a } else { b }
}

Config {
    threads: if override_cfg.threads == 0 { base.threads } else { override_cfg.threads },
    level: if override_cfg.level == 0 { base.level } else { override_cfg.level },
}

循环：while / for in / break / continue

while cond { ... } 是基础循环；break/continue 可用于提前退出或跳过。 数值区间循环 for i in start..end 直接支持；对集合的 for x in collection 迭代在部分路径仍会回退（见「特性成熟度总表」）。真实示例：

// demos/rosetta/103_labeled_break/main.sla（while + break）
while done == false {
    inner = inner + 1;
    if inner >= 3 { break; };
}

// rosetta 各 demo 中常见的区间循环
for i in 0..4 {
    total = total + i;
}

? 错误传播

? 作用于返回 Result<T, E> 的调用：出错则提取错误并提前返回， 成功则解出 T 继续（demos/rosetta/309_try_block_macro/main.sla）：

@import "sa_std/core/result.sa"

fn parse_num(value: i32) -> Result<i32, i32> {
    Ok(value)
}

fn compute() -> Result<i32, i32> {
    let a = parse_num(10)?;
    let b = parse_num(20)?;
    Ok(a + b)
}
注意panic(code) 用于立即失败并携带整数诊断码， 是所有 @test demo 的统一断言手段。

程序入口：main 契约

可执行程序的入口是名为 main 的普通函数：检查器对 main 的签名不作任何特判，契约由宿主层执行——宿主只为「kind 为普通函数、名为 main、0 参数」的函数生成 C 入口包装。带参数的 main 不生成包装，即没有入口（且当前无诊断；检查器响亮拒绝列为批三候选）。语料惯例一边倒：tests 与 demos 中的 fn main 全部是 fn main() -> i32。

  • 返回与退出码：编译路——入口包装零参调用 main，返回值强转 i32 作进程退出码；void 返回补 0；fallible 返回取其 status 字段。解释路——退出码为 main 返回值截断 u8（fallible 同样取 status 截断），另有保留码：程序自设退出（UserExit）、除零 100、调用栈溢出 108。
  • argv 不经形参：包装把宿主的 argc / argv 存入全局，程序内经 SA 层 sys_argc / sys_argv 读取，或经 std env 域 @extern sa_env_args_json() 取得 JSON 句柄。wasm_compat 时入口名改为 __main_argc_argv（WASI 契约）。
  • main 必须同步：宿主层不存在 async 入口这一形态。写 async fn main 当前不会被检查器拒绝，但其 future 返回会被入口包装按普通返回值处理、永不被驱动——程序静默失效而非响亮报错（此失效形态系代码路径推定，未做探针实证）。惯例是 main 为同步函数，异步工作在 main 内以 std 的 block_on 形态驱动（sa_std/async.sla 的轮询驱动）。检查器对 async main 的响亮拒绝同列批三候选。
