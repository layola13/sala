模块与 @import

这一页介绍 SLA 的代码组织单元：mod 模块、pub 可见性、 @import 对 SLA 源文件与 SA 契约（.sai/.sal/.sa）的导入， 以及 using 静态扩展。读完这一页，你能把代码拆成多文件并正确引用 sa_std。

mod 与 pub

mod 名称 { ... } 在文件内定义命名空间，成员用 :: 路径访问； 只有标注 pub 的项对外可见 （demos/rosetta/41_module_imports/main.sla）：

mod math {
    pub fn double(x: i32) -> i32 {
        x * 2
    }
}

let value = math::double(21);   // 42

@import 的三种目标

目标示例（真实源码）说明
SA 契约 .sai@import "sa_std/io/print.sai"读取 extern 函数签名，注册为强类型函数
布局契约 .sal@import "sa_std/rc.sal"读取外部结构体布局偏移，保证 ABI 兼容
SLA / SA 源文件@import "score_math.sla"、@import "sa_std/string.sa"引入其中定义的模块、函数与宏

多文件项目的真实写法（demos/syntax_sugar/combined/main.sla 及其配套文件 score_math.sla）：

@import "sla_std/cmp.sla"
@import "../using_module_import/score_math.sla"

@import "score_math.sla"   // using_module_import/main.sla 中使用相对路径

// score_math.sla 内容：
mod score_math {
    pub fn add_bonus(value: i32, bonus: i32) -> i32 {
        return value + bonus;
    }
}
注意SLA 直接复用 sa_std 的契约文件， 前端内置了 .sai/.sal 解析器，因此类型和 ABI 与底层验证器共享同一份数据源， 不会出现双重声明漂移。带标准契约的第三方插件可一行 @import 即可强类型调用。

sa_std 的解析位置

sa_std/... 形式的路径默认从环境变量 SA_STD_DIR（已设置时）解析， 否则回退到本机约定的 sci/sa_std 目录。编译器在类型检查之前加载全部导入契约， 因此 extern 函数对 SLA 代码直接可用。

using：静态扩展

using 模块名; 把该模块中可见函数注册为静态扩展方法： 第一个参数类型匹配的值即可链式调用这些函数。这是纯前端的调用改写，不引入运行时分发 （demos/syntax_sugar/using_module/main.sla）：

mod score_math {
    pub fn add_bonus(value: i32, bonus: i32) -> i32 {
        return value + bonus;
    }
    pub fn double(value: i32) -> i32 {
        return value + value;
    }
}

using score_math;

@test "using module turns functions into chainable calls"() {
    let base: i32 = 10;
    let score = base.add_bonus(5).double();   // 30
    if score != 30 { panic(34000); };
}

using 也作用于通过 @import 引入的模块 （demos/syntax_sugar/using_module_import/main.sla），并可与 impl 方法叠加使用：

using math;

impl Meter {
    fn double(self) -> i32 {
        return self.value.double();   // 调到 using 进来的扩展
    }
}
警告模块级 method-style 调用必须显式声明 using；没有 using 时，对非 impl 方法的链式调用会在前端报“未找到方法”。
