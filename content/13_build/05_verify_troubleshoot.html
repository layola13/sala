构建验证与故障排查

推荐验证顺序

# 运行目录：sci 仓库根目录
zig build                          # 1. 默认全构建（含 LLVM 后端，需 llvm-14-dev）
zig build core -Dllvm=false        # 2. 跨平台核心检查（快）
zig build sa-std-unit              # 3. 标准运行时单元测试（含 FreeBSD 解析器用例）
zig build test                     # 4. 完整门禁（慢，10 分钟以上；见下）
# 交叉目标逐个验证（见矩阵总览与各章节）：
zig build -Dtarget=x86_64-windows-gnu -Dllvm=false -p /tmp/sa-win
zig build -Dtarget=aarch64-linux-gnu -Dllvm=false -p /tmp/sa-arm
zig build -Dtarget=aarch64-macos -Dllvm=false -p /tmp/sa-mac
sh tools/build_freebsd.sh --prefix /tmp/sa-fbsd

已知现象（非代码问题）

现象原因处理
wasm-matrix / 部分 plugin-host-smoke 报 LLVM-C backend is disabled构建时传了 -Dllvm=false，相关测试需要 LLVM 后端安装 llvm-14-dev 后用默认开关重跑
sa_std dynamic loading helpers are usable from C 报 FileNotFound (zig-out/lib)之前用 -p 把产物装到了别处，默认 zig-out/lib 缺失跑一次默认 zig build 再测
stdlib.h / dlfcn.h file not found（freebsd 目标）缺少 FreeBSD sysroot（Zig 不自带 freebsd libc）走 FreeBSD 章节 的脚本/手动流程
unable to find or provide libc for target 'x86_64-freebsd…'只传了 -Dsysroot，缺 -Dlibc 描述文件按脚本生成 freebsd-libc.txt 并传入
undefined symbol: _c_recvmsg（macOS dylib 链接）旧代码，已修复：extern 名必须与 libc 真实符号一致更新 main 到含该修复的版本
std.net.if_nametoindex unimplemented for this OS（freebsd）旧代码，已修复：见 FreeBSD 兼容层更新 main 到含该修复的版本
裸 zig test src/runtime/sa_std.zig 报 posix @bitCast size mismatch裸测没链 libc，走进 std 的非 libc 路径；项目正规入口是 zig build sa-std-unit（带 link_libc）用 zig build sa-std-unit 代替

构建副作用

zig build 会把编出的库同步回源码树 artifacts/sa_std/libsa_std.a（git 跟踪文件）。仅做本地验证时， 结束用 git checkout -- artifacts/sa_std/libsa_std.a 还原， 保持工作树干净。
