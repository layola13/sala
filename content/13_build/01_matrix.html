多平台编译矩阵总览

sci（SA 编译器）用 Zig 构建系统编译，build.zig.zon 要求 Zig 0.14.1。下表是已验证可通过的全部目标（stock Zig 0.14.1， Linux x86_64 主机；main 分支已包含 cross-platform 分支的全部多平台运行时）：

目标Triple命令产物
Linux x86_64（原生）x86_64-linux-gnu（默认）zig build（需 LLVM 14，见本地构建）zig-out/bin/sa（约 20M）、libsa_std.a/.so
Windows x86_64x86_64-windows-gnuzig build -Dtarget=x86_64-windows-gnu -Dllvm=falsesa.exe（约 11M）、hubproxy.exe
ARM Linuxaarch64-linux-gnuzig build -Dtarget=aarch64-linux-gnu -Dllvm=falseARM aarch64 ELF（file 可验证）
macOS ARMaarch64-macoszig build -Dtarget=aarch64-macos -Dllvm=falseMach-O arm64 sa + libsa_std.dylib
macOS Intelx86_64-macoszig build -Dtarget=x86_64-macos -Dllvm=false同上，x86_64 Mach-O
FreeBSD x86_64x86_64-freebsdsh tools/build_freebsd.sh（需 sysroot，见FreeBSD 章节）FreeBSD 14.4 ELF（interpreter /libexec/ld-elf.so.1）

通用说明：

  • -Dllvm=false 关闭 LLVM-C 后端（交叉目标默认只能如此；Windows 原生除外， Linux 原生默认开启）。关闭后 llvmc 相关测试会跳过/失败，属预期行为。
  • -p <目录> 可把安装前缀从默认 zig-out/ 改到别处； 注意 sa-std-runtime 测试要求默认 zig-out/lib 存在， 用 -p 构建后跑该测试会报 FileNotFound，先跑一次默认 zig build 即可恢复。
  • 构建会同步产物到源码树 artifacts/sa_std/libsa_std.a（git 跟踪文件）； 若只是本地验证，构建完用 git checkout -- artifacts/sa_std/libsa_std.a 还原， 避免把本地构建产物混入提交。
注意交叉编译只证明“编译 + 链接”通过。 各目标的行为正确性仍需在真机（或 QEMU / Wine 等）上跑对应测试套件确认。
