Variables, Functions, and Structs: Your First SLA Program

This chapter is the guided first pass for Rust programmers. It teaches one feature at a time, in the order you would meet them writing your first programs, and it follows a strict rule: every SLA code block in this chapter was actually compiled and run before it was written down (toolchain: sa 0.1.9 + the installed SLA plugin, verified 2026-11-20). The output quoted under each program is the output the program really printed. Where a familiar Rust form does not carry over, the page says so and shows the real diagnostic instead of inventing a workaround. For the measured, reference-style comparison — syntax matrices, censuses, performance numbers — see the Comparison with Rust section; this chapter is the tutorial companion to it.

Variables: let Is Mutable by Default

The first surprise for a Rust programmer: an SLA let binding can be reassigned without any mut keyword. Mutability is the default; const is the immutable form.

// Rust
fn main() {
    let x = 10;
    let mut y = 20;
    y += 5;
    println!("{} {}", x, y);
}
// output: 10 25
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn main() -> i32 {
    let x = 10;
    let y = 20;
    y += 5;
    println("{} {}", x, y);
    return 0;
}

Verified output: 10 25, exit code 0. Writing let mut in SLA is not just unnecessary — the parser rejects it, loudly and on purpose (see the syntax comparison matrix). Delete mut when you port code; do not look for a replacement keyword.

Functions

Function signatures read exactly as in Rust: typed parameters, an arrow, a return type, and an explicit return. One difference at the entry point: SLA main returns i32, and that value becomes the process exit code.

// Rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    let result = add(10, 20);
    println!("{}", result);
}
// output: 30
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

fn main() -> i32 {
    let result = add(10, 20);
    println("{}", result);
    return 0;
}

Verified output: 30, exit code 0.

Structs

Struct declarations and struct literals keep the Rust shape: field names, types, and Type { field: value } construction.

// Rust
struct User {
    id: u64,
    age: u32,
}

fn main() {
    let user = User { id: 100, age: 20 };
    println!("{}", user.age);
}
// output: 20
@import "sa_std/io/print.sai"
@import "sa_std/fmt.sai"

struct User {
    id: u64,
    age: u32,
}

fn main() -> i32 {
    let user = User { id: 100, age: 20 };
    println("{}", user.age);
    return 0;
}

Verified output: 20, exit code 0.

Strings: Build Them with format(...)

One form to unlearn early: String::from("...") is not the SLA form — it was tested and does not work. The verified way to build a String is format("..."), which appears throughout this chapter, for example format("Alice") on the next page and format("division by zero") in the error-handling page. Think of format as doing the job of both String::from and format! for the cases shown here.

Key Points of This Page

  • SLA let is mutable by default; let mut is rejected by the parser. const is the immutable binding.
  • Function signatures, explicit return, and struct literals read as in Rust; main returns i32 as the exit code.
  • Build a String with format("..."), not String::from(...).
  • Every SLA program in this chapter was compiled and run on sa 0.1.9 before being quoted; outputs are measured, not illustrative.
