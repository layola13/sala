资源限制与退出码

本页逐字摘录 src/sandbox.zig 的所有默认值与 src/plugin.zig 的退出码映射， 并列出策略（sa.vm.policy/1）和环境变量回退顺序。读完本节可以在不读源码的前提下，准确预测 任何 sa vm ... 调用在边界条件下的退出码与 stderr 输出。

资源限制项与默认值

以下字段在 src/sandbox.zig::Limits 中定义。除 max_call_depth / stack_headroom_bytes 之外， 所有字段默认值都是 null 或 0，即"无上限"——dev 路径不带任何 flag 时 vm 与未加固模式无差别。

字段类型默认值CLI flagenv 回退policy.limits 段
fuel?u64null（无计费）--fuel=NSA_VM_FUEL=N"fuel": N
wall_clock_ms?u64null（无限时）--deadline-ms=NSA_VM_DEADLINE_MS=N"wall_clock_ms": N
mem_cap_bytes?u64null（不限内存）--mem-cap-bytes=NSA_VM_MEM_CAP_BYTES=N"mem_cap_bytes": N
max_call_depthu32100_000（default_max_call_depth）--max-call-depth=N——
stack_headroom_bytesusize256 * 1024（default_stack_headroom_bytes）———
注意max_call_depth 与 stack_headroom_bytes 没有 CLI/env 开关，但即使不设任何 cap，递归失控也不会硬崩： vm 会优先撞到 TEB 栈守页（Windows）或 host stack，触发 E_STACK_OVERFLOW panic 退出 235， 而不是 0xC0000005 abort。

Fuel 计费公式

逐字摘自 src/sandbox.zig::blockCost：

cost = body_words * 1 + slow_words * 15 + call_words * 31 + terminator(1)
fast-arm 固定 = 4
空块也至少 = 1（否则 while(true){} 是免费的）

对应常量为：

常量值
block_cost_base1
block_cost_slow_op15
block_cost_call31
block_cost_fast_arm4
clock_check_interval_blocks1024

挂钟检查是惰性的：每 1024 个计费块采样一次；FFI / pthread / builtin / broker 调用边界强制采样。 一个阻塞的系统调用（卡在 native FFI 里）无法被中途中断。

优先级与回退顺序

src/plugin.zig::applySandboxEnvFallbacks 与随后的 if (sandbox_options.xxx) |v| limits.xxx = v; 实现以下优先级：

  1. CLI 显式 flag 永远赢（且不报冲突，effective 值会回显在 start 事件中）。
  2. env 回退：SA_VM_FUEL / SA_VM_DEADLINE_MS / SA_VM_MEM_CAP_BYTES / SA_VM_POLICY（注意 SA_VM_POLICY 是回退到 --policy，不是回退到 cap）。
  3. 策略文件的 limits 段：解析后把 fuel / wall_clock_ms / mem_cap_bytes 三个非空字段填入 Limits。
  4. 否则关闭。

对应源码骨架：

if (parsed_policy) |*policy| {
    if (policy.limits.fuel != null)         limits.fuel          = policy.limits.fuel;
    if (policy.limits.wall_clock_ms != null) limits.wall_clock_ms = policy.limits.wall_clock_ms;
    if (policy.limits.mem_cap_bytes orelse 0 != 0) limits.mem_cap_bytes = policy.limits.mem_cap_bytes;
}
if (sandbox_options.fuel)         |v| limits.fuel          = v;
if (sandbox_options.deadline_ms)  |v| limits.wall_clock_ms = v;
if (sandbox_options.mem_cap_bytes) |v| limits.mem_cap_bytes = if (v == 0) null else v;
if (sandbox_options.max_call_depth) |v| limits.max_call_depth = v;

内存配额（QuotaAllocator）

src/sandbox.zig::QuotaAllocator 包住 std.heap.c_allocator，在 alloc / resize / remap 前做 live_bytes + additional <= cap 校验；超限返回 null / false，被 vm 翻译为 E_MEM_QUOTA panic（.alloc / stack_alloc 指令 + 帧分配两个 catch 点）。 注意：解析 arena 不走 quota，quota 只覆盖执行期的 exec_allocator。

跟踪指标（--stats 不直接暴露，但 violation 事件里的 mem_peak_bytes 是它）：

  • live_bytes：当前在用字节。
  • peak_bytes：本进程 VM 期内最大瞬时值。

退出码与 panic code 映射

src/sandbox.zig 顶端定义所有保留码（code_* 常量），src/plugin.zig 始终以 128 + code 计算进程退出码（code & 0x7f 用于 panic，但保留码都 < 128，所以"+"与"+&0x7f"等价）。

code名称退出码触发条件
100E_CAPABILITY_DENIED228策略拒绝（fs / http / env / process / extern.allow / ffi / threads / net_raw 任一）
101E_FUEL_EXHAUSTED229block-cost 累计超出 --fuel（或 policy.limits.fuel）
102E_TIMEOUT230挂钟超出 --deadline-ms（每 1024 块 + FFI/builtin 边界采样）
103E_MEM_QUOTA231执行分配器 QuotaAllocator 拒绝 alloc / resize / remap
104E_VERIFY_FAILED232（reserved）当前未触发，保留位
105E_POLICY_INVALID233--policy JSON 不通过 schema 校验（含未知键、非绝对路径 fs pattern 等，fail closed）
106E_SANDBOX_MISCONFIG234（reserved）--sandboxed 与 --policy / --allow-ffi 同时使用
107E_STACK_OVERFLOW235guest 递归超 max_call_depth 或 host stack headroom 不足（256 KiB）

所有 code_* 常量命名可通过 sandbox_mod.nameForCode 取人类可读字符串 （E_FUEL_EXHAUSTED、E_TIMEOUT 等），便于写入事件。

事件协议：sa-vm-event

每次启动只要配置了任何 cap 或 policy，vm 会先写一行 start 事件：

sa-vm-event: {"v":1,"event":"start","fuel":N|null,"wall_clock_ms":N|null,"mem_cap_bytes":N|null,"max_call_depth":N,"stack_headroom_bytes":N}

每个 cap 违规写一行 violation 事件：

sa-vm-event: {"v":1,"event":"violation","code":N,"name":"E_...","detail":"...","fuel_used":N,"wall_ms":N,"mem_peak_bytes":N}

事件是单行 JSON 以 \n 结尾，可用 grep '^sa-vm-event:' 抓取。 schema version 字段 "v":1 用于未来扩展兼容。

策略 schema：sa.vm.policy/1

传给 --policy=foo.json 的文件必须以 "schema": "sa.vm.policy/1" 起头。 以下字段会被读取，未知键会让解析失败（fail closed）以免误用旧策略：

键子键作用
schema—必须为 "sa.vm.policy/1"
limitsfuel / wall_clock_ms / mem_cap_bytes资源 cap，CLI flag 覆盖
externallow (string[])Layer 1 符号白名单；默认拒绝
fsread (string[])、write (string[])Glob 路径模式；Windows 走 realpath 规范化后匹配
httpallow (object[])每个对象：host / methods / path / port
envstring[]可读 / 写的环境变量名单
processspawn (bool) / exec (object[])spawn 开关 + exec 路径 / 参数白名单
警告非绝对路径的 fs 模式会被 policy.zig 直接拒收（fs_path_invalid）。 这包括 ..、junction / symlink 跳出、8.3 短名绕过、NTFS 备用数据流、CON / NUL / COM1.. 等 DOS 设备名。 详情见 src/policy.zig 头注释的威胁表。
