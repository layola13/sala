Source Map (In Development)

Status: the design is complete and the work is in development. The source map is not a usable feature yet — this page records what is being built and why, so that nobody mistakes the plan for the product.

Why it is needed: three measured gaps

Today, when a psa program fails, the position in the message is often not a position in anything the author wrote (all three behaviours measured on 2026-11-26):

  • psa’s own diagnostics have a line but no column. A frontend error names the .psa file and the line; the column is always null, and there is no source excerpt.
  • When the generated code is refused downstream, the reported position is in the generated files. A 7-line .psa program expands to 3,171 lines of generated SLA and 78,486 lines of generated SA; a host trap reports the expanded SA line. Without a map, that number is noise to the psa author, and psa’s own wrapper adds nothing but the generated file’s name.
  • A runtime panic carries a code and no position at all. An out-of-bounds program’s entire output is PANIC: code=32 — no psa line, no SLA line.

What is being built

Dual presentation of every diagnostic. When compilation fails, the generated SLA’s error is preserved verbatim — its code, its message, and its position in the generated file, unaltered and unreplaced — and, alongside it, psa presents the corresponding psa information: the .psa file, line and column, with a source excerpt. Neither half replaces the other; where a mapping can only be given at reduced precision, the presentation says so rather than pretending exactness.

A machine-readable map that ships with the build output. The mapping is written to a sidecar file, <stem>.psa-map.json, next to the generated SLA (and copied next to the executable on a successful build). It records the sources (with hashes, so a stale map is detected rather than silently applied to a changed file), the segments connecting generated positions to psa positions with their origin and precision, prebuilt bidirectional indexes — psa line to generated positions, and generated line back to psa — and an index of panic sites. The intended consumer is a future debugger: a breakpoint set on a psa line is resolved through this file to the generated positions it must stop at. The debugger itself is later work; the map is the interface it will consume.

Key Points of This Page

  • Source map: design complete, in development — not yet a usable feature.
  • Diagnostics will be dual: the SLA error verbatim, plus the psa file, line, column, and excerpt.
  • The map is a persistent artefact (.psa-map.json, bidirectional indexes) intended for later breakpoint debugging in psa source.
